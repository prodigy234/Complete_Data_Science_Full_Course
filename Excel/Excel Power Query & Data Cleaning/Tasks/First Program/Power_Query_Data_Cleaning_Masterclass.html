Power Query Data Cleaning Masterclass

Ten Comprehensive Dirty Datasets - Excel and Power BI Editions

Prepared by Kajola Gbenga Adewale | Data Expert

Introduction

This guide accompanies ten deliberately dirty, Nigerian business-context datasets built for teaching Power Query inside both Microsoft Excel and Microsoft Power BI Desktop. Each dataset simulates a real operational export - the kind of file a trainee would actually receive from a store manager, a bank operations officer, an HR system, a hospital records desk, or a delivery dispatcher. Nothing here is randomly scrambled; every error was inserted on purpose so it maps to a specific, namable data quality problem and a specific Power Query technique.

Use each section as a standalone lesson. Open the named CSV file in Excel (Data tab, Get Data, From File, From Text/CSV) or in Power BI Desktop (Home tab, Get Data, Text/CSV), then follow the numbered cleaning steps in the Power Query Editor. Every step references the actual ribbon command or M function so trainees can follow along click for click. Where the workflow differs between Excel and Power BI, both versions are given side by side.

General Cleaning Checklist (Apply to Every Dataset)

  1. Promote headers correctly (Use First Row as Headers) and confirm no header row got treated as data.
  2. Check and fix data types column by column - Power Query's auto-detect guesses wrong on mixed currency and mixed date columns almost every time.
  3. Trim and Clean text columns (Transform > Format > Trim / Clean) to remove leading, trailing, and double spaces and non-printable characters.
  4. Standardise text casing (Transform > Format > UPPERCASE / lowercase / Capitalize Each Word) so the same value is not stored under three different cases.
  5. Replace inconsistent null markers (blank, N/A, NULL, -, unknown, NIL) with a true Null using Replace Values, then decide a fill strategy.
  6. Remove exact duplicate rows (Home > Remove Rows > Remove Duplicates) and investigate near-duplicates with Group By.
  7. Split combined columns (Transform > Split Column > By Delimiter / By Number of Characters / By Positions) such as full names or full addresses.
  8. Standardise categorical spelling (Transform > Replace Values, or a Merge Queries lookup table) so Lagos, lagos, and LAGOS State all become one value.
  9. Fix currency text columns by removing symbols and words with Replace Values and Extract, then convert to a true Decimal Number type.
  10. Fix inconsistent phone number formats with Replace Values and Extract > Text Between Delimiters, or a custom column with Text.Select to keep digits only.
  11. Validate ranges and flag impossible values (negative quantities, ages above 120, future dates, zero prices) using conditional columns before deciding to filter or correct them.
  12. Document every step in Applied Steps with clear, renamed step names so the query reads like a recipe anyone else can audit.

Dataset 1Supermarket Point of Sale Transactions

Domain: Retail and FMCG  |  File: 01_retail_supermarket_sales_DIRTY.csv

A five-branch Lagos and Abuja supermarket chain (Prodigy Mart) exports its daily point of sale log as a single CSV. The file is handed to a new data analyst exactly as it left the till system, with no cleanup.

Columns: TransactionID, Date, Store, ProductName, Category, Quantity, UnitPrice, TotalAmount, PaymentMethod, CustomerName, CustomerPhone, State, CashierID, DiscountApplied

Data Quality Issues Deliberately Built In

  • Mixed date formats in the Date column (31/01/2025, 2025-01-31, 31-Jan-2025 all appear).
  • UnitPrice and TotalAmount stored as text with mixed currency symbols and words: NGN, naira, N, and the naira sign all show up for the same field.
  • Quantity contains impossible values, including 0 and negative numbers.
  • TransactionID inconsistently cased (TXN1001 versus txn1001).
  • Store and ProductName have inconsistent capitalisation and stray leading or trailing spaces.
  • Category and TotalAmount contain blank, N/A, NULL, and Unknown style nulls mixed together.
  • CustomerPhone uses at least five different formats, including 0-prefixed, +234, dashed, and spaced versions.
  • State column mixes Lagos, lagos, LAGOS, and Lagos State for the same state.
  • DiscountApplied mixes Yes/No, Y/N, 1/0, and TRUE/FALSE for the same boolean fact.
  • Around five percent of rows are exact duplicates of other rows.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the file: From Text/CSV, and confirm the delimiter is detected as Comma with UTF-8 encoding.
  2. Promote headers (Use First Row as Headers) if Power Query did not do it automatically.
  3. Remove exact duplicates first with Home > Remove Rows > Remove Duplicates, selecting all columns, so later cleaning is not repeated on copies.
  4. Trim and Clean the Store, ProductName, CustomerName, and PaymentMethod columns in one pass using Transform > Format > Trim, then Transform > Format > Clean.
  5. Standardise casing: apply Transform > Format > Capitalize Each Word to Store and ProductName, and Capitalize Each Word to CustomerName.
  6. Fix the Date column: select the column, Transform > Data Type > Date. If errors appear, use Replace Errors to null, or split the column first using Column From Examples to coach Power Query through the mixed formats, then recombine with a Date.FromText custom column that tests each format with try/otherwise.
  7. Clean UnitPrice and TotalAmount: Replace Values to strip 'naira', 'NGN', and the naira sign, then use Transform > Format > Trim, then change Data Type to Decimal Number. Any row that still errors out should be inspected with a filter on Error before deciding whether to fix or remove it.
  8. Standardise State: Replace Values to collapse lagos, LAGOS, and Lagos State into Lagos, repeating for each state with variants, or build a small two-column lookup table and use Merge Queries with a Left Outer join to standardise in one step.
  9. Standardise CustomerPhone: add a custom column using Text.Select([CustomerPhone], {"0".."9","+"}) to strip spaces, brackets, and dashes, then apply a final Replace Values pass to normalise the country code prefix.
  10. Replace null markers: select Category, CustomerName, and TotalAmount, then Replace Values to convert N/A, NULL, Unknown, and a lone dash into a true null, so later Power BI measures do not silently treat them as text.
  11. Standardise DiscountApplied: Replace Values to map Y, 1, TRUE, yes into Yes and N, 0, FALSE, no into No, then set the column type to Text or a custom True/False logical column.
  12. Fix Quantity: filter for Quantity less than or equal to 0, review the rows, and either correct from TotalAmount and UnitPrice with a calculated column, or exclude them with a documented Applied Step named 'Removed invalid quantity rows'.
  13. Finish by adding a calculated column CheckTotal = Quantity * UnitPrice and comparing it to TotalAmount to catch any remaining entry errors, then load.

Dataset 2Retail Bank Customer Transaction Log

Domain: Banking and Financial Services  |  File: 02_bank_customer_transactions_DIRTY.csv

A mid-size Nigerian bank's operations team exports a multi-branch transaction log covering deposits, withdrawals, transfers, and bill payments, pulled straight from the core banking export tool with no formatting applied.

Columns: TransactionRef, AccountNumber, CustomerName, BankBranch, TransactionType, Channel, Amount, Date, Time, Status, BeneficiaryAccount, PhoneNumber, State, Currency

Data Quality Issues Deliberately Built In

  • AccountNumber has blank values where the export failed to capture the field.
  • Amount is stored as text with naira sign, NGN, and naira-word formats mixed in, and a small number of rows show a negative amount due to a sign error.
  • Date uses several formats and some rows show 00/00/0000 or text placeholders instead of a real date.
  • Time is recorded in both 24-hour and 12-hour AM/PM formats.
  • Status has inconsistent casing (Successful, successful, SUCCESSFUL) plus a Reversed status that needs business clarification.
  • Channel values mix Title Case and lowercase for the same channel (Mobile App versus mobile app).
  • BeneficiaryAccount is often blank for non-transfer transactions, which is expected, but needs to be distinguished from a missing value that should have been captured.
  • Currency column mixes NGN, Naira, ngn, and a handful of USD rows that need flagging or converting.
  • Duplicate transaction rows appear where the export tool repeated a batch.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and check that AccountNumber and BeneficiaryAccount import as Text, not Whole Number, so leading zeros are preserved.
  2. Remove duplicate rows on all columns using Remove Rows > Remove Duplicates before any other cleaning.
  3. Clean Amount: Replace Values to remove 'NGN', 'naira', the naira sign, and any thousands separators, Trim the result, then set Data Type to Decimal Number. Use Transform > Standard > Absolute Value, or a conditional column, to correct the small number of negative amounts after confirming with the business that they are sign errors and not legitimate reversals.
  4. Clean Date: convert to Date type, then filter on errors or on the literal text 00/00/0000 to isolate bad rows for manual review or removal, naming the Applied Step 'Isolated invalid transaction dates'.
  5. Standardise Time: extract hours and minutes with a custom column using Time.FromText with try/otherwise to handle both 24-hour and AM/PM strings, producing one consistent Time type column.
  6. Standardise Status and Channel: apply Transform > Format > Capitalize Each Word to both columns, then use Replace Values for any remaining category collisions such as 'Reversed' needing its own bucket separate from 'Failed'.
  7. Standardise CustomerName: Trim, Clean, then Capitalize Each Word.
  8. Handle BeneficiaryAccount nulls deliberately: add a conditional column IsTransfer = if [TransactionType] = "Transfer" then true else false, then only flag blank BeneficiaryAccount as a data quality issue where IsTransfer is true.
  9. Standardise Currency: Replace Values to map ngn, NGN, Naira, and 'NGN ' (with trailing space, caught by Trim first) into a single NGN value, and split out the USD rows into a separate review query using a filter.
  10. Standardise PhoneNumber using the same Text.Select digits-only technique as the retail dataset.
  11. Add a Branch and City split: Split Column > By Delimiter on the last space in BankBranch to separate the bank name from the branch location for easier grouping in a PivotTable or Power BI matrix.
  12. Close and load, naming the query 'Bank_Transactions_Clean', and disable Load for any intermediate staging queries used only for the USD review.

Dataset 3Company HR Employee Master File

Domain: Human Resources  |  File: 03_hr_employee_records_DIRTY.csv

An HR officer at a Lagos-based training and consulting company exports the full staff master list ahead of a payroll audit. The export blends manual entry over several years, so formatting has drifted badly.

Columns: EmployeeID, FullName, Department, JobTitle, Gender, DateOfBirth, HireDate, Email, PhoneNumber, MaritalStatus, EmploymentType, MonthlySalary, State, YearsOfExperience, Active

Data Quality Issues Deliberately Built In

  • Department has up to six spelling and casing variants for the same department (Sales, sales, SALES, Sales Dept; HR, Human Resources, human resources).
  • Gender mixes Male/Female with single-letter M/F in different cases.
  • DateOfBirth and HireDate use multiple date formats and some placeholder 'unknown date' text.
  • MonthlySalary is stored as text with mixed currency notation.
  • MaritalStatus has trailing spaces and inconsistent casing.
  • YearsOfExperience contains impossible values such as negative numbers and 99.
  • Active uses a mix of Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Email is missing for some employees and was never validated for a proper format.
  • A handful of fully duplicated employee rows exist from repeated exports being appended together.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the file and remove exact duplicate rows first with Remove Duplicates on EmployeeID plus FullName, since EmployeeID should be unique.
  2. Build a Department lookup table as a second query (six rows: each dirty variant mapped to one clean department name), then use Merge Queries with a Left Outer join on Department to bring in the standardised name, and remove the old column.
  3. Standardise Gender with Replace Values, mapping M, m, male into Male and F, f, female into Female.
  4. Fix DateOfBirth and HireDate: set Data Type to Date, filter on errors to find the 'unknown date' rows, and decide a business rule, for example leaving them null rather than guessing.
  5. Add a calculated Age column using Date.From(DateTime.LocalNow()) minus DateOfBirth, divided into years with Duration.Days, to cross check against any stated age fields and to validate HireDate is after DateOfBirth.
  6. Clean MonthlySalary the same way as the retail UnitPrice column: Replace Values to strip currency text and symbols, Trim, then set to Decimal Number.
  7. Trim and standardise MaritalStatus and EmploymentType with Trim, Clean, and Capitalize Each Word.
  8. Fix YearsOfExperience: filter for negative values or values above a realistic ceiling such as 45, and route them to a review table using a duplicated query rather than silently deleting them.
  9. Standardise Active into a true Logical (True/False) type using Replace Values before changing Data Type, so payroll reports can filter active staff with a simple Boolean filter.
  10. Validate Email: add a custom column IsValidEmail = Text.Contains([Email], "@") and Text.Contains([Email], ".") to flag malformed or missing addresses for HR follow up rather than guessing a value.
  11. Finish with a Split Column > By Delimiter (space) on FullName into FirstName and LastName only after confirming every name has exactly one space, handling exceptions with a conditional column first.
  12. Close and load as 'HR_Employees_Clean'.

Dataset 4Hospital Patient Admission and Billing Records

Domain: Healthcare  |  File: 04_hospital_patient_records_DIRTY.csv

A private hospital's records desk exports admission, diagnosis, and billing data for a quarterly NHIS reconciliation. The export mixes data entered by different shifts of front desk staff over many months.

Columns: PatientID, PatientName, Gender, Age, DateOfBirth, BloodGroup, Genotype, Weight_kg, Department, Ward, Diagnosis, AdmissionDate, DischargeDate, PhoneNumber, State, NHIS_Covered, BillAmount

Data Quality Issues Deliberately Built In

  • PatientID uses two different ID schemes (MUSC-PT-prefixed and a plain PT-prefixed series) that need a single standard going forward.
  • Age contains impossible values, including 0, negative numbers, and 150, and disagrees with DateOfBirth in some rows.
  • DateOfBirth includes a placeholder 00/00/0000 value where the field was never captured.
  • Weight_kg mixes kilograms and pounds in the same column without a unit label on most rows.
  • BloodGroup and Genotype contain blanks, NIL, unknown, and inconsistent casing such as 'O positive' instead of 'O+'.
  • Ward has inconsistent casing and a NULL text marker mixed with genuine blanks.
  • Diagnosis has leading spaces and inconsistent casing for the same diagnosis (Typhoid Fever versus typhoid versus TYPHOID).
  • BillAmount is stored as text with mixed currency notation and some rows show a lone dash instead of an amount.
  • NHIS_Covered mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • AdmissionDate and DischargeDate use mixed formats, and a few DischargeDate values predate AdmissionDate, which is logically impossible.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the file as Text/CSV and immediately set PatientID, PhoneNumber, and BloodGroup to Text type so Power Query does not misinterpret them.
  2. Standardise PatientID format with a conditional column that detects the MUSC-PT- prefix and rewrites both schemes into one consistent pattern, for example PT-00001, using Text.PadStart on the numeric portion.
  3. Fix DateOfBirth: set to Date type, filter on the 00/00/0000 placeholder and on errors, and null those rows out explicitly rather than letting them silently fail later calculations.
  4. Recompute Age from DateOfBirth where DateOfBirth is valid, using Date.From(DateTime.LocalNow()) minus DateOfBirth, and only fall back to the original Age column where DateOfBirth is null, using a conditional column with two branches.
  5. Standardise Weight_kg: add a custom column that checks Text.Contains([Weight_kg], "lbs"), extracts the numeric portion with Text.BeforeDelimiter, converts pounds to kilograms by multiplying by 0.4536, and merges this with the already-clean kilogram rows into one numeric Weight_kg column.
  6. Clean BloodGroup and Genotype: Trim, Capitalize, then Replace Values to fix variants such as 'O positive' into 'O+' and 'B Positive' into 'B+', and convert NIL, unknown, and blanks into a true null.
  7. Standardise Ward and Department: Trim, Clean, Capitalize Each Word, and Replace Values to convert the text NULL marker into a true null.
  8. Clean Diagnosis: Trim and Capitalize Each Word so 'Typhoid Fever', 'typhoid', and 'TYPHOID' collapse into one consistent category, which is essential before building any diagnosis frequency chart.
  9. Clean BillAmount with the same currency stripping and Decimal Number conversion technique used in the retail and bank datasets, treating the lone dash as a null rather than a zero.
  10. Standardise NHIS_Covered into a Logical True/False column with Replace Values before changing Data Type.
  11. Fix AdmissionDate and DischargeDate: convert both to Date type, then add a validation column DischargeAfterAdmission = [DischargeDate] >= [AdmissionDate] to flag the logically impossible rows for the records team to correct at source.
  12. Close and load as 'Hospital_Patients_Clean', keeping a separate 'Hospital_DataQuality_Flags' query that surfaces every row this process flagged rather than corrected automatically.

Dataset 5Secondary School Student Academic Records

Domain: Education  |  File: 05_school_student_records_DIRTY.csv

A secondary school's exams office exports a term result sheet covering continuous assessment and exam scores across subjects and classes, compiled by several class teachers with no shared template.

Columns: StudentID, StudentName, Class, Gender, DateOfBirth, Subject, CA_Score, ExamScore, TotalScore, Grade, GuardianName, GuardianRelationship, GuardianPhone, State, TermSession, FeesPaid

Data Quality Issues Deliberately Built In

  • Class has inconsistent formatting for the same class (JSS1, jss1, Jss 1, SS1, SS 1).
  • ExamScore and TotalScore contain impossible values outside the 0 to 100 range, including negative scores and scores above 100.
  • CA_Score is sometimes missing even though ExamScore is present, and the reverse also happens.
  • Grade mixes letter grades with words like Pass, Fail, and Distinction, which are not on the same scale and need separating.
  • GuardianRelationship has inconsistent casing (Father, father, MOTHER).
  • TermSession is written in at least four different text formats for what should be a single consistent academic session label.
  • FeesPaid mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • GuardianPhone has the same multi-format problem seen across the other datasets.
  • Duplicate student-subject rows exist from a merged export of two source files.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove exact duplicates on StudentID, Subject, and TermSession together, since the same student should only have one result per subject per term.
  2. Standardise Class: Trim, remove internal spaces with Replace Values (' ' into ''), then Capitalize Each Word, so 'Jss 1', 'jss1', and 'JSS1' all become 'JSS1'.
  3. Validate ExamScore, CA_Score, and TotalScore: set to Whole Number type, then filter for values outside 0 to 100 and route them into a review query rather than deleting them, since an exams officer needs to manually verify the correct score against the paper record.
  4. Recompute TotalScore = CA_Score + ExamScore where both are valid and within range, using a custom column, and compare it against the original TotalScore to catch transcription errors.
  5. Separate Grade into two concepts: add a conditional column GradeType that detects whether the value is a single letter (A to F) or a word (Pass, Fail, Distinction), so reporting does not mix two different grading scales in one chart.
  6. Standardise GuardianRelationship and GuardianName with Trim, Clean, and Capitalize Each Word.
  7. Standardise TermSession with Replace Values into a single canonical format such as '2025/2026 First Term', mapping every variant found in the issues list to that one string.
  8. Standardise FeesPaid into a Logical True/False column with Replace Values before changing Data Type.
  9. Clean GuardianPhone using the same Text.Select digits-only approach as the retail and bank datasets.
  10. Build a simple Student Performance summary query on top of the cleaned table using Group By on StudentID and TermSession with an Average of TotalScore, to demonstrate to trainees how clean data immediately enables a useful aggregation.
  11. Close and load as 'Student_Results_Clean'.

Dataset 6Online Store Customer Orders

Domain: E-commerce and Retail  |  File: 06_ecommerce_orders_DIRTY.csv

An online fashion and electronics store exports its order history ahead of a logistics review. Customer-entered shipping addresses and inconsistent courier naming make this one of the messiest files in the set.

Columns: OrderID, CustomerName, Email, PhoneNumber, ShippingAddress, ItemName, Category, Quantity, UnitPrice, OrderDate, DeliveryDate, OrderStatus, Courier, PaymentMethod, Rating

Data Quality Issues Deliberately Built In

  • ShippingAddress is a single combined column holding street, city, state, and country together, which needs splitting for any geographic analysis.
  • Quantity includes a negative value that should never occur for an order line.
  • OrderStatus has inconsistent casing for the same status (Delivered, delivered, DELIVERED).
  • Courier has inconsistent casing and abbreviation (GIG Logistics, gig logistics, GIGL).
  • Rating includes values outside the expected 1 to 5 scale, including 0 and 6, and is frequently missing.
  • Email is missing for some customers and not validated for format.
  • DeliveryDate is blank for a meaningful share of rows, which needs to be distinguished from undelivered orders versus a data capture gap.
  • UnitPrice is stored as text with mixed currency notation.
  • Duplicate order rows exist from a retried export job.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove exact duplicate rows on OrderID first, since OrderID should be unique per order line.
  2. Split ShippingAddress: use Split Column > By Delimiter on the comma, splitting into Street, City, StateRaw, and a trailing Country segment, then Trim each resulting column to remove the extra spaces left behind by the split.
  3. Standardise StateRaw into State using Replace Values, stripping the word 'State' where present and fixing any casing issues, consistent with the approach used in the retail dataset.
  4. Clean CustomerName with Trim, Clean, and Capitalize Each Word.
  5. Validate Email with the same IsValidEmail conditional column technique used in the HR dataset.
  6. Clean PhoneNumber using the Text.Select digits-only technique.
  7. Fix Quantity: filter for values less than or equal to 0 and route to a review query rather than silently deleting, since a negative quantity likely represents a return that was miscoded.
  8. Clean UnitPrice with the standard currency stripping and Decimal Number conversion technique, then add a calculated LineTotal = Quantity * UnitPrice for downstream revenue analysis.
  9. Standardise OrderStatus and Courier with Trim, Clean, and Capitalize Each Word, then a final Replace Values pass to fold abbreviations like GIGL into the full courier name using a small lookup table merged in with Merge Queries.
  10. Fix OrderDate and DeliveryDate: set both to Date type, then add a conditional column DeliveryGap = if [OrderStatus] = "Delivered" and [DeliveryDate] = null then "Missing delivery date" else if [OrderStatus] <> "Delivered" then "Not yet delivered" else "OK", so blanks are explained rather than just flagged as errors.
  11. Validate Rating: filter for values outside 1 to 5, and convert any 0 values to null since a 0 rating on this platform is not a valid customer input, then set Data Type to Whole Number.
  12. Close and load as 'Ecommerce_Orders_Clean', keeping the original ShippingAddress as a disabled-load reference query in case the raw text is needed later for an audit.

Dataset 7Telecom Subscriber Usage and Billing Data

Domain: Telecommunications  |  File: 07_telecom_subscriber_data_DIRTY.csv

A telecom customer experience analyst exports a subscriber usage and billing snapshot to investigate churn, pulling fields straight from three different backend systems that were never standardised against each other.

Columns: SubscriberID, FullName, PhoneNumber, Network, PlanType, RegistrationDate, DataBundle, DataUsed_MB, CallMinutesUsed, SMSCount, MonthlySpend, State, SIM_Status, NIN_Linked

Data Quality Issues Deliberately Built In

  • Network and PlanType have inconsistent casing for the same network or plan (MTN, mtn, AIRTEL; Prepaid, prepaid, PAYG).
  • DataUsed_MB and CallMinutesUsed contain impossible negative values and unrealistic outliers such as 99999 MB.
  • DataBundle mixes units and formats (1GB, 1.5GB, 500MB, 1000MB, '2 GB' with a space, and a text value 'No active bundle').
  • MonthlySpend is stored as text with mixed currency notation.
  • SIM_Status has inconsistent casing and a trailing space variant ('Active ' versus 'Active').
  • NIN_Linked mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • RegistrationDate uses mixed date formats.
  • Duplicate subscriber rows exist from merging exports across the three backend systems.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove duplicate rows on SubscriberID first.
  2. Standardise Network and PlanType with Trim and Capitalize, then a final Replace Values pass since network names like MTN should stay uppercase by business convention rather than Title Case, which Capitalize Each Word would get wrong, so apply Text.Upper specifically to Network instead.
  3. Convert DataBundle into a consistent numeric MB column: add a custom column that uses Text.Contains to detect GB versus MB, strips the unit text and any stray space with Replace Values, converts to a Number, and multiplies GB values by 1024 to express everything in MB, while mapping 'No active bundle' to 0.
  4. Fix DataUsed_MB and CallMinutesUsed: set to Decimal Number and Whole Number respectively, then filter for negative values and unrealistic outliers (for example DataUsed_MB above 50000) and route them to a review query rather than deleting, since these often indicate a system export bug rather than a true reading.
  5. Clean MonthlySpend with the standard currency stripping and Decimal Number conversion technique.
  6. Standardise SIM_Status: Trim to remove the trailing space variant, then Capitalize, then Replace Values to fold BLACKLISTED into a clear, distinct status rather than letting it collide with Inactive.
  7. Standardise NIN_Linked into a Logical True/False column the same way as FeesPaid and Active in earlier datasets.
  8. Fix RegistrationDate: convert to Date type and resolve format errors the same way as the other datasets, then add a calculated TenureMonths column using Duration.Days between RegistrationDate and today, divided by 30, rounded down.
  9. Clean FullName and PhoneNumber using the same Trim, Clean, Capitalize, and digits-only techniques used throughout the other nine datasets.
  10. Close and load as 'Telecom_Subscribers_Clean'.

Dataset 8Property Listings for Sale and Rent

Domain: Real Estate  |  File: 08_real_estate_listings_DIRTY.csv

A property agency aggregates listings from several agents across Lagos and Abuja into one spreadsheet ahead of a website refresh. Agents typed their own listings with no shared dropdown lists, so almost every text field has variants.

Columns: ListingID, PropertyTitle, PropertyType, ListingType, Bedrooms, Bathrooms, SizeSqm, Price, PricePeriod, Area, State, AgentName, AgentPhone, ListedDate, Furnished, ServiceCharge

Data Quality Issues Deliberately Built In

  • PropertyType has inconsistent casing for the same type (Duplex, duplex, BUNGALOW).
  • Bedrooms and Bathrooms include impossible values such as 0 and negative numbers.
  • SizeSqm mixes square metres and what are actually square feet values converted into the same column with no unit label, since some agents measured in feet.
  • Price is stored as text with mixed currency notation, and PricePeriod is inconsistently labelled or blank.
  • ListingType has inconsistent casing (For Sale, for sale, FOR RENT).
  • ServiceCharge is frequently blank, which needs to be distinguished between genuinely no service charge and a missing entry.
  • Furnished mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Duplicate listing rows exist where an agent's listing was pulled into the master sheet twice.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove duplicate rows on ListingID first.
  2. Standardise PropertyType and ListingType with Trim, Clean, and Capitalize Each Word.
  3. Fix Bedrooms and Bathrooms: set to Whole Number, then filter for values less than or equal to 0 (except where PropertyType is Land, which legitimately has 0 bedrooms) using a conditional filter, and route remaining suspicious rows to a review query.
  4. Resolve the SizeSqm unit mix: since the source data does not carry an explicit unit flag, build a documented business rule in a custom column, for example any SizeSqm value below 150 is treated as plausible square metres for typical residential units while anything wildly inconsistent with PropertyType and Bedrooms is flagged for agent confirmation rather than silently converted, demonstrating to trainees that not every ambiguity can be resolved by formula alone.
  5. Clean Price with the standard currency stripping and Decimal Number conversion technique, and standardise PricePeriod with Replace Values into a small fixed set such as Per Annum or One-off, converting blanks into a null pending agent follow up.
  6. Standardise Area and State with Trim, Clean, Capitalize Each Word, and the State lookup table merge technique used in the retail dataset.
  7. Clean AgentName and AgentPhone with the standard Trim, Clean, Capitalize, and digits-only techniques.
  8. Fix ListedDate: convert to Date type and resolve format errors using the same approach as the other nine datasets.
  9. Handle ServiceCharge nulls deliberately: add a conditional column ServiceChargeStatus = if [ServiceCharge] = null then "Not provided" else "Provided", so a blank is never silently treated as zero naira in a financial summary.
  10. Standardise Furnished into a Logical True/False column with Replace Values before changing Data Type.
  11. Add a PricePerSqm calculated column (Price divided by SizeSqm) only where both fields are valid and non-zero, using a conditional column to avoid a divide by zero error, and use this as a teaching example of safe calculated columns in Power Query.
  12. Close and load as 'Property_Listings_Clean'.

Dataset 9Fleet Delivery and Dispatch Records

Domain: Logistics and Transportation  |  File: 09_logistics_fleet_delivery_DIRTY.csv

A last-mile delivery company exports its dispatch log across bikes, vans, and trucks for a route efficiency review. Distance and weight fields were captured by different drivers using different units with no standard unit field.

Columns: ShipmentID, DriverName, VehicleType, VehiclePlateNumber, OriginCity, DestinationCity, DispatchDate, DeliveryDate, Distance_km, PackageWeight_kg, DeliveryStatus, DeliveryFee, CustomerPhone, FuelCost, OnTimeDelivery

Data Quality Issues Deliberately Built In

  • VehicleType has inconsistent casing for the same vehicle type (Bike, bike, VAN).
  • Distance_km mixes kilometres and miles in the same column with no unit flag, since some entries were converted from miles before export.
  • PackageWeight_kg mixes kilograms and grams in the same column, with some values clearly off by a factor of one thousand.
  • DeliveryStatus has inconsistent casing (Delivered, delivered, DELAYED).
  • VehiclePlateNumber is missing for some shipments.
  • DeliveryFee and FuelCost are stored as text with mixed currency notation, and FuelCost is frequently blank.
  • OnTimeDelivery mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • DispatchDate and DeliveryDate use mixed formats, and DeliveryDate is blank for some rows that need to be distinguished from genuinely undelivered shipments.
  • Duplicate shipment rows exist from a dispatch system retry.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove duplicate rows on ShipmentID first.
  2. Standardise VehicleType and DeliveryStatus with Trim, Clean, and Capitalize Each Word.
  3. Resolve the Distance_km unit mix with a documented business rule: since route distances on this network rarely exceed 900 km, build a conditional column that treats any value following a known miles-to-km conversion pattern as suspect and flags it for dispatch confirmation, again reinforcing that ambiguous unit problems need a documented assumption, not a silent guess.
  4. Resolve the PackageWeight_kg unit mix: add a conditional column that treats any value above a realistic ceiling such as 1000 as likely grams rather than kilograms, divides those values by 1000, and leaves smaller values untouched, then review the boundary cases manually.
  5. Fill or flag missing VehiclePlateNumber: add a conditional column PlateStatus = if [VehiclePlateNumber] = null then "Missing - flag for fleet office" else "OK" rather than leaving a silent blank in a fleet audit.
  6. Clean DeliveryFee and FuelCost with the standard currency stripping and Decimal Number conversion technique, treating a genuinely blank FuelCost as a null pending confirmation rather than assuming zero cost.
  7. Standardise OnTimeDelivery into a Logical True/False column with Replace Values before changing Data Type.
  8. Fix DispatchDate and DeliveryDate: convert both to Date type, resolve format errors, then add a DeliveryDurationDays calculated column (DeliveryDate minus DispatchDate) only where DeliveryDate is not null, and a DeliveryGap conditional column matching the e-commerce dataset's approach to explain blanks rather than just flag them.
  9. Clean DriverName and CustomerPhone with the standard Trim, Clean, Capitalize, and digits-only techniques.
  10. Add a RouteKey calculated column combining OriginCity and DestinationCity with Text.Combine, to support a Group By summary of average delivery time and fuel cost per route as a closing classroom exercise.
  11. Close and load as 'Fleet_Deliveries_Clean'.

Dataset 10Restaurant and Food Delivery Orders

Domain: Food and Hospitality  |  File: 10_restaurant_food_delivery_orders_DIRTY.csv

A food delivery aggregator exports orders across nine partner restaurants ahead of a monthly partner performance review, with delivery addresses and order timestamps typed freely by call centre agents.

Columns: OrderID, CustomerName, PhoneNumber, Restaurant, DishOrdered, Quantity, UnitPrice, DeliveryAddress, OrderTime, DeliveryStatus, DeliveryFee, PaymentMethod, Rating, ReviewNote

Data Quality Issues Deliberately Built In

  • Restaurant has inconsistent casing for the same restaurant name.
  • Quantity includes a negative value that should never occur for an order line.
  • OrderTime combines a mixed-format date with a mixed-format time in a single text field, requiring a two-stage split.
  • DeliveryStatus has inconsistent casing (Delivered, delivered, CANCELLED).
  • UnitPrice and DeliveryFee are stored as text with mixed currency notation.
  • PaymentMethod has overlapping labels for the same concept (Cash, cash on delivery, COD all mean the same thing).
  • Rating includes a 0 value outside the expected 1 to 5 scale and is frequently missing.
  • ReviewNote mixes genuine blank, the text N/A, and short free-text comments, which need separate handling from the numeric Rating field.
  • DeliveryAddress is a single combined column needing a street and area split similar to the e-commerce dataset.
  • Duplicate order rows exist from a call centre double-entry.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove duplicate rows on OrderID first.
  2. Standardise Restaurant, DeliveryStatus, and DishOrdered with Trim, Clean, and Capitalize Each Word.
  3. Split OrderTime in two stages: first Split Column > By Delimiter on the first space to separate the date portion from the time portion, then convert the date portion to Date type and the time portion to Time type separately, resolving the same mixed-format issue handled in the bank dataset.
  4. Fix Quantity: filter for values less than or equal to 0 and route to a review query, consistent with the e-commerce and retail datasets.
  5. Clean UnitPrice and DeliveryFee with the standard currency stripping and Decimal Number conversion technique, then add a calculated LineTotal = Quantity * UnitPrice + DeliveryFee.
  6. Standardise PaymentMethod with a small lookup table merged in through Merge Queries, mapping 'cash on delivery' and 'COD' into a single 'Cash on Delivery' category alongside Cash, Card, Transfer, and Wallet.
  7. Validate Rating: set to Whole Number, convert 0 values to null since this platform does not allow a genuine zero star rating, and filter for any value outside 1 to 5 to catch remaining entry errors.
  8. Clean ReviewNote: Replace Values to convert N/A and blank into a true null, keeping genuine free-text comments untouched, and add a HasReview conditional column (true where ReviewNote is not null) for quick filtering in a partner performance dashboard.
  9. Split DeliveryAddress: Split Column > By Delimiter on the comma into Street and Area columns, Trim each result, consistent with the e-commerce dataset approach.
  10. Clean CustomerName and PhoneNumber with the standard Trim, Clean, Capitalize, and digits-only techniques.
  11. Close and load as 'Restaurant_Orders_Clean', then build a quick Group By on Restaurant with Average of Rating and Sum of LineTotal as a closing classroom exercise tying the cleaning work back to a business question.

Facilitator Notes

  • Encourage trainees to never edit the raw CSV. All cleaning happens inside Power Query so the steps stay documented, repeatable, and auditable in the Applied Steps pane.
  • Each Applied Step should be renamed to a short plain-English description (right-click the step, Rename) so the finished query reads like a checklist, not a list of Step 1, Step 2, Step 3.
  • Where a fix depends on a business assumption (unit conversions, what counts as a valid rating, how to treat a negative quantity), say so explicitly in a step name or a comment, rather than silently overwriting data.
  • Use Group By early and often as a diagnostic tool, not just a final reporting step. Grouping a category column and counting rows is the fastest way to discover every spelling variant that exists in a column before deciding on a Replace Values strategy.
  • Errors are not failures. Power Query's red error cells and the 'Keep Errors' / 'Remove Errors' commands are themselves a cleaning workflow worth teaching explicitly, since real exports always contain a few truly broken rows.
  • Encourage saving a small reusable lookup table workbook or query group (state name variants, courier name variants, department name variants) that trainees can reuse across multiple datasets and future client projects, since this is exactly the kind of reusable asset a working data analyst builds over time.
Note: All ten CSV files referenced in this guide use standard, intentionally inconsistent formatting for teaching purposes. Trainees should never edit the raw files directly; all cleaning should happen inside the Power Query Editor in either Excel or Power BI Desktop so the process stays documented and repeatable.
