Reusable Solution Components: The Six Shared Helper Functions (Recap)

Create each function below as its own blank query in the Power Query Editor (Home > New Source > Blank Query, then Advanced Editor), name the query exactly as shown, and set 'Include in report refresh' / Load off for all six since they are building blocks rather than tables. Once created, every one of the ten dataset queries below can call them directly, for example fxCleanText([Store]) or fxToNumber([UnitPrice]), exactly like any other M function.

fxCleanText

Trims whitespace, strips non-printable characters, and converts every known null-marker string (blank, N/A, NULL, NIL, unknown, a lone dash, a question mark, and similar placeholders seen across all ten files) into a true M null so that later steps, aggregations, and Power BI measures never silently treat a placeholder as real text.

(inputValue as any) as nullable text =>
let
    AsText = if inputValue = null then null else Text.From(inputValue),
    Trimmed = if AsText = null then null else Text.Trim(Text.Clean(AsText)),
    NullMarkers = {
        "", "N/A", "NA", "N.A", "N.A.", "NULL", "NIL", "UNKNOWN",
        "UNKNOWN DATE", "NOT SET", "-", "--", "?", "NONE", "#N/A", "UNDEFINED"
    },
    Result =
        if Trimmed = null then null
        else if List.Contains(NullMarkers, Text.Upper(Trimmed)) then null
        else Trimmed
in
    Result
fxToNumber

Converts any of the currency-as-text formats found across the ten files - the naira sign, the word naira, the letters NGN, thousands-separator commas, and stray spaces - into a true Decimal Number, returning null for any remaining null-marker or truly unparseable text instead of raising a step error that would silently poison a downstream calculation.

(inputValue as any) as nullable number =>
let
    AsText = if inputValue = null then null else Text.From(inputValue),
    NullMarkers = {"", "-", "--", "?", "N/A", "NA", "NIL", "UNKNOWN", "NONE"},
    IsNullLike = AsText = null or List.Contains(NullMarkers, Text.Upper(Text.Trim(AsText))),
    Step1 = if IsNullLike then null else Text.Replace(AsText, "₦", ""),
    Step2 = if Step1 = null then null else Text.Replace(Step1, "NGN", ""),
    Step3 = if Step2 = null then null else Text.Replace(Step2, "naira", ""),
    Step4 = if Step3 = null then null else Text.Replace(Step3, "Naira", ""),
    Step5 = if Step4 = null then null else Text.Replace(Step4, ",", ""),
    Cleaned = if Step5 = null then null else Text.Trim(Step5),
    Result = if Cleaned = null or Cleaned = "" then null else try Number.FromText(Cleaned) otherwise null
in
    Result
fxDigitsOnlyPhone

Strips every non-digit character (spaces, brackets, dashes, plus signs) from a phone number field regardless of which of the five formats it arrived in, then re-applies a single consistent Nigerian local format (a leading 0 followed by ten digits), so the same subscriber number is never stored three different ways in the same column.

(inputValue as any) as nullable text =>
let
    AsText = if inputValue = null then null else Text.From(inputValue),
    DigitsOnly = if AsText = null then null else Text.Select(AsText, {"0".."9"}),
    Result =
        if DigitsOnly = null or DigitsOnly = "" then null
        else if Text.StartsWith(DigitsOnly, "234") and Text.Length(DigitsOnly) = 13
             then "0" & Text.Middle(DigitsOnly, 3, 10)
        else if Text.Length(DigitsOnly) = 11 then DigitsOnly
        else if Text.Length(DigitsOnly) = 10 then "0" & DigitsOnly
        else DigitsOnly
in
    Result
fxToBoolean

Standardises any of the six common Yes/No spellings used across the ten files (Yes/No, Y/N, 1/0, TRUE/FALSE, in any letter case, with any surrounding whitespace) into a true Power Query Logical value, so filters, slicers, and DAX measures can use a real Boolean instead of pattern-matching text every time.

(inputValue as any) as nullable logical =>
let
    AsText = if inputValue = null then null else Text.Upper(Text.Trim(Text.From(inputValue))),
    TrueValues = {"YES", "Y", "1", "TRUE"},
    FalseValues = {"NO", "N", "0", "FALSE"},
    Result =
        if AsText = null then null
        else if List.Contains(TrueValues, AsText) then true
        else if List.Contains(FalseValues, AsText) then false
        else null
in
    Result
fxTryParseDate

Attempts several known date text patterns in turn (ISO 2025-01-31, UK-style 31/01/2025, US-style 01/31/2025, dotted 31.01.2025, and long form 31 January 2025 or 31-Jan-2025) using try...otherwise so that one unrecognised format never crashes the whole column, and converts every recognised placeholder (blank, not set, unknown date, 00/00/0000) into a clean null rather than a parsing error.

(inputValue as any) as nullable date =>
let
    AsText = if inputValue = null then null else Text.Trim(Text.From(inputValue)),
    NullMarkers = {"", "NOT SET", "UNKNOWN DATE", "00/00/0000", "N/A", "NULL", "NIL"},
    IsNullLike = AsText = null or List.Contains(NullMarkers, Text.Upper(AsText)),
    Attempt1 = if IsNullLike then null else try Date.From(DateTime.FromText(AsText)) otherwise null,
    Attempt2 = if Attempt1 <> null then Attempt1
               else if IsNullLike then null
               else try Date.FromText(AsText, "en-GB") otherwise null,
    Attempt3 = if Attempt2 <> null then Attempt2
               else if IsNullLike then null
               else try Date.FromText(AsText, "en-US") otherwise null,
    Result = Attempt3
in
    Result
fxCleanState

Folds every Nigerian state-name variant seen in the ten files (different letter case, the word State tacked on or left off, a state capital used in place of the state, and common abbreviations such as FCT or Lag) into one canonical spelling, without needing a separate Merge Queries lookup step inside every dataset query.

(inputValue as any) as nullable text =>
let
    Raw = fxCleanText(inputValue),
    Upper = if Raw = null then null else Text.Upper(Raw),
    NoStateWord =
        if Upper = null then null
        else Text.Trim(Text.Replace(Text.Replace(Upper, " STATE", ""), "STATE ", "")),
    Mapped =
        if NoStateWord = null then null
        else if NoStateWord = "LAGOS" or NoStateWord = "LAG" or NoStateWord = "IKEJA" or NoStateWord = "LEKKI" then "Lagos"
        else if NoStateWord = "ABUJA" or NoStateWord = "FCT" or NoStateWord = "FCT ABUJA" then "FCT Abuja"
        else if NoStateWord = "KANO" then "Kano"
        else if NoStateWord = "OYO" or NoStateWord = "IBADAN" then "Oyo"
        else if NoStateWord = "RIVERS" or NoStateWord = "PORT HARCOURT" then "Rivers"
        else Text.Proper(NoStateWord),
    Result = Mapped
in
    Result
A note on method: two equally valid ways exist in Power Query to standardise a messy categorical column such as State, Department, or Courier - a hand-written conditional function like fxCleanState below, or a small two-column lookup table merged in with Merge Queries and a Left Outer join. This guide uses the function approach throughout for compactness, but the Lookup Table Appendix at the end of this document shows the Merge Queries method worked through in full for one dataset, so trainees are comfortable with both techniques and can choose whichever fits a future client's workbook better - a function travels inside the query itself, while a lookup table is easier for a non-technical colleague to open and edit without touching M code.

Dataset 11Insurance Claims Processing Register — Full Solution

Domain: Insurance  |  File: 11_insurance_claims_DIRTY.csv

Recap of Planted Data Quality Issues

  • PolicyType has overlapping, inconsistently cased entries (Motor, Motor Comprehensive; Life, Life (Term)) needing casing consolidation.
  • IncidentDate and ClaimDate use mixed date formats; some ClaimDate values fall before IncidentDate.
  • CauseOfClaim has trailing spaces and mixed casing for the same cause.
  • PremiumPaid, ClaimAmount, PayoutAmount stored as text with mixed currency notation; PayoutAmount frequently blank.
  • ClaimStatus uses inconsistent casing and overlapping labels (Approved, Partially Approved, Settled).
  • PolicyActive mixes Yes/No, Y/N, 1/0, TRUE/FALSE; roughly five percent duplicate rows from a pasted shared workbook.

Complete Power Query M Solution (Paste into the Advanced Editor)

let
    Source = Csv.Document(File.Contents("C:\ProdigyTrainingHub\11_insurance_claims_DIRTY.csv"),
        [Delimiter=",", Columns=15, Encoding=65001, QuoteStyle=QuoteStyle.Csv]),
    PromotedHeaders = Table.PromoteHeaders(Source, [PromoteAllScalars=true]),
    AllText = Table.TransformColumnTypes(PromotedHeaders,
        List.Transform(Table.ColumnNames(PromotedHeaders), each {_, type text})),
    TypedPolicyNumber = Table.TransformColumnTypes(AllText, {{"PolicyNumber", type text}}),
    RemovedDuplicateRows = Table.Distinct(TypedPolicyNumber),
    CleanedNamesAndCause = Table.TransformColumns(RemovedDuplicateRows, {
        {"CustomerName", each Text.Proper(fxCleanText(_)), type text},
        {"InsurerName", each Text.Proper(fxCleanText(_)), type text},
        {"CauseOfClaim", each Text.Proper(fxCleanText(_)), type text},
        {"PolicyType", each Text.Proper(fxCleanText(_)), type text}
    }),
    ParsedIncidentDate = Table.TransformColumns(CleanedNamesAndCause, {{"IncidentDate", each fxTryParseDate(_), type date}}),
    ParsedClaimDate = Table.TransformColumns(ParsedIncidentDate, {{"ClaimDate", each fxTryParseDate(_), type date}}),
    AddedClaimAfterIncident = Table.AddColumn(ParsedClaimDate, "ClaimAfterIncident", each
        if [IncidentDate] = null or [ClaimDate] = null then null
        else [ClaimDate] >= [IncidentDate], type logical),
    NumericPremium = Table.TransformColumns(AddedClaimAfterIncident, {{"PremiumPaid", each fxToNumber(_), type number}}),
    NumericClaimAmount = Table.TransformColumns(NumericPremium, {{"ClaimAmount", each fxToNumber(_), type number}}),
    NumericPayoutAmount = Table.TransformColumns(NumericClaimAmount, {{"PayoutAmount", each fxToNumber(_), type number}}),
    StandardisedClaimStatus = Table.TransformColumns(NumericPayoutAmount, {{"ClaimStatus", each
        let U = Text.Upper(Text.Trim(fxCleanText(_) ?? ""))
        in if U = null then null
           else if U = "SETTLED" or U = "APPROVED" then "Approved"
           else if U = "PARTIALLY APPROVED" then "Partially Approved"
           else Text.Proper(U), type text}}),
    AddedPayoutStatus = Table.AddColumn(StandardisedClaimStatus, "PayoutStatus", each
        if [PayoutAmount] = null and [ClaimStatus] = "Approved" then "Payout missing - review"
        else if [PayoutAmount] = null then "No payout"
        else "Paid", type text),
    StandardisedPolicyActive = Table.TransformColumns(AddedPayoutStatus, {{"PolicyActive", each fxToBoolean(_), type logical}}),
    DigitsOnlyPhone = Table.TransformColumns(StandardisedPolicyActive, {{"CustomerPhone", each fxDigitsOnlyPhone(_), type text}}),
    StandardisedState = Table.TransformColumns(DigitsOnlyPhone, {{"State", each fxCleanState(_), type text}}),
    ReorderedColumns = Table.ReorderColumns(StandardisedState,
        {"ClaimID","PolicyNumber","PolicyType","InsurerName","CustomerName","CustomerPhone","IncidentDate","ClaimDate",
         "ClaimAfterIncident","CauseOfClaim","PremiumPaid","ClaimAmount","PayoutAmount","PayoutStatus","ClaimStatus",
         "State","PolicyActive"})
in
    ReorderedColumns

Step-by-Step Explanation of the Non-Obvious Decisions

  • PolicyNumber typed as Text before anything else — A policy number that is purely numeric would otherwise be auto-detected as a Whole Number and could lose a leading zero or a leading letter prefix in a mixed alphanumeric scheme, exactly the same risk this guide has flagged for account and ID columns in every dataset so far.
  • ClaimAfterIncident computed immediately after both dates parse, before any currency cleaning — Placing the logical-impossibility check right next to the two date-parsing steps keeps the reasoning for that specific business rule together in the Applied Steps pane, which matters when a claims officer later needs to audit exactly how a row was classified.
  • ClaimStatus consolidation is a documented business decision, not a silent default — The masterclass narrative is explicit that folding Settled into Approved is 'whatever the business says is the correct mapping'; this solution documents the choice made (Settled treated as a form of Approved) directly in the Business Assumptions list below rather than hiding it inside an unexplained Replace Values step.
  • PayoutStatus built as a three-way conditional rather than a simple null check — A blank PayoutAmount is completely normal on a claim still Pending or Rejected, but the exact same blank on an Approved claim is a genuine process gap the claims team needs to chase; the three-way conditional keeps those two situations distinct instead of flagging every blank payout equally.

Validation Checklist Before Close & Load

  • Filter ClaimAfterIncident = false and confirm every flagged row is routed to the claims team rather than silently corrected.
  • Group By ClaimStatus and confirm only the agreed canonical bucket list remains (for example Approved, Partially Approved, Pending, Rejected).
  • Filter PayoutStatus = "Payout missing - review" and cross-check a sample against the claims file to confirm every flagged row is genuinely Approved with no PayoutAmount recorded.
  • Group By PolicyType and confirm casing variants have collapsed while genuinely distinct sub-products (Motor versus Motor Comprehensive) remain separate.
  • Check Table.RowCount before and after Table.Distinct to confirm the duplicate count removed is consistent with the roughly five percent figure noted in the file profile.

Business Assumptions Made Explicit

  • Settled and Approved are treated as the same underlying claim outcome and consolidated into a single 'Approved' status; a business with a genuine operational distinction between the two would need to override this mapping.
  • A blank PayoutAmount is only treated as a process gap requiring review when ClaimStatus is Approved; the same blank on any other status is accepted as normal and simply labelled 'No payout'.
  • PolicyType casing is standardised with Text.Proper rather than collapsed into fewer categories, preserving the distinction between a base product and its named sub-variant (for example Motor Comprehensive stays distinct from Motor).

Dataset 12Microfinance Institution Loan Records — Full Solution

Domain: Microfinance and Credit  |  File: 12_microfinance_loan_records_DIRTY.csv

Recap of Planted Data Quality Issues

  • LoanPurpose has trailing spaces and mixed casing, including short forms (business, SCHOOL FEES) needing expansion.
  • PrincipalAmount and AmountRepaid stored as text with mixed currency notation; InterestRate_pct sometimes carries a percent symbol and is sometimes missing.
  • AmountRepaid exceeds PrincipalAmount by more than 10 percent in some rows.
  • LoanStatus mixes casing and overlapping labels from two branch systems.
  • CollateralType has inconsistent casing and a high blank rate that must be split into 'confirmed none' versus 'unknown'.
  • NPL_Flag mixes Yes/No, Y/N, 1/0, TRUE/FALSE; DisbursementDate and MaturityDate use mixed formats with some logically impossible pairs.
  • Gender mixes Male/Female with single-letter M/F; roughly four percent duplicate rows from a two-system merge.

Complete Power Query M Solution (Paste into the Advanced Editor)

let
    Source = Csv.Document(File.Contents("C:\ProdigyTrainingHub\12_microfinance_loan_records_DIRTY.csv"),
        [Delimiter=",", Columns=15, Encoding=65001, QuoteStyle=QuoteStyle.Csv]),
    PromotedHeaders = Table.PromoteHeaders(Source, [PromoteAllScalars=true]),
    AllText = Table.TransformColumnTypes(PromotedHeaders,
        List.Transform(Table.ColumnNames(PromotedHeaders), each {_, type text})),
    RemovedDuplicateRows = Table.Distinct(AllText),
    CleanedBorrowerName = Table.TransformColumns(RemovedDuplicateRows, {{"BorrowerName", each Text.Proper(fxCleanText(_)), type text}}),
    StandardisedGender = Table.TransformColumns(CleanedBorrowerName, {{"Gender", each
        let U = Text.Upper(Text.Trim(fxCleanText(_) ?? ""))
        in if U = "M" or U = "MALE" then "Male" else if U = "F" or U = "FEMALE" then "Female" else null, type text}}),
    StandardisedLoanPurpose = Table.TransformColumns(StandardisedGender, {{"LoanPurpose", each
        let U = Text.Upper(Text.Trim(fxCleanText(_) ?? ""))
        in if U = null then null
           else if Text.Contains(U, "BUSINESS") then "Business Expansion"
           else if Text.Contains(U, "SCHOOL") then "School Fees"
           else if Text.Contains(U, "MEDICAL") then "Medical Bills"
           else Text.Proper(U), type text}}),
    NumericPrincipal = Table.TransformColumns(StandardisedLoanPurpose, {{"PrincipalAmount", each fxToNumber(_), type number}}),
    NumericAmountRepaid = Table.TransformColumns(NumericPrincipal, {{"AmountRepaid", each fxToNumber(_), type number}}),
    AddedOverRepayment = Table.AddColumn(NumericAmountRepaid, "OverRepaymentFlag", each
        if [PrincipalAmount] = null or [AmountRepaid] = null then "Cannot verify"
        else if [AmountRepaid] > [PrincipalAmount] * 1.10 then "Overpayment - review"
        else "OK", type text),
    NumericInterestRate = Table.TransformColumns(AddedOverRepayment, {{"InterestRate_pct", each
        let
            Raw = fxCleanText(_),
            NoPercent = if Raw = null then null else Text.Replace(Raw, "%", "")
        in
            if NoPercent = null then null else try Number.FromText(NoPercent) otherwise null, type number}}),
    StandardisedLoanStatus = Table.TransformColumns(NumericInterestRate, {{"LoanStatus", each
        let U = Text.Upper(Text.Trim(fxCleanText(_) ?? ""))
        in if U = null then null
           else if U = "OVERDUE" then "Overdue"
           else if Text.Contains(U, "DEFAULT") then "Defaulted"
           else if Text.Contains(U, "FULLY") then "Fully Repaid"
           else if Text.Contains(U, "WRITTEN") then "Written Off"
           else if Text.Contains(U, "ACTIVE") then "Active"
           else Text.Proper(U), type text}}),
    StandardisedCollateral = Table.TransformColumns(StandardisedLoanStatus, {{"CollateralType", each
        let Raw = fxCleanText(_)
        in if Raw = null then null else if Text.Upper(Raw) = "NONE" then "None (Uncollateralised)" else Text.Proper(Raw), type text}}),
    StandardisedNPLFlag = Table.TransformColumns(StandardisedCollateral, {{"NPL_Flag", each fxToBoolean(_), type logical}}),
    ParsedDisbursement = Table.TransformColumns(StandardisedNPLFlag, {{"DisbursementDate", each fxTryParseDate(_), type date}}),
    ParsedMaturity = Table.TransformColumns(ParsedDisbursement, {{"MaturityDate", each fxTryParseDate(_), type date}}),
    AddedMaturityCheck = Table.AddColumn(ParsedMaturity, "MaturityAfterDisbursement", each
        if [DisbursementDate] = null or [MaturityDate] = null then null
        else [MaturityDate] > [DisbursementDate], type logical),
    DigitsOnlyPhone = Table.TransformColumns(AddedMaturityCheck, {{"BorrowerPhone", each fxDigitsOnlyPhone(_), type text}}),
    StandardisedState = Table.TransformColumns(DigitsOnlyPhone, {{"State", each fxCleanState(_), type text}}),
    ReorderedColumns = Table.ReorderColumns(StandardisedState,
        {"LoanID","BorrowerName","BorrowerPhone","Gender","LoanPurpose","PrincipalAmount","InterestRate_pct",
         "DisbursementDate","MaturityDate","MaturityAfterDisbursement","AmountRepaid","OverRepaymentFlag","LoanStatus",
         "CollateralType","LoanOfficer","State","NPL_Flag"})
in
    ReorderedColumns

Step-by-Step Explanation of the Non-Obvious Decisions

  • OverRepaymentFlag uses a 10 percent tolerance band, not a strict greater-than test — The masterclass narrative explicitly notes the cause could be interest capture, rounding, or a genuine error; a strict AmountRepaid > PrincipalAmount test would flag every loan that has simply finished paying its interest on top of the principal, which is normal, so the 1.10 multiplier only catches genuinely excessive overpayment.
  • InterestRate_pct strips the percent symbol before the numeric parse, not after — Number.FromText fails outright on a string containing a percent sign; removing it first with a targeted Text.Replace, rather than trying to catch the resulting error afterwards, is the simpler and more transparent fix.
  • CollateralType makes a data governance decision explicit rather than defaulting silently — The word 'None' in the source data reflects a confirmed business fact (no collateral was taken), while an empty blank reflects an unknown data gap; only the literal word None is remapped to the explicit label, leaving genuine blanks as null so the two situations stay distinguishable exactly as the original masterclass instructs.
  • LoanStatus folds both branch systems' vocabulary with Text.Contains before falling back to Text.Proper — Checking for the substrings DEFAULT, FULLY, WRITTEN, and ACTIVE catches every casing and spacing variant from both merged branch systems in one pass, while the fallback to Text.Proper protects any genuinely new status value from being silently dropped.

Validation Checklist Before Close & Load

  • Filter OverRepaymentFlag = "Overpayment - review" and confirm this is a small minority of rows, consistent with a genuine entry-error rate rather than a systemic double-counting problem across the whole portfolio.
  • Group By LoanStatus and confirm the distinct list has collapsed to the five canonical statuses (Active, Fully Repaid, Defaulted, Written Off, Overdue).
  • Group By CollateralType and confirm 'None (Uncollateralised)' is now clearly distinct from a genuine null in the Column Quality panel.
  • Filter MaturityAfterDisbursement = false and confirm every flagged row is escalated to the portfolio management team.
  • Check InterestRate_pct's Column Distribution for a plausible range (roughly single digits to high thirties) with no remaining outliers above 100.

Business Assumptions Made Explicit

  • An overpayment is only flagged for review once AmountRepaid exceeds 110 percent of PrincipalAmount, accepting that a loan fully repaid with interest will naturally show AmountRepaid slightly above PrincipalAmount.
  • The literal text 'None' in CollateralType is treated as a confirmed uncollateralised loan and relabelled explicitly; any other blank is left as a genuine unknown rather than assumed to also mean uncollateralised.
  • A MaturityDate on or before its DisbursementDate is flagged for the credit team to correct at source rather than auto-swapped, since either field could be the one in error.

Complete Power Query M Solution (Paste into the Advanced Editor)

    Source = Csv.Document(File.Contents("C:\ProdigyTrainingHub\13_hotel_hospitality_reservations_DIRTY.csv"),
        [Delimiter=",", Columns=15, Encoding=65001, QuoteStyle=QuoteStyle.Csv]),
    PromotedHeaders = Table.PromoteHeaders(Source, [PromoteAllScalars=true]),
    AllText = Table.TransformColumnTypes(PromotedHeaders,

    RemovedDuplicateRows = Table.Distinct(AllText),
    CleanedGuestAndHotel = Table.TransformColumns(RemovedDuplicateRows, {
        {"GuestName", each Text.Proper(fxCleanText(_)), type text},
        {"HotelName", each Text.Proper(fxCleanText(_)), type text},
        {"RoomType", each Text.Proper(fxCleanText(_)), type text}
    }),
    NumericNights = Table.TransformColumns(CleanedGuestAndHotel,
        {{"NumberOfNights", each try Number.FromText(fxCleanText(_)) otherwise null, Int64.Type}}),
    AddedNightsFlag = Table.AddColumn(NumericNights, "NightsFlag", each
        if [NumberOfNights] = null or [NumberOfNights] < 1 then "Review - invalid night count" else "OK", type text),
    ParsedCheckIn = Table.TransformColumns(AddedNightsFlag, {{"CheckInDate", each fxTryParseDate(_), type date}}),
    ParsedCheckOut = Table.TransformColumns(ParsedCheckIn, {{"CheckOutDate", each fxTryParseDate(_), type date}}),
    AddedStayValidation = Table.AddColumn(ParsedCheckOut, "StayValidation", each
        if [CheckOutDate] = null then "Missing checkout date"
        else if [CheckOutDate] <= [CheckInDate] then "Checkout before checkin - review"
        else "OK", type text),
    NumericRoomRate = Table.TransformColumns(AddedStayValidation, {{"RoomRatePerNight", each fxToNumber(_), type number}}),
    NumericTotalBill = Table.TransformColumns(NumericRoomRate, {{"TotalBill", each fxToNumber(_), type number}}),
    AddedExpectedBill = Table.AddColumn(NumericTotalBill, "ExpectedBill", each
        if [NumberOfNights] = null or [NumberOfNights] < 1 or [RoomRatePerNight] = null then null
        else Number.Round([NumberOfNights] * [RoomRatePerNight], 2), type number),
    AddedBillVariance = Table.AddColumn(AddedExpectedBill, "BillVariance", each
        if [TotalBill] = null or [ExpectedBill] = null then null
        else Number.Round([TotalBill] - [ExpectedBill], 2), type number),
    StandardisedBookingSource = Table.TransformColumns(AddedBillVariance, {{"BookingSource", each

Step-by-Step Explanation of the Non-Obvious Decisions

  • ProjectType uses a Merge Queries lookup table, the fourth and final dataset in Set 2 to specifically require it — Three overlapping procurement-system labels per project category, in some cases needing the accompanying ProjectName text to disambiguate a genuinely ambiguous Bridge versus Bridge Rehabilitation entry, is exactly the kind of many-to-one mapping problem the masterclass narrative identifies as too complex for a simple conditional function, so the ProjectTypeLookupTable query is built and merged in exactly as specified.
  • fxToNumber handles the embedded thousands commas in billion-naira values without any extra step — Because fxToNumber already strips commas as one of its standard cleaning operations, the masterclass narrative's specific warning about needing an additional Text.Replace for commas in this dataset is already satisfied by the shared helper function; no extra step is needed here, which is itself worth pointing out to trainees who might otherwise duplicate work the helper library already does.
  • CompletionDataCheck runs immediately after ProjectStatus is standardised, before the currency columns are touched — Sequencing the two date-related checks (this one and, further down, OverpaymentCheck once currency is cleaned) close to the steps that produced their inputs keeps the Applied Steps pane readable as a narrative of 'clean this, then check this' pairs, rather than grouping every check together at the very end of the query.
  • ProgressConsistency treats a missing percentage and a contradictory percentage as two different findings — A blank PercentageCompletion is a data completeness gap, while a 100 percent reading on a project still marked Ongoing is a genuine logical contradiction that likely means either the percentage or the status field is wrong; giving them different flag text lets the auditor triage the two situations with different urgency.
  • ProjectDurationDays is calculated from planned dates only, deliberately not from ActualCompletionDate — The masterclass narrative asks specifically for a planned-versus-actual duration analysis to be supported in Power BI; keeping ProjectDurationDays as the planned duration only, rather than conflating it with actual duration, leaves the actual-versus-planned comparison itself as a downstream Power BI calculation the trainee builds later, rather than pre-computing an answer that would need its own separate variance column here.

Validation and Quality Assurance Methodology for Audit-Style Datasets

Set 2 leans heavily on audit and revenue-assurance style datasets, where the deliverable a client actually cares about is not the clean table itself but the short list of exceptions it surfaces. The five-part validation routine from the Set 1 solutions guide still applies in full to every dataset in this set, and should be run first. The two additional checks below are specific to the flag-heavy, audit-oriented datasets that make up most of Set 2 (payroll, electricity billing, pharmacy, and construction).

  1. Row count reconciliation, Column Quality, Group By, flag audit, and recomputation cross-checks — Run all five checks from the Set 1 QA methodology first, exactly as documented there, before moving on to the two audit-specific checks below.
  2. Companion exception-query row count sanity check — For every dataset with a companion AuditFlags query (Payroll_AuditFlags, Revenue_Assurance_Flags, Pharmacy_ComplianceFlags, Projects_AuditFlags), confirm its row count is a genuinely small fraction of the full cleaned table - typically under ten percent. A companion query returning close to the full row count almost always means one of its flag conditions is miscalibrated (too strict a tolerance, or a condition that should have used <> "OK" but was written the wrong way round) rather than a real finding that most of the population is non-compliant.
  3. Cross-flag correlation check — Where a dataset has more than one flag column (for example ExpiryStatus and MarginCheck in the pharmacy dataset), Group By each flag column pair and check whether the same rows tend to trigger multiple flags together. A cluster of rows failing every check at once is often a sign of one upstream data corruption event (a whole batch import gone wrong) rather than many independent, unrelated errors, and is worth investigating as a single root cause before writing up ten separate findings.
