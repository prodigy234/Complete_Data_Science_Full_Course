Introduction

This is the fourth set of ten deliberately dirty Nigerian business-context datasets for teaching Power Query data cleaning in both Microsoft Excel and Microsoft Power BI Desktop. Set 4 is the first mixed-format set: five datasets are delivered as plain CSV files and five are delivered as formatted Excel workbooks (.xlsx). This mirrors the real-world situation an analyst faces daily - some exports from operational systems arrive as raw text files with no formatting, while others arrive as styled workbooks from colleagues who have done some light formatting but left the underlying data quality completely untouched. The ten domains covered in this set are: solid minerals and mining, pension and retirement benefits, legal services and law firm case records, printing and publishing, sports academy and football player records, cold chain and refrigerated logistics, urban planning and land use records, veterinary clinic and animal health records, tax administration (FIRS), and funeral and cemetery management. Every quality problem in every file was deliberately embedded to map to a specific, namable Power Query cleaning technique.

The connection step in Power Query differs by file format. For each CSV file, go to Data > Get Data > From File > From Text/CSV in Excel, or Home > Get Data > Text/CSV in Power BI Desktop, select the file, and click Transform Data. For each .xlsx file, go to Data > Get Data > From File > From Workbook in Excel, or Home > Get Data > Excel Workbook in Power BI Desktop, select the file, choose the correct sheet in the navigator, and click Transform Data. After that point the Power Query Editor is identical regardless of the source format, and every cleaning step in this guide applies equally in both tools. Where a step differs between Excel and Power BI, the note is given inline.

General Cleaning Checklist - Apply to Every Dataset

  1. Identify the file format before connecting - CSV files use Get Data > From Text/CSV; .xlsx files use Get Data > From Workbook. Using the wrong connector produces an error or loads metadata instead of data.
  2. For .xlsx files: always select the correct named sheet in the navigator, not the workbook root node. The workbook root returns a table of sheet metadata, not the data itself.
  3. Delete the auto-generated Changed Type step immediately after load for both CSV and .xlsx sources, and re-set data types manually after all text cleaning is complete.
  4. Confirm header promotion (Home > Use First Row as Headers) is the first Applied Step after Source for both file types. For CSV files Power Query usually promotes automatically; for .xlsx files it depends on whether the workbook had a frozen header row.
  5. Remove exact duplicate rows (Home > Remove Rows > Remove Duplicates on all columns) before any other transformation, so subsequent steps are not applied twice to copied records.
  6. Select all text columns in one pass and apply Trim (Transform > Format > Trim) then Clean (Transform > Format > Clean) to strip leading, trailing, and double spaces and non-printable characters before any Replace Values steps.
  7. Run a null standardisation pass across all text columns: Replace Values to convert blank, N/A, n/a, NULL, null, nil, NIL, -, --, unknown, ?, and Not Available into a true null.
  8. Standardise text casing (Capitalize Each Word for names, titles, and categories; Text.Upper for acronyms and short codes) before Replace Values steps, because Replace Values searches are case-sensitive in Power Query by default.
  9. For every currency-as-text column: strip the naira sign, NGN, naira, and N prefix with Replace Values; strip commas from large values; Trim the result; then set Data Type to Decimal Number. Inspect error cells before removing.
  10. Rename every Applied Step in plain English (right-click > Rename) so the finished query reads like a documented cleaning checklist and is auditable by anyone who inherits the file.

Dataset 31  |  CSV

Mining License and Mineral Production Records

Domain: Solid Minerals and Mining  |  File: 31_mining_solid_minerals_DIRTY.csv

The Nigerian Mining Cadastre Office exports a license and production register covering gold, iron ore, coal, limestone, tin, columbite, barite, and other minerals across eight mining states. The register merges data from the online mining cadastre portal with a manually maintained inspection log, so mineral names, license types, quantity units, and status labels all have multiple inconsistent representations.

Columns: LicenseID, CompanyName, MineralType, MineSite, LicenseType, LicenseIssueDate, LicenseExpiryDate, QuantityMined_tonnes, RevenueNGN, RoyaltyPaidNGN, MineStatus, ContactPhone, State, EnvironmentalClearance, NMRCRegistered

Data Quality Issues Deliberately Built In

  • MineralType has inconsistent casing and trailing spaces for the same mineral (Gold, gold, GOLD; Iron Ore, Iron ore; Tin, Tin with a trailing space).
  • LicenseType mixes full names and abbreviated forms with inconsistent casing (Exploration, Mining Lease, mining lease, MINING LEASE, Small-Scale Mining, Small Scale, small-scale mining).
  • QuantityMined_tonnes mixes metric tonnes and short tons in the same column, with some rows appending the text "short tons" to the numeric value.
  • LicenseIssueDate and LicenseExpiryDate use mixed date formats. Some LicenseExpiryDate values precede LicenseIssueDate, which is logically impossible.
  • RevenueNGN and RoyaltyPaidNGN are stored as text with mixed currency notation. Large revenue values include thousands-separator commas.
  • RoyaltyPaidNGN is blank for many rows, which may indicate royalty not yet due or simply a data capture gap.
  • MineStatus has inconsistent casing and a trailing-space variant (Active, active, Suspended, Suspended with a trailing space, Inactive).
  • EnvironmentalClearance and NMRCRegistered both mix Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • ContactPhone uses the standard multi-format problem seen throughout these datasets.
  • Around five percent of rows are exact duplicates from the portal and manual log being merged without deduplication.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV (Get Data > From Text/CSV > Transform Data). Confirm delimiter is Comma and encoding is UTF-8. Delete the auto-generated Changed Type step. Promote headers if not done automatically.
  2. Remove duplicate rows on all columns (Home > Remove Rows > Remove Duplicates).
  3. Trim and Clean all text columns in one pass.
  4. Standardise MineralType: Capitalize Each Word, then Replace Values to fold trailing-space variants already removed by Trim. The result should be a clean named mineral list with no casing variants.
  5. Standardise LicenseType: Capitalize Each Word first, then build a small lookup table (DirtyType, CleanType) mapping every abbreviated and long-form variant to a canonical four-value list (Exploration, Mining Lease, Quarry Lease, Small-Scale Mining) and Merge Queries with a Left Outer join.
  6. Resolve the QuantityMined_tonnes unit mix: add a custom column that checks Text.Contains([QuantityMined_tonnes], "short tons") - if true, extract the numeric portion with Text.BeforeDelimiter, convert to Decimal Number, and multiply by 0.907185 to convert short tons to metric tonnes; if false, convert directly to Decimal Number. Name the result QuantityMined_tonnes and drop the original.
  7. Fix LicenseIssueDate and LicenseExpiryDate: convert both to Date type using try/otherwise to catch the mixed-format errors. Add a LicenseLogicCheck column: if [LicenseExpiryDate] <= [LicenseIssueDate] then "Expiry before issue - review" else if [LicenseExpiryDate] < Date.From(DateTime.LocalNow()) then "License expired" else "Valid".
  8. Clean RevenueNGN and RoyaltyPaidNGN: strip commas first (Replace Values, comma to empty string), then apply the standard currency-stripping chain (naira sign, NGN, naira, N prefix), Trim, then set to Decimal Number.
  9. Handle RoyaltyPaidNGN blanks deliberately: after currency conversion, add a RoyaltyStatus conditional column - if [RoyaltyPaidNGN] = null and [MineStatus] = "Active" then "Royalty not recorded for active mine - flag" else if [RoyaltyPaidNGN] = null then "Not applicable" else "Recorded".
  10. Standardise MineStatus: Trim already done, Capitalize Each Word, then Replace Values to produce a four-value list (Active, Inactive, Suspended, Reclaimed).
  11. Standardise EnvironmentalClearance and NMRCRegistered into Logical True/False columns with Replace Values before changing Data Type for each.
  12. Clean ContactPhone using Text.Select([ContactPhone], {"0".."9","+"}).
  13. Close and load as Mining_Licenses_Clean.
Dataset 32  |  XLSX

Pension Fund Administrator Membership Records

Domain: Pension and Financial Services  |  File: 32_pension_retirement_benefits_DIRTY.xlsx

A Pension Fund Administrator (PFA) exports its member register ahead of a National Pension Commission (PenCom) regulatory review. The register merges records from three legacy pension systems - the old defined benefit scheme, the contributory pension scheme, and a military/police scheme - each of which used different field conventions for member status, scheme type, and contribution amounts.

Columns: MemberID, FullName, Gender, DateOfBirth, RSAPin, PFAName, Scheme, Sector, EmployerName, JoinDate, RetirementDate, MemberStatus, MonthlyContribution, TotalAccumulation, MonthlyBenefit, BankAccountNo

Data Quality Issues Deliberately Built In

  • Scheme has inconsistent casing, abbreviations, and trailing spaces for the same scheme (Contributory Pension Scheme (CPS), CPS, cps, CPS with a trailing space, contributory; Legacy Defined Benefit, Legacy, LEGACY DB, Defined Benefit).
  • Sector mixes full names and abbreviations with inconsistent casing (Public Service, PUBLIC SERVICE, Private Sector, Private with a trailing space, private sector).
  • MemberStatus has trailing spaces and inconsistent casing across the three legacy systems (Active Contributor, active contributor, RETIREE, Retiree, Active with a trailing space, Deferred with a trailing space, death benefit).
  • MonthlyContribution, TotalAccumulation, and MonthlyBenefit are all stored as text with mixed currency notation.
  • TotalAccumulation is blank for some members whose records were migrated from the legacy defined benefit system without accumulation data.
  • MonthlyBenefit is blank for active contributors who have not yet reached retirement, which is expected, but also blank for some Retiree records, which is a data gap.
  • RetirementDate uses mixed date formats and is blank for active contributors, which is expected.
  • BankAccountNo is missing for some members, which is a critical compliance gap for benefit payment.
  • Gender mixes Male/Female with single-letter M/F in different cases.
  • RSAPin is missing for some members on the legacy defined benefit scheme, since RSA pins only apply to the contributory scheme.
  • Around four percent of rows are duplicates from the three-system merge.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook (Get Data > From Workbook), select the Pension Records sheet, click Transform Data. Delete the auto-generated Changed Type step. Confirm header promotion.
  2. Set BankAccountNo and RSAPin to Text type immediately to preserve leading zeros. Remove duplicate rows on all columns.
  3. Trim and Clean all text columns in one pass.
  4. Standardise Scheme: build a reference lookup table mapping every variant to three canonical values (Contributory Pension Scheme (CPS), Defined Benefit, Military/Police Scheme) and Merge Queries with a Left Outer join. A lookup table is the right tool here because there are too many variants for stacked Replace Values steps to be maintainable.
  5. Standardise Sector: Capitalize Each Word, then Replace Values to fold Private and "private sector" into Private Sector and "PUBLIC SERVICE" into Public Service.
  6. Standardise MemberStatus: Trim already done, Capitalize Each Word, then Replace Values to produce a clean five-value list (Active Contributor, Retiree, Deferred, Death Benefit, Disability).
  7. Standardise Gender: Replace Values to map M and m to Male and F and f to Female.
  8. Clean MonthlyContribution, TotalAccumulation, and MonthlyBenefit with the standard currency-stripping and Decimal Number conversion technique for each column in sequence.
  9. Handle TotalAccumulation blanks: add a AccumulationStatus column - if [TotalAccumulation] = null and [Scheme] = "Defined Benefit" then "Defined benefit - accumulation not applicable" else if [TotalAccumulation] = null then "Missing - follow up with employer" else "Recorded".
  10. Handle MonthlyBenefit blanks: add a BenefitStatus column - if [MemberStatus] = "Retiree" and [MonthlyBenefit] = null then "MISSING benefit amount for retiree - critical gap" else if [MemberStatus] <> "Retiree" then "Not yet payable" else "Recorded".
  11. Fix DateOfBirth, JoinDate, and RetirementDate: convert all three to Date type using try/otherwise. Add an Age column from DateOfBirth. Add a TenureYears column from JoinDate to today, or to RetirementDate where not null. Flag any TenureYears above 45 or below 1 as potentially erroneous.
  12. Flag missing BankAccountNo: add a BankAccountFlag = if [BankAccountNo] = null then "CRITICAL - no bank account for benefit payment" else "OK".
  13. Close and load as Pension_Members_Clean.
Dataset 33  |  CSV

Law Firm Case Management Records

Domain: Legal Services  |  File: 33_legal_lawfirm_case_records_DIRTY.csv

A Lagos-based multi-practice law firm exports its case management register covering civil litigation, criminal defence, commercial disputes, property law, family law, and employment law matters across multiple courts. The register is maintained in a shared practice management system by different teams in each practice group, and formatting conventions for case numbers, court names, fee amounts, and case status labels vary across the groups.

Columns: CaseID, CaseNumber, ClientName, ClientPhone, CaseType, CourtName, AssignedLawyer, DateFiled, NextHearingDate, ClosingDate, CaseStatus, Outcome, LegalFeeNGN, AmountPaidNGN, State, ProBonoCase

Data Quality Issues Deliberately Built In

  • CaseType mixes full practice area names with abbreviated forms and inconsistent casing (Civil Litigation, civil litigation, CRIMINAL, Criminal Defence, Commercial dispute, Property law with a trailing space, Labour Law).
  • CaseNumber has inconsistent formatting across practice groups (SUIT/FHC/1234/2024 versus suit/fhc/1234/2024 versus mixed case) with no standardised capitalisation convention.
  • DateFiled, NextHearingDate, and ClosingDate all use mixed date formats. Some NextHearingDate values fall before DateFiled, which is logically impossible for a newly filed case. Some ClosingDate values exist on rows where CaseStatus is still Active, which is a contradictory state.
  • CaseStatus has inconsistent casing and trailing spaces, and overlapping labels from different practice groups (Active, active, Closed, CLOSED, Settled Out of Court, Settled, Adjourned with a trailing space, Struck Out).
  • Outcome is frequently blank for active cases, which is expected, but also blank for some Closed cases, which is a data quality gap.
  • LegalFeeNGN and AmountPaidNGN are stored as text with mixed currency notation.
  • AmountPaidNGN exceeds LegalFeeNGN for some rows, which may indicate a retainer overpayment or a data entry error.
  • ProBonoCase mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • AssignedLawyer has leading spaces and inconsistent casing.
  • Around four percent of rows are duplicate case entries from a system migration.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV (Get Data > From Text/CSV > Transform Data). Delete the auto-generated Changed Type step. Remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass.
  3. Standardise CaseType: Capitalize Each Word, then build a lookup table mapping every variant to a canonical six-value practice area list (Civil Litigation, Criminal Defence, Commercial Dispute, Property Law, Family Law, Employment Law) and Merge Queries with a Left Outer join.
  4. Standardise CaseNumber: apply Text.Upper to produce a consistent all-caps format (SUIT/FHC/1234/2024), since case numbers are formal court references that should use a fixed convention.
  5. Fix DateFiled, NextHearingDate, and ClosingDate: convert all three to Date type using try/otherwise. Add a HearingLogicCheck column: if [NextHearingDate] < [DateFiled] then "Hearing before filing - impossible" else "OK". Add a ClosingStatusCheck: if [CaseStatus] = "Active" and [ClosingDate] <> null then "Active case with closing date - review" else "OK".
  6. Standardise CaseStatus: Trim already done, Capitalize Each Word, then Replace Values to consolidate Settled Out of Court and Settled into one canonical value (Settled Out of Court, or whichever the firm prefers) and to produce a clean six-value status list.
  7. Handle Outcome blanks: add an OutcomeStatus column - if [CaseStatus] = "Closed" or [CaseStatus] = "Settled Out of Court" or [CaseStatus] = "Struck Out" then if [Outcome] = null then "Outcome missing for closed case - follow up" else "Recorded" else "Expected blank for active or adjourned case".
  8. Clean LegalFeeNGN and AmountPaidNGN with the standard currency-stripping and Decimal Number conversion technique.
  9. Add an Overpayment flag: if [AmountPaidNGN] > [LegalFeeNGN] then "Overpayment - review with accounts" else "OK". Add a BalanceOwing column = [LegalFeeNGN] - [AmountPaidNGN] where both are not null.
  10. Standardise ProBonoCase into a Logical True/False column with Replace Values before changing Data Type.
  11. Clean ClientPhone using Text.Select to digits and + only.
  12. Close and load as LawFirm_Cases_Clean.
Dataset 34  |  XLSX

Print Shop Order and Production Records

Domain: Printing and Publishing  |  File: 34_printing_publishing_orders_DIRTY.xlsx

A commercial printing company operating in Lagos and Abuja exports its order register covering book printing, newspaper, magazine, packaging, branding and stationery, and flexographic print jobs. The register is compiled from two production management systems used by the Lagos and Abuja branches respectively, and every categorical field has formatting differences between the two branches.

Columns: OrderID, ClientName, ClientPhone, ClientType, PrintType, ProductTitle, PaperSize, QuantityCopies, CostPerCopy, TotalCostNGN, OrderDate, DeliveryDate, OrderStatus, State, VAT_Applied

Data Quality Issues Deliberately Built In

  • PrintType has inconsistent casing and trailing spaces across the two branches (Book Printing, book printing, NEWSPAPER, Magazine with a trailing space, Packaging, packaging, Branding/Stationery, Branding).
  • ClientType has abbreviations and inconsistent casing (Corporate, corporate, Individual, INDIVIDUAL, Government, Govt, NGO, ngo).
  • PaperSize has inconsistent formatting for the same size (A4, a4, A 4 with an internal space; B2, B2 with a trailing space; FOOLSCAP versus Foolscap).
  • QuantityCopies contains negative values and zeros, which should not appear on a valid print order.
  • CostPerCopy and TotalCostNGN are stored as text with mixed currency notation. TotalCostNGN should equal QuantityCopies multiplied by CostPerCopy and rows where it does not match reveal quote-to-order transcription errors.
  • TotalCostNGN is blank for some rows.
  • OrderDate and DeliveryDate use mixed date formats. DeliveryDate is blank for orders not yet completed, which is expected, but blank for some Completed and Delivered orders, which is a data gap.
  • OrderStatus has inconsistent casing and trailing spaces (Completed, completed, IN PRODUCTION, Awaiting Approval, Awaiting approval, Cancelled with a trailing space).
  • VAT_Applied mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are duplicate order entries from the two-branch system merge.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook (Get Data > From Workbook), select the Print Orders sheet, click Transform Data. Delete the auto-generated Changed Type step. Remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass. This resolves trailing spaces in PrintType, PaperSize, and OrderStatus immediately.
  3. Standardise PrintType: Capitalize Each Word, then Replace Values to fold Branding into Branding/Stationery and packaging into Packaging, producing a clean six-value type list.
  4. Standardise ClientType: Capitalize Each Word, then Replace Values to fold Govt into Government and ngo into NGO (since NGO is an acronym, apply Text.Upper to that value specifically using a conditional column rather than Capitalize Each Word, which would produce Ngo).
  5. Standardise PaperSize: Replace Values to remove the internal space from "A 4" (already handled if Trim was applied globally, but an internal space is different from a leading/trailing space - use Replace Values with "A 4" as the find string and "A4" as the replace), then Capitalize, producing a clean five-value size list (A3, A4, A5, B2, Foolscap).
  6. Fix QuantityCopies: set to Whole Number, then filter for values less than or equal to 0 and route to a review query named PrintOrders_InvalidQuantity.
  7. Clean CostPerCopy and TotalCostNGN with the standard currency-stripping and Decimal Number conversion technique.
  8. Add a calculated ExpectedTotal column = [QuantityCopies] * [CostPerCopy] where both are positive and not null, then a TotalCostVariance column to flag transcription discrepancies between the expected and recorded total.
  9. Fix OrderDate and DeliveryDate: convert both to Date type using try/otherwise. Add a DeliveryGap column = if [OrderStatus] = "Completed" or [OrderStatus] = "Delivered" then if [DeliveryDate] = null then "Missing delivery date for completed order" else "OK" else "Expected blank".
  10. Standardise OrderStatus: Trim already done, Capitalize Each Word, then Replace Values to produce a clean five-value list (Completed, In Production, Awaiting Approval, Cancelled, Delivered).
  11. Standardise VAT_Applied into a Logical True/False column with Replace Values before changing Data Type.
  12. Close and load as PrintOrders_Clean.
Dataset 35  |  CSV

Football Academy Player Records

Domain: Sports and Athletics  |  File: 35_sports_academy_player_records_DIRTY.csv

A Nigerian football federation data analyst exports a player register from seven NPFL-affiliated academies covering player profiles, contract details, performance statistics, and registration data. The register merges exports from two player management systems, one used by northern academies and one by southern academies, each with different conventions for position names, nationality labels, and performance stat formats.

Columns: PlayerID, PlayerName, Nationality, DateOfBirth, Position, PreferredFoot, Academy, JoinDate, ContractEndDate, MonthlySalaryNGN, GoalsScored, Assists, AppearancesTotal, PlayerStatus, FIFARegistered, ContactPhone

Data Quality Issues Deliberately Built In

  • Position has inconsistent casing, trailing spaces, and multi-word spacing errors for the same playing position (Goalkeeper, goalkeeper; Defender, DEFENDER; Midfielder, Mid fielder with an internal space; Forward, Forward with a trailing space; Striker with a trailing space).
  • PreferredFoot mixes full words and abbreviations with inconsistent casing (Right, right, right foot; Left, LEFT; Both, both).
  • Nationality has trailing spaces and inconsistent casing (Nigerian, NIGERIAN, Nigerian with a trailing space, nigerian).
  • GoalsScored and Assists contain negative values and an impossibly high outlier (999) that should be flagged for review.
  • AppearancesTotal also contains a negative value and an outlier.
  • MonthlySalaryNGN is stored as text with mixed currency notation.
  • ContractEndDate uses mixed date formats and is blank for some players, which may indicate an expired or informal contract.
  • JoinDate and DateOfBirth use mixed date formats. A player whose DateOfBirth plus 15 years is after their JoinDate would have joined the academy under age 15, which needs flagging.
  • PlayerStatus has trailing spaces and inconsistent casing (Active, active, INJURED, Loaned Out, Loaned out, Active with a trailing space).
  • FIFARegistered mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are duplicate player records from the two-system merge.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV (Get Data > From Text/CSV > Transform Data). Delete the auto-generated Changed Type step. Remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass. This resolves trailing-space variants in Position, Nationality, and PlayerStatus.
  3. Standardise Position: Replace Values to remove the internal space from "Mid fielder" first (this is not a leading/trailing space so Trim will not catch it), then Capitalize Each Word to resolve casing variants, producing a clean six-value position list (Goalkeeper, Defender, Midfielder, Forward, Winger, Striker).
  4. Standardise PreferredFoot: Capitalize Each Word, then Replace Values to fold "right foot" into Right, producing a clean three-value list (Right, Left, Both).
  5. Standardise Nationality: Capitalize Each Word. This resolves all casing variants in one step.
  6. Fix GoalsScored, Assists, and AppearancesTotal: set each to Whole Number. Add a StatsFlag conditional column: if [GoalsScored] < 0 then "Negative goals - impossible" else if [GoalsScored] > 200 then "Outlier - verify" else "OK", and equivalent checks for Assists and AppearancesTotal. Route flagged rows to a review query.
  7. Clean MonthlySalaryNGN with the standard currency-stripping and Decimal Number conversion technique.
  8. Fix DateOfBirth, JoinDate, and ContractEndDate: convert all three to Date type using try/otherwise. Add an AgeAtJoining column = Duration.Days([JoinDate] - [DateOfBirth]) / 365.25, rounded down, and flag any player who joined under age 14 or over 35 as needing verification. Add a ContractStatus column: if [ContractEndDate] = null then "No contract end date - verify" else if [ContractEndDate] < Date.From(DateTime.LocalNow()) then "Contract expired" else "Active contract".
  9. Standardise PlayerStatus: Trim already done, Capitalize Each Word, then Replace Values to produce a clean five-value list (Active, Injured, Loaned Out, Retired, Transferred).
  10. Standardise FIFARegistered into a Logical True/False column with Replace Values before changing Data Type.
  11. Clean ContactPhone using Text.Select to digits and + only.
  12. Close and load as AcademyPlayers_Clean.
Dataset 36  |  XLSX

Cold Chain and Refrigerated Cargo Shipment Records

Domain: Cold Chain and Logistics  |  File: 36_cold_chain_refrigerated_logistics_DIRTY.xlsx

A cold chain logistics company exporting frozen poultry, fresh seafood, dairy products, vaccines, blood products, and pharmaceutical cargo across major Nigerian cities exports its shipment log for a supply chain quality audit. The log merges data from two temperature monitoring systems and a manual dispatch register, producing a file where temperature readings, cargo type labels, and shipment status codes all have multiple representations.

Columns: ShipmentID, ClientName, CarrierName, CargoType, DispatchDate, DeliveryDate, OriginCity, DestinationCity, SetTemperature_C, ActualTemperature_C, WeightKg, ShippingCostNGN, TemperatureStatus, ShipmentStatus, InsuranceCovered

Data Quality Issues Deliberately Built In

  • CargoType has inconsistent casing and trailing spaces for the same cargo category (Frozen Poultry, frozen poultry; Vaccines, VACCINES; Fresh Seafood, Fresh seafood; Dairy Products, Dairy with a trailing space; Blood Products, Blood products).
  • ActualTemperature_C mixes Celsius and Fahrenheit values in the same column, with some rows appending the letter "F" to Fahrenheit readings.
  • SetTemperature_C is occasionally missing, which makes the TemperatureStatus column unverifiable for those rows.
  • TemperatureStatus has inconsistent casing and trailing spaces (Within Range, within range, BREACH DETECTED, Breach with a trailing space, Temperature Unknown).
  • ShipmentStatus has inconsistent casing and trailing spaces (Delivered, delivered, IN TRANSIT, Delayed with a trailing space, SPOILED).
  • DeliveryDate uses mixed date formats and is blank for in-transit shipments, which is expected, but blank for some Delivered rows, which is a data gap.
  • WeightKg is occasionally missing and should be flagged since weight is a required field for a shipment invoice.
  • ShippingCostNGN is stored as text with mixed currency notation.
  • InsuranceCovered mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

Do not convert null to zero here since a missing penalty is different from a waived penalty.

  11. Standardise AuditFlag into a Logical True/False column with Replace Values before changing Data Type.

Facilitator Notes

  • Open the first lesson by loading one CSV and one .xlsx file side by side in two separate queries, and show trainees that once both files are in the Power Query Editor the transformation experience is completely identical. The difference is only in the Source step at the top of the M code.
  • Use Column Quality (View > Column Quality) and Column Distribution (View > Column Distribution) at the start of every dataset. These two views do more diagnostic work in 30 seconds than a trainee could do by scrolling through data for 10 minutes.
  • For the mixed-unit columns in this set (temperature in Celsius and Fahrenheit in DS 36, weight in kg and lbs in DS 38, land area in square metres and square feet in DS 37, mined quantity in metric tonnes and short tons in DS 31), always make the business assumption explicit in the Applied Step name before applying a conversion formula. An undocumented unit conversion is a silent error waiting to cause problems downstream.
  • The tax dataset (DS 39) is an excellent vehicle for teaching the OutstandingNGN recomputation pattern: clean TaxLiabilityNGN and TaxPaidNGN to Decimal Number first, then add a calculated OutstandingRecalc = TaxLiabilityNGN - TaxPaidNGN column, and compare it to the original OutstandingNGN to surface rows where the carried-forward balance was wrong in the source system.
  • The pension dataset (DS 32) is a good opportunity to teach the cross-column date validation pattern: RetirementDate must always be after JoinDate, and a calculated TenureYears column (Duration.Days between them divided by 365.25) should fall within a plausible range for the Sector. Flag rows outside the range for the PFA compliance team rather than correcting them silently.
  • For the cold chain dataset (DS 36), use the temperature breach logic as a teaching moment about conditional column chains: a TemperatureBreach flag derived from SetTemperature_C versus ActualTemperature_C is only meaningful after both columns have been cleaned to a consistent Celsius numeric type, which is itself only possible after the mixed-unit conversion step. The order of Applied Steps matters and this dataset demonstrates it clearly.
  • Encourage trainees to build a reusable currency-cleaning function query (a named query that takes a text column and returns a Decimal Number column after stripping all known currency markers) by the end of Set 4. They have now applied the same pattern across 40 datasets and are ready to abstract it into a function.
