Introduction

This is the third set of ten deliberately dirty Nigerian business-context datasets for teaching Power Query data cleaning in both Microsoft Excel and Microsoft Power BI Desktop. Unlike Sets 1 and 2, every file in this set is delivered as a formatted Microsoft Excel workbook (.xlsx) with styled headers, alternating row colours, and adjusted column widths - exactly the kind of file a trainee will receive from a department head, a project manager, or an IT team that has already done some basic formatting but left the underlying data quality completely unaddressed. The ten domains covered are corporate event management, NGO beneficiary and grant records, media and advertising campaigns, airport passenger and flight records, waste management and sanitation, capital market trading records, ride-hailing trip records, fintech digital wallet transactions, WAEC and NECO examination results, and WASH water and sanitation project records. Every quality problem was deliberately embedded to map to a specific, namable Power Query cleaning technique.

Open each .xlsx file directly through Power Query. In Excel, go to Data > Get Data > From File > From Workbook, select the file, choose the sheet in the navigator, and click Transform Data. In Power BI Desktop, go to Home > Get Data > Excel Workbook, select the file, choose the sheet, and click Transform Data. Because the files are already formatted workbooks, Power Query will auto-promote the first row as headers in most cases - always confirm this in the Applied Steps pane before proceeding. Every numbered cleaning step in this guide references a specific ribbon command or M function so trainees can follow along click by click.

General Cleaning Checklist - Apply to Every Dataset

  1. Connect to the .xlsx file through Power Query - never clean data directly in the Excel sheet. All cleaning must live in the Applied Steps pane so it is repeatable and auditable.
  2. Confirm headers were promoted correctly (Home > Use First Row as Headers) and that the first data row was not accidentally consumed as the header row.
  3. Set data types explicitly for every column immediately after promotion. Auto-detect fails on mixed-format columns - especially currency-as-text, dates-as-text, and numeric IDs that Power Query tries to parse as whole numbers.
  4. Remove exact duplicate rows early (Home > Remove Rows > Remove Duplicates on all columns) before any other transformation so subsequent steps are not applied twice to the same record.
  5. Select all text columns in one pass and apply Trim (Transform > Format > Trim) followed by Clean (Transform > Format > Clean) to remove leading, trailing, and double spaces and any non-printable characters carried over from the source system.
  6. Run a null standardisation pass: select all text columns, Replace Values to convert blank, N/A, n/a, NULL, null, nil, NIL, -, --, unknown, ?, and Not Available into a true null so all downstream aggregations treat missing data correctly.
  7. Standardise text casing (Capitalize Each Word for names and categories, UPPERCASE for codes and short identifiers) before running any Replace Values step - Replace Values searches are case-sensitive by default in Power Query.
  8. For every currency-as-text column: Replace Values to strip the naira sign, NGN, and the word naira; Trim the result; then set Data Type to Decimal Number. Inspect the error cells that appear after the type change with Keep Errors before deciding to remove them.
  9. For every date-as-text column: set Data Type to Date and immediately filter on errors to find placeholder text such as 00/00/0000, not set, unknown, and N/A - these need a documented business decision, not a formula guess.
  10. Rename every Applied Step (right-click > Rename) with a short plain-English label so the finished query reads like a documented cleaning checklist, not a numbered list of Changed Type1, Changed Type2.

Dataset 21

Corporate Event Management Records

Domain: Events and Hospitality  |  File: 21_event_management_records_DIRTY.xlsx

A Lagos-based event management company maintains a client booking register covering corporate conferences, weddings, product launches, galas, and award ceremonies across five-star venues in Lagos and Abuja. The register is managed by three event coordinators who each have their own formatting preferences, so every categorical field in the file has at least three representations for the same value.

Columns: EventID, ClientName, ClientPhone, EventType, VenueName, BookingDate, EventDate, NumberOfGuests, Package, PricePerHead, TotalEventCost, DepositPaid, PaymentStatus, State, Caterer, EventCompleted

Data Quality Issues Deliberately Built In

  • EventType has trailing spaces and inconsistent casing for the same event category (Conference, conference, WEDDING, Workshop, Workshop with a trailing space, product launch).
  • NumberOfGuests contains negative values and zeros, which should never appear on a confirmed event booking.
  • BookingDate and EventDate use mixed date formats, and some EventDate values fall before the BookingDate, which is logically impossible for a new booking.
  • PricePerHead, TotalEventCost, and DepositPaid are all stored as text with mixed currency notation - naira sign, NGN, N prefix, and bare numbers are all present.
  • TotalEventCost should equal NumberOfGuests multiplied by PricePerHead, and rows where it does not match reveal manual override entries that need explanation.
  • DepositPaid exceeds TotalEventCost in some rows, which is logically impossible unless a refund was miscoded as a deposit.
  • PaymentStatus mixes casing and overlapping labels (Paid in Full, paid, PARTIAL, paid in full, Pending).
  • Package has a trailing-space variant (Standard versus Standard with a trailing space) and inconsistent casing.
  • Caterer mixes N/A, Not Confirmed, and blank for what should be three distinct states.
  • EventCompleted mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around five percent of rows are exact duplicate bookings from a shared workbook paste collision between two coordinators.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the .xlsx file (Data > Get Data > From File > From Workbook in Excel, or Get Data > Excel Workbook in Power BI), select the Event Records sheet, click Transform Data.
  2. Confirm headers were promoted correctly in Applied Steps, then remove exact duplicate rows on all columns (Home > Remove Rows > Remove Duplicates).
  3. Trim and Clean all text columns in one multi-select pass (Transform > Format > Trim, then Format > Clean) to remove leading, trailing, and double spaces first, because trailing spaces are responsible for Package, PaymentStatus, and Caterer matching failures.
  4. Standardise EventType: Capitalize Each Word, then Replace Values to fold all variants of the same event category (conference into Conference, WEDDING into Wedding, Workshop with a trailing space into Workshop) into one canonical list of eight event types.
  5. Standardise Package: Capitalize Each Word - this is sufficient since the only Package issues are casing and the trailing space already removed by Trim.
  6. Fix NumberOfGuests: set to Whole Number, then filter for values less than or equal to 0 and route those rows to a review query named Events_InvalidGuests rather than silently deleting them.
  7. Fix BookingDate and EventDate: convert both to Date type, resolve format errors using the standard technique. Add a BookingLogicCheck column: if [EventDate] < [BookingDate] then "Event before booking - review" else "OK" to surface logically impossible dates.
  8. Clean PricePerHead, TotalEventCost, and DepositPaid with the standard currency-stripping Replace Values chain (naira sign, NGN, N prefix, the word naira), Trim, then set Data Type to Decimal Number.
  9. Add a calculated ExpectedTotal column = [NumberOfGuests] * [PricePerHead] where both are positive and not null, then a TotalCostVariance column comparing it to TotalEventCost to surface manual overrides.
  10. Add a DepositExceedsTotal flag column: if [DepositPaid] > [TotalEventCost] then "Overpayment - review" else "OK".
  11. Standardise PaymentStatus: Trim is already done, so apply Capitalize Each Word, then Replace Values to produce a four-value list (Paid in Full, Partial Payment, Unpaid, Refunded).
  12. Handle Caterer nulls deliberately: Replace Values to convert blank, N/A, and Not Confirmed each into their own distinct null-category using a conditional column, since "no caterer confirmed" and "caterer data not captured" are different operational states.
  13. Standardise EventCompleted into a Logical True/False column with Replace Values before changing Data Type. Close and load as Events_Clean.
Dataset 22

NGO Beneficiary and Grant Records

Domain: Non-Profit and Development  |  File: 22_ngo_beneficiary_grant_records_DIRTY.xlsx

A Lagos-based non-governmental organisation running food support, education bursary, healthcare outreach, widow support, and youth empowerment programmes exports its beneficiary master register ahead of a donor audit. The register was built over three years by programme officers using different data entry templates, and it merges records funded by seven different international and local donors.

Columns: BeneficiaryID, FullName, Gender, DateOfBirth, PhoneNumber, Program, DonorOrganisation, GrantAmount, EnrollmentDate, ExitDate, BeneficiaryStatus, HouseholdSize, MonthlyIncome, State, NINVerified

Data Quality Issues Deliberately Built In

  • Program has trailing spaces and mixed casing for the same programme name (Food Support, food support, EDUCATION BURSARY, Healthcare, Healthcare Outreach - where the last two should be the same value).
  • Gender mixes Male/Female with single-letter M/F across different cases.
  • HouseholdSize contains a negative value and a suspiciously high value (20) that need flagging rather than silent deletion.
  • GrantAmount and MonthlyIncome are stored as text with mixed currency notation.
  • MonthlyIncome is frequently blank, which may mean zero income (subsistence beneficiaries) or simply not captured - these are different states for a donor report.
  • BeneficiaryStatus has inconsistent casing and a trailing-space variant (Active, active, COMPLETED, Active with a trailing space, Pending).
  • DonorOrganisation has inconsistent casing and a trailing-space variant (UNICEF, UNICEF with a trailing space, usaid versus USAID).
  • ExitDate is blank for beneficiaries still on active programmes, which is expected and should not be treated as a data quality error - only missing ExitDate on Completed or Withdrawn records is a genuine gap.
  • DateOfBirth and EnrollmentDate use mixed date formats.
  • NINVerified mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are duplicates from a quarterly backup file being merged with the live register.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook, select the Beneficiary Records sheet, click Transform Data. Confirm header promotion, then remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass. This is especially important for BeneficiaryStatus, DonorOrganisation, and Program, each of which has trailing-space variants.
  3. Standardise Gender: Capitalize, then Replace Values to map M and m to Male and F and f to Female.
  4. Standardise Program: Capitalize Each Word, then Replace Values to fold Healthcare into Healthcare Outreach (if the business confirms they are the same), and to fold all food support and food support variants into Food Support.
  5. Standardise DonorOrganisation: for acronyms like USAID and UNICEF, use Text.Upper rather than Capitalize Each Word (which would produce Usaid and Unicef), using a custom column: if Text.Length(Text.Trim([DonorOrganisation])) <= 6 then Text.Upper(Text.Trim([DonorOrganisation])) else Text.Proper(Text.Trim([DonorOrganisation])).
  6. Clean GrantAmount and MonthlyIncome with the standard currency-stripping and Decimal Number conversion technique.
  7. Handle MonthlyIncome blanks deliberately: after the currency conversion, add a conditional column IncomeDataStatus = if [MonthlyIncome] = null and [BeneficiaryStatus] = "Active" then "Income not captured - follow up" else if [MonthlyIncome] = null then "Not applicable" else "Captured", distinguishing missing data from expected blanks.
  8. Fix HouseholdSize: set to Whole Number, then add a HouseholdFlag column: if [HouseholdSize] < 1 then "Invalid - negative" else if [HouseholdSize] > 15 then "Unusually large - verify" else "OK".
  9. Fix DateOfBirth and EnrollmentDate: convert both to Date type and resolve errors. Add an Age column. Flag beneficiaries below age 5 or above 90 as potentially erroneous.
  10. Handle ExitDate logically: convert to Date type, then add an ExitDateCheck column: if [BeneficiaryStatus] = "Completed" or [BeneficiaryStatus] = "Withdrawn" then if [ExitDate] = null then "Exit date missing for closed case" else "OK" else "Expected blank for active case".
  11. Standardise BeneficiaryStatus: Trim is already done, Capitalize Each Word, then Replace Values to produce a four-value list (Active, Completed, Suspended, Withdrawn).
  12. Standardise NINVerified into a Logical True/False column with Replace Values before changing Data Type. Close and load as NGO_Beneficiaries_Clean.
Dataset 23

Brand Advertising Campaign Records

Domain: Media and Advertising  |  File: 23_media_advertising_campaigns_DIRTY.xlsx

A Lagos-based media buying agency exports a campaign performance register covering television, radio, billboard, digital, and print campaigns run on behalf of ten major Nigerian and multinational brands. The register merges data from three media monitoring systems that were never aligned on field conventions, so budget figures, click-through rates, and status labels all have multiple representations.

Columns: CampaignID, BrandName, MediaType, AgencyName, CampaignTitle, StartDate, EndDate, BudgetNGN, ActualSpendNGN, Impressions, ClickThroughRate, CampaignStatus, Region, ROI_pct, ApprovedByNBC

Data Quality Issues Deliberately Built In

  • MediaType has inconsistent casing and overlapping labels (Television, television, Digital, Digital/Social Media, Social Media - where the last three may or may not be the same channel depending on the campaign brief).
  • BudgetNGN and ActualSpendNGN are stored as text with mixed currency notation.
  • ActualSpendNGN exceeds BudgetNGN by more than 10 percent in some rows, which is a budget overrun flag for the finance team.
  • Impressions contains negative values and zeros, which are physically impossible for a launched campaign.
  • ClickThroughRate is inconsistently formatted - some rows use a percentage symbol (3.5%) while others use a bare decimal (3.5) for the same type of value, making aggregation wrong if the column is treated as uniform.
  • ROI_pct is missing for many rows and has both positive and negative values, the latter representing loss-making campaigns.
  • CampaignStatus mixes casing, trailing spaces, and overlapping labels (Running, running, COMPLETED, completed with a trailing space, On Hold).
  • EndDate is blank for currently running campaigns, which is expected, but also blank for some Completed campaigns, which is a data gap.
  • StartDate uses mixed date formats.
  • ApprovedByNBC mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are duplicate campaign entries from a monthly report being merged with the master register.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook, select the Campaign Records sheet, click Transform Data. Confirm header promotion, then remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass.
  3. Standardise MediaType: Capitalize Each Word, then present the business with a reconciliation question - are Digital, Digital/Social Media, and Social Media the same channel or different channels? Document the answer as a comment in the step name. Apply Replace Values based on the agreed answer.
  4. Standardise CampaignStatus: Trim is already done, Capitalize Each Word, then Replace Values to produce a five-value list (Running, Completed, Paused, Cancelled, On Hold).
  5. Clean BudgetNGN and ActualSpendNGN with the standard currency-stripping and Decimal Number conversion technique. For billion-naira values, the chain must also strip commas (add a Text.Replace step for the comma character) before the type conversion.
  6. Add a BudgetOverrun flag: if [ActualSpendNGN] > [BudgetNGN] * 1.10 then "Budget overrun - flag for finance" else "OK".
  7. Fix Impressions: set to Whole Number, then filter for values less than or equal to 0 and route to a review query named Campaigns_InvalidImpressions.
  8. Standardise ClickThroughRate: Replace Values to remove the percentage symbol (%) from all rows that have it, Trim, then set to Decimal Number. After the type change, all values are now consistent decimals representing the same percentage concept - document this assumption clearly in the step name.
  9. Handle ROI_pct: Trim, remove any trailing percentage symbol if present, set to Decimal Number. Null values should remain null - a missing ROI means not yet calculated, not zero.
  10. Handle EndDate logically: convert to Date type, then add an EndDateCheck column: if [CampaignStatus] = "Completed" and [EndDate] = null then "End date missing for completed campaign" else "OK".
  11. Fix StartDate: convert to Date type and resolve errors. Add a CampaignDuration column = Duration.Days([EndDate] - [StartDate]) where both dates are valid.
  12. Standardise ApprovedByNBC into a Logical True/False column with Replace Values before changing Data Type. Close and load as AdCampaigns_Clean.
Dataset 24

Airport Passenger and Flight Records

Domain: Aviation and Transport  |  File: 24_airport_passenger_flight_records_DIRTY.xlsx

A Nigerian civil aviation data analyst exports a passenger and flight log from five international and domestic airports covering Air Peace, Ibom Air, United Nigeria Airlines, and Dana Air operations. The log merges data from three airport information systems that use different conventions for airline names, cabin class labels, and flight status codes.

Columns: PassengerID, PassengerName, PassengerPhone, Airline, FlightNumber, DepartureAirport, ArrivalAirport, FlightDate, DepartureTime, CabinClass, TravelType, TicketPrice, BaggageWeight_kg, FlightStatus, Nationality

Data Quality Issues Deliberately Built In

  • Airline has inconsistent casing and trailing spaces for the same carrier (Air Peace, air peace, IBOM AIR, Air Peace with a trailing space, Dana Air with a trailing space).
  • CabinClass mixes full names and abbreviated names for the same class (Business, Business Class, BUSINESS; Economy, Economy with a trailing space).
  • TravelType has a typographical error embedded in the dirty data (Domesctic instead of Domestic, Internatonal instead of International) alongside the usual casing variants.
  • DepartureTime mixes 24-hour and 12-hour AM/PM formats in the same column.
  • FlightDate uses mixed date formats.
  • DepartureAirport and ArrivalAirport are occasionally identical, producing a same-origin-and-destination record that should never exist for a completed trip.
  • TicketPrice is stored as text with mixed currency notation.
  • BaggageWeight_kg is missing for some rows and should be distinguished from a zero-baggage passenger.
  • FlightStatus has inconsistent casing and trailing spaces (On Time, on time, DELAYED, Cancelled with a trailing space).
  • Nationality mixes casing and has trailing spaces (Nigerian, NIGERIAN, Nigerian with a trailing space).
  • Around four percent of rows are duplicate passenger records from an airport gate scanner upload that ran twice.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook, select the Passenger Records sheet, click Transform Data. Confirm header promotion, then remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass. Trailing spaces are responsible for Airline, CabinClass, FlightStatus, and Nationality duplicates and must be removed before any Replace Values step.
  3. Standardise Airline: Capitalize Each Word, then Replace Values to fold any remaining variants. Airline names are proper nouns, so Capitalize Each Word is the right approach rather than UPPERCASE.
  4. Standardise CabinClass: Capitalize Each Word, then Replace Values to fold Business Class into Business and Economy with a trailing space (already handled by Trim) into Economy, producing a clean three-value list (Economy, Business, First Class).
  5. Fix TravelType: Replace Values to correct the two typos first (Domesctic into Domestic, Internatonal into International), then Capitalize Each Word to standardise the remaining casing variants.
  6. Fix DepartureTime: add a custom column that uses Time.FromText with a try/otherwise wrapper to parse both 24-hour (14:30) and 12-hour (2:30 PM) formats into a consistent Time type, replacing errors with null and flagging them for review.
  7. Fix FlightDate: convert to Date type and resolve format errors using the standard technique.
  8. Add a SameAirportCheck column: if [DepartureAirport] = [ArrivalAirport] then "Same origin and destination - review" else "OK" to catch logically impossible routes.
  9. Clean TicketPrice with the standard currency-stripping and Decimal Number conversion technique.
  10. Handle BaggageWeight_kg: set to Decimal Number, then add a BaggageStatus column: if [BaggageWeight_kg] = null then "Not recorded" else if [BaggageWeight_kg] = 0 then "Hand luggage only" else "Checked baggage" so the three states are explicit.
  11. Standardise FlightStatus: Trim is already done, Capitalize Each Word, then Replace Values to produce a clean five-value list (On Time, Delayed, Cancelled, Diverted, Boarding).
  12. Standardise Nationality: Trim is already done, Capitalize Each Word. Close and load as Airport_Passengers_Clean.
Dataset 25

Waste Management and Sanitation Collection Records

Domain: Environment and Public Services  |  File: 25_waste_management_sanitation_DIRTY.xlsx

A state waste management authority exports a collection log from six local government areas in Lagos and Abuja covering household, medical, industrial, electronic, recyclable, and hazardous waste streams. The log is compiled from paper route sheets keyed in by data entry clerks at three depots, so unit conventions for weight, trip counts, and disposal site names are inconsistent across the depots.

Columns: RecordID, CollectionDate, LGA, Ward, WasteType, TruckID, DriverName, WeightCollected_kg, TripCount, CollectionStatus, DisposalSite, CollectionCost, State, RecyclingDone

Data Quality Issues Deliberately Built In

  • WasteType has trailing spaces and inconsistent casing for the same category (Household Waste, household, MEDICAL WASTE, Recyclable with a trailing space, industrial waste).
  • WeightCollected_kg mixes kilograms and pounds in the same column - some depot clerks entered values from a scale that displayed in pounds, appending the unit text "lbs" to the value.
  • TripCount contains negative values and zeros, which should not appear on a completed route record.
  • LGA has inconsistent casing across the three depots (Ikeja LGA, ikeja lga, SURULERE LGA).
  • CollectionStatus has trailing spaces and inconsistent casing (Collected, collected, MISSED, Missed with a trailing space, Partial Collection).
  • DisposalSite has N/A values, blank values, and genuinely missing entries that need separate treatment since a hazardous waste collection record with no disposal site is a regulatory compliance gap.
  • CollectionCost is stored as text with mixed currency notation.
  • TruckID is occasionally missing, which is an operational flag since every collection trip must be assigned to a vehicle.
  • CollectionDate uses mixed date formats.
  • RecyclingDone mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are duplicate collection entries from a depot daily upload that ran twice.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook, select the Waste Collection Records sheet, click Transform Data. Confirm header promotion, then remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass to remove trailing spaces from WasteType, CollectionStatus, and DisposalSite.
  3. Standardise LGA: Capitalize Each Word, which collapses Ikeja LGA, ikeja lga, and SURULERE LGA into their correctly cased forms in one step.
  4. Standardise WasteType: Capitalize Each Word, then Replace Values to fold household into Household Waste and industrial waste into Industrial Waste, producing a clean six-value controlled vocabulary.
  5. Standardise CollectionStatus: Trim is already done, Capitalize Each Word, then Replace Values to produce a clean five-value list (Collected, Missed, Partial Collection, Pending, Delayed).
  6. Fix WeightCollected_kg: add a custom column that checks Text.Contains([WeightCollected_kg], "lbs") - if true, extract the numeric portion with Text.BeforeDelimiter([WeightCollected_kg], " "), convert to Decimal Number, and multiply by 0.4536 to convert to kilograms; if false, convert the value directly to Decimal Number. Remove the original text column and rename the calculated column to WeightCollected_kg.
  7. Fix TripCount: set to Whole Number, then filter for values less than or equal to 0 and route to a review query named Waste_InvalidTripCount.
  8. Clean CollectionCost with the standard currency-stripping and Decimal Number conversion technique.
  9. Handle DisposalSite nulls deliberately: after Trim and null standardisation, add a DisposalSiteCheck column: if [DisposalSite] = null and [WasteType] = "Hazardous" then "COMPLIANCE RISK - no disposal site for hazardous waste" else if [WasteType] = "Medical Waste" and [DisposalSite] = null then "COMPLIANCE RISK - no disposal site for medical waste" else if [DisposalSite] = null then "Disposal site not recorded" else "OK".
  10. Flag missing TruckID: add a TruckFlag column = if [TruckID] = null then "No vehicle assigned - operational gap" else "OK".
  11. Fix CollectionDate: convert to Date type and resolve errors. Add a WeekNumber column using Date.WeekOfYear([CollectionDate]) to support a weekly waste volume trend analysis.
  12. Standardise RecyclingDone into a Logical True/False column with Replace Values before changing Data Type. Close and load as WasteCollection_Clean.
Dataset 26

Nigerian Stock Exchange Trading Records

Domain: Capital Markets and Investment  |  File: 26_capital_market_trading_records_DIRTY.xlsx

A capital market analyst at a Lagos stockbroking firm exports a trading log covering equities transactions across seven stockbroking houses on the Nigerian Exchange Group (NGX). The log merges exports from three different order management systems that each format trade values, settlement dates, and order types differently.

Columns: TradeID, TraderName, TraderPhone, BrokerName, SecurityName, Sector, OrderType, Quantity, PricePerShare, TotalTradeValue, Commission, TradeDate, SettlementDate, OrderStatus, CHNNumber

Data Quality Issues Deliberately Built In

  • OrderType mixes full labels and abbreviations with inconsistent casing (Buy, buy, Market Buy, Limit Buy; Sell, sell, SELL, Market Sell, Limit Sell).
  • Quantity contains negative values and zeros, which should not appear on an executed trade record.
  • PricePerShare, TotalTradeValue, and Commission are stored as text with mixed currency notation. Some TotalTradeValue entries for high-volume trades include thousands-separator commas embedded in the text that must be stripped before the currency symbols.
  • TotalTradeValue should equal Quantity multiplied by PricePerShare, and rows where it does not match reveal price or quantity transcription errors.
  • SettlementDate should be exactly T+2 business days from TradeDate for equities under NGX rules, and rows where it is not are settlement risk flags.
  • SettlementDate occasionally falls before TradeDate, which is logically impossible.
  • SecurityName has inconsistent casing (Dangote Cement PLC, dangote cement plc, ZENITH BANK PLC).
  • OrderStatus has inconsistent casing and a trailing-space variant (Executed, executed, CANCELLED, Pending with a trailing space).
  • CHNNumber is missing for some traders, which is a compliance gap since every registered investor on the NGX must have a Central Securities Clearing System holder number.
  • Around five percent of rows are duplicate trade entries from a settlement system reconciliation file being merged with the execution log.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook, select the Trading Records sheet, click Transform Data. Set CHNNumber to Text type immediately on load to preserve leading zeros. Remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass.
  3. Standardise SecurityName: Capitalize Each Word resolves all casing variants in one step since security names are proper nouns.
  4. Standardise OrderType: Capitalize Each Word, then Replace Values to agree with the business on whether Market Buy and Limit Buy are the same category as Buy for reporting purposes, or whether they need to remain distinct. Document the decision as the step name.
  5. Standardise OrderStatus: Trim is already done, Capitalize Each Word, then Replace Values to produce a clean five-value list (Executed, Pending, Cancelled, Partially Filled, Expired).
  6. Clean PricePerShare, TotalTradeValue, and Commission: before stripping currency symbols, add a Replace Values step to remove commas from the TotalTradeValue column first (since a value like "NGN 1,250,000" must have its comma removed before the NGN prefix is stripped, otherwise a Text.Replace chain leaves the comma in the numeric string). Then apply the standard currency-stripping chain and set to Decimal Number.
  7. Fix Quantity: set to Whole Number, filter for values less than or equal to 0, and route those rows to a review query named Trades_InvalidQuantity.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook, select the Trip Records sheet, click Transform Data. Remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass. This resolves the VehicleCategory, PaymentMethod, and TripStatus trailing-space variants immediately.
  3. Standardise Platform: for all-caps acronyms and branded names, use a Replace Values lookup table (mapping uber to Uber, BOLT to Bolt, Lagride to LAGRIDE if LAGRIDE is the official capitalisation, etc.) so the result matches each platform's official brand name rather than relying on Capitalize Each Word, which would produce wrong output for inDrive and LAGRIDE.

  5. Split TripStartTime in two stages: first Split Column > By Delimiter (space) into TripDate and TripTime halves. Then convert TripDate to Date type and TripTime to Time type, using try/otherwise wrappers for the mixed-format handling.
  6. Fix TripDuration_min: set to Whole Number, filter for values less than or equal to 0, and route to a review query named Trips_InvalidDuration.
  7. Resolve the Distance_km unit mix: add a custom column that checks Text.EndsWith(Text.Trim([Distance_km]), "mi") - if true, extract the numeric portion with Text.BeforeDelimiter, convert to Decimal Number, multiply by 1.60934 to convert to kilometres; if false, convert directly to Decimal Number. Drop the original text column and name the result Distance_km.
  8. Clean FareAmount with the standard currency-stripping and Decimal Number conversion technique.
  9. Standardise PaymentMethod: Trim is already done, Capitalize Each Word.
  10. Standardise TripStatus: Capitalize Each Word, then Replace Values to decide - with the business - whether Driver No Show and No Show are the same status and fold them accordingly.
  11. Fix RiderRating and DriverRating: set to Whole Number, then add conditional columns RiderRatingValid = if [RiderRating] >= 1 and [RiderRating] <= 5 then [RiderRating] else null and the same for DriverRating, converting out-of-range values to null rather than removing the row.
  12. Close and load as RideHailing_Trips_Clean.

A fintech compliance analyst exports a transaction log covering eight digital wallet and mobile money platforms (Opay, PalmPay, Kuda, Carbon, FairMoney, Moniepoint, VFD Microfinance, and Piggyvest) for an AML/CFT pattern screening exercise. Data Quality Issues Deliberately Built In

  • TransactionType has trailing spaces and inconsistent casing for the same type (Send Money, send money, SEND MONEY, Airtime, Airtime Top-Up - where the last two may be the same category).
  • Amount is stored as text with mixed currency notation, and some high-value transfers have thousands-separator commas embedded that must be stripped before the currency symbols.
  • TransactionFee is frequently blank, which needs to be treated as zero (fee-free transaction) rather than as missing data, since platforms like Kuda advertise zero-fee transfers.
  • Narration mixes genuine free-text entries, null text placeholders (the text "null" and "N/A"), and genuine blank values.
  • DateTime combines a mixed-format date with a time or date-time string in one text field requiring splitting.
  • TransactionStatus has inconsistent casing, trailing spaces, and an overlapping label (Successful, successful, FAILED, Success, Failed with a trailing space - where Successful and Success are the same state).

  • RecipientPhone is blank for non-transfer transaction types (bill payment, airtime, savings), which is expected, but blank for Send Money transactions, which is a data quality gap requiring flagging.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Connect to the workbook, select the Wallet Transactions sheet, click Transform Data. Remove duplicate rows on all columns first.
  2. Trim and Clean all text columns in one pass to handle TransactionType, TransactionStatus, and DeviceType trailing-space variants.
  3. Standardise TransactionType: Capitalize Each Word, then Replace Values to fold Airtime into Airtime Top-Up (or vice versa, per the business decision), and to fold Send Money variants into one canonical form. Produce a clean seven-value type list.
  4. Standardise TransactionStatus: Trim is already done, Capitalize Each Word, then Replace Values to fold Success into Successful and Failed with a space (already handled by Trim) into Failed, producing a four-value list (Successful, Failed, Pending, Reversed).
  5. Standardise DeviceType: Trim is already done. Replace Values to fold IOS into iOS (since this is the correct capitalisation) and android into Android. Capitalize Each Word will not handle iOS correctly, so use Replace Values for all variants.
  6. Clean Amount: before stripping currency symbols, add a Replace Values step to remove commas first. Then apply the standard currency-stripping chain (naira sign, NGN, naira word, N prefix) and Trim, then set to Decimal Number.
  7. Handle TransactionFee: clean the currency text the same way. Then, after the type conversion, replace null values with 0 using Replace Value on null (not a null-marker text replacement, but a true null replacement after type conversion), since a missing fee on a successfully executed transaction means the fee was zero.
  8. Clean Narration: Replace Values to convert the text "null" and "N/A" into a true null, leaving genuine free-text comments untouched. Add a HasNarration conditional column (true where Narration is not null) for AML screening filters.
  9. Split DateTime in two stages: Split Column > By Delimiter (space) into DatePart and TimePart. Convert DatePart to Date type using try/otherwise, and TimePart to Time type using try/otherwise.
  10. Handle RecipientPhone logically: apply the standard digits-only cleaning (Text.Select), then add a RecipientCheck column: if [TransactionType] = "Send Money" and [RecipientPhone] = null then "Missing recipient phone for transfer - AML flag" else "OK".
  11. Standardise BVN_Verified into a Logical True/False column with Replace Values before changing Data Type. Close and load as Fintech_Transactions_Clean.

Facilitator Notes

  • Start every session by showing Column Quality (View > Column Quality) and Column Distribution (View > Column Distribution) in the Power Query Editor before touching any step. The visual percentage bars for valid, empty, and error cells give trainees an instant overview of every problem column without a single formula.
  • Demonstrate that the styled formatting in these .xlsx source files has zero effect inside Power Query. Header colours, alternating row fills, and bold fonts are a common source of trainee confusion when moving from raw CSV work to formatted workbook work.
  • Use the Reference query pattern throughout this set. When a lookup table is needed (for category standardisation, broker name normalisation, or grade mapping), create it as a separate named query and use Merge Queries with a Left Outer join rather than stacking Replace Values steps. This produces more maintainable, reusable queries.
  • Teach the difference between a Remove Rows step and a routing-to-review-table step. Silent row deletion destroys evidence. A duplicate-query-then-filter approach keeps a separate companion query holding every flagged row so the business team can investigate at source.
  • For the financial and trading datasets (DS 26, DS 28), reinforce that stripping thousands-separator commas from amount fields must happen before the Replace Values steps that strip currency words - otherwise a field like "NGN 1,250,000" becomes "1250000" correctly only if the comma is removed first as part of the strip chain.
  • Use Group By as a diagnostic throughout, not just as a final reporting step. Grouping a Status or Category column and counting rows before cleaning reveals the full universe of variants that need Replace Values treatment. Grouping again after cleaning confirms the consolidation worked correctly.
  • For the exam results dataset (DS 29), use the grade standardisation as a teaching moment on the difference between data cleaning (making Grade A and grade a the same value) and data modelling (deciding whether A1 maps to Distinction and B2 maps to Credit for downstream scoring logic, which belongs in a DAX calculated column or a data model relationship, not in Power Query).
