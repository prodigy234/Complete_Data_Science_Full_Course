Introduction

This is the second set of ten deliberately dirty, Nigerian business-context datasets for teaching Power Query data cleaning in both Microsoft Excel and Microsoft Power BI Desktop. The first set covered retail, banking, HR, healthcare, education, e-commerce, telecom, real estate, logistics, and food delivery. This set covers ten entirely different domains: insurance, microfinance, hospitality, agriculture, government payroll, petroleum retail, university enrollment, electricity billing, pharmaceutical inventory, and construction project management. All ten files simulate the exact kind of messy data that analysts receive from operational systems, manual registers, and inter-departmental exports in Nigerian organisations, and every quality problem in every file was deliberately inserted to map to a specific, namable cleaning technique in Power Query.

Open each CSV file through Power Query in Excel (Data tab, Get Data, From File, From Text/CSV, then click Transform Data) or in Power BI Desktop (Home, Get Data, Text/CSV, then click Transform Data). Follow the numbered steps for each dataset inside the Power Query Editor. Where a technique needs a different ribbon path in Excel versus Power BI, the note is given inline. Every step was written so a trainer can narrate it live in front of a class while learners follow on their own machines.

General Cleaning Checklist - Apply to Every Dataset

  1. Load via Power Query - never clean data by hand in the CSV. All cleaning happens in the Applied Steps pane so it is repeatable, documented, and rerunnable on the next export.
  2. Check the header row was promoted correctly (Home > Use First Row as Headers) and that no data row was accidentally treated as a header.
  3. Review the column list on load - right-click each column header to confirm the auto-detected data type is correct. Currency-as-text, dates-as-text, and IDs-as-numbers are the three most common auto-detect failures.
  4. Run Remove Duplicates (Home > Remove Rows > Remove Duplicates, selecting all columns) early, before any other transformations, so later steps are not applied twice to the same row.
  5. Apply Trim and Clean (Transform > Format > Trim, then Format > Clean) to every text column in one multi-select pass before touching any individual column, because trailing spaces make Replace Values fail silently.
  6. Build a standard null replacement pass: select all text columns, Replace Values to convert blank, N/A, NULL, nil, -, --, unknown, and ? into a true null, so downstream measures count missing data correctly.
  7. Standardise casing (Capitalize Each Word for names and categories, UPPERCASE for codes and short identifiers) before trying Replace Values on category columns, because a Replace Values search is case-sensitive in Power Query by default.
  8. Fix numeric columns that arrived as text - strip all currency symbols and words (NGN, naira, the naira sign) with Replace Values, Trim the result, then change the Data Type to Decimal Number. Errors that appear after the type change should be investigated with Keep Errors before being removed.
  9. Fix date columns by setting the Data Type to Date and immediately filtering the column for errors to find placeholder text values such as 00/00/0000, unknown date, and not set, which need a business decision, not a formula guess.
  10. Rename every Applied Step (right-click, Rename) with a short plain-English description. A query that reads "Trimmed all text columns", "Replaced null markers", "Fixed currency fields", "Standardised date columns" is far more useful to a future analyst than "Changed Type1", "Replaced Value2".

Dataset 11Insurance Claims Processing Register

Domain: Insurance  |  File: 11_insurance_claims_DIRTY.csv

A Lagos-based insurance broker compiles a claims register spanning motor, life, health, and property policies across several underwriting partners. The register is maintained in a shared Excel workbook by a rotating team of claims officers, so formatting standards have drifted across every column.

Columns: ClaimID, PolicyNumber, PolicyType, InsurerName, CustomerName, CustomerPhone, IncidentDate, ClaimDate, CauseOfClaim, PremiumPaid, ClaimAmount, PayoutAmount, ClaimStatus, State, PolicyActive

Data Quality Issues Deliberately Built In

  • PolicyType has overlapping, inconsistently cased entries for the same product (Motor, Motor Comprehensive; Life, Life (Term); Health, Health (Family)) that need consolidation into a clean product hierarchy.
  • IncidentDate and ClaimDate both use mixed date formats, and some ClaimDate values fall before IncidentDate, which is logically impossible.
  • CauseOfClaim has trailing spaces and mixed casing for the same cause (Accident, accident; Theft, Theft; Fire, FIRE).
  • PremiumPaid, ClaimAmount, and PayoutAmount are all stored as text with mixed currency notation.
  • PayoutAmount is blank for many rows, which may mean no payout was made or that the value was simply not recorded.
  • ClaimStatus uses inconsistent casing and overlapping labels (Approved, Partially Approved, Settled) that need a business decision on how to group them.
  • PolicyActive mixes Yes/No, Y/N, 1/0, and TRUE/FALSE for the same boolean fact.
  • CustomerPhone has the standard multi-format problem present across all Nigerian business datasets.
  • Around five percent of rows are exact duplicates inserted when the shared workbook was pasted between tabs.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV (Get Data > From Text/CSV > Transform Data) and immediately set PolicyNumber to Text type to prevent Power Query from dropping leading zeros or misinterpreting the format.
  2. Remove duplicate rows on all columns using Home > Remove Rows > Remove Duplicates before any other step.
  3. Trim and Clean all text columns in one multi-select pass (Transform > Format > Trim, then Format > Clean) to remove leading, trailing, and double spaces and non-printable characters.
  4. Standardise CauseOfClaim: apply Capitalize Each Word, then use Replace Values for any remaining variants that capitalisation alone does not resolve.
  5. Standardise PolicyType: build a small two-column lookup table as a separate query (DirtyType mapped to CleanType), then use Merge Queries (Left Outer join on PolicyType) to bring in the canonical product name and remove the original column. This is cleaner than stacking 10 Replace Values steps.
  6. Fix IncidentDate and ClaimDate: set both to Date type, filter on errors to find and null out placeholder text values, then add a validation column ClaimAfterIncident = [ClaimDate] >= [IncidentDate] to flag the logically impossible rows for the claims team to investigate at source rather than silently deleting them.
  7. Clean PremiumPaid, ClaimAmount, and PayoutAmount: Replace Values to strip the naira sign, NGN, and the word naira, Trim the result, set Data Type to Decimal Number. Inspect errors before removing.
  8. Handle PayoutAmount blanks deliberately: after converting to numeric, add a conditional column PayoutStatus = if [PayoutAmount] = null and [ClaimStatus] = "Approved" then "Payout missing - review" else if [PayoutAmount] = null then "No payout" else "Paid".
  9. Standardise ClaimStatus: Trim, Capitalize Each Word, then apply a Replace Values pass to consolidate Settled into Approved (or whatever the business says is the correct mapping) so reports use a consistent three-bucket system.
  10. Standardise PolicyActive into a true Logical (True/False) column using the Replace Values technique (Y, 1, yes, TRUE all mapped to true, then change Data Type to True/False).
  11. Clean CustomerPhone using Text.Select([CustomerPhone], {"0".."9","+"}) in a custom column to strip all formatting characters, leaving only the digits and any leading plus sign.
  12. Rename every Applied Step in plain English, then close and load as Claims_Register_Clean.

Dataset 12Microfinance Institution Loan Records

Domain: Microfinance and Credit  |  File: 12_microfinance_loan_records_DIRTY.csv

A microfinance bank serving small traders and farmers across multiple states exports its loan portfolio register for a quarterly non-performing loan (NPL) review. The register merges records from two branch systems that were never aligned on formatting or status terminology.

Columns: LoanID, BorrowerName, BorrowerPhone, Gender, LoanPurpose, PrincipalAmount, InterestRate_pct, DisbursementDate, MaturityDate, AmountRepaid, LoanStatus, CollateralType, LoanOfficer, State, NPL_Flag

Data Quality Issues Deliberately Built In

  • LoanPurpose has trailing spaces and mixed casing for the same purpose category (Business Expansion, business; School Fees, SCHOOL FEES; Medical Bills, Medical).
  • PrincipalAmount, AmountRepaid are text with mixed currency notation.
  • InterestRate_pct is missing for some rows and stored inconsistently (18.5 versus 18.5% with the percent symbol appended).
  • AmountRepaid exceeds PrincipalAmount in some rows by more than 10 percent, which may indicate data entry errors or partial interest records being double-counted.
  • LoanStatus mixes casing and has overlapping labels from the two branch systems (Active, active; Fully Repaid, Fully repaid; Defaulted, DEFAULTED; Written Off, Overdue).
  • CollateralType has inconsistent casing and a high rate of blanks that need to be distinguished from genuinely uncollateralised loans versus missing entries.
  • NPL_Flag mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • DisbursementDate and MaturityDate use mixed formats, and some MaturityDate values predate DisbursementDate, which is logically impossible.
  • Gender mixes Male/Female with single-letter M/F in different cases.
  • Around four percent of rows are duplicate portfolio entries from the two-system merge.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove duplicate rows on all columns first.
  2. Trim and Clean all text columns in one pass.
  3. Standardise LoanPurpose: Capitalize Each Word, then Replace Values to fold short-form entries (business, SCHOOL FEES) into their canonical long-form counterparts.
  4. Clean PrincipalAmount and AmountRepaid with the standard currency-stripping Replace Values chain (naira sign, NGN, naira), Trim, then set Data Type to Decimal Number.
  5. Fix InterestRate_pct: Replace Values to strip the percent symbol where it was appended, Trim, then set to Decimal Number. After the type change, filter for nulls and errors to isolate missing rates for the portfolio management team.
  6. Add an OverRepayment flag: a conditional column that checks if [AmountRepaid] > [PrincipalAmount] * 1.10, and labels those rows "Overpayment - review" rather than silently correcting them, since the cause could be interest capture, rounding, or genuine entry error.
  7. Standardise LoanStatus: Trim first (critical, because "paid " and "paid" are different before trimming), Capitalize Each Word, then build a lookup table that maps both branch system variants to one canonical status list (Active, Fully Repaid, Defaulted, Written Off, Overdue) and merge it in.
  8. Handle CollateralType nulls deliberately: Replace Values to convert blank, N/A, and None into two distinct values - "None (Uncollateralised)" where the business has confirmed no collateral was taken, or null where the data is simply missing - using a conditional column that the trainer can discuss with the class as a data governance decision.
  9. Standardise Gender: Replace Values to map M, m, male into Male and F, f, female into Female.
  10. Standardise NPL_Flag into a Logical True/False column with Replace Values before changing Data Type.
  11. Fix DisbursementDate and MaturityDate: convert both to Date, then add a MaturityAfterDisbursement validation column to flag rows where MaturityDate is on or before DisbursementDate.
  12. Close and load as MFI_Loans_Clean.

Dataset 13Hotel and Hospitality Reservation Records

Domain: Hospitality  |  File: 13_hotel_hospitality_reservations_DIRTY.csv

A hospitality group with properties in Lagos, Abuja, and Port Harcourt exports a consolidated reservation log from its three property management systems ahead of a revenue and occupancy analysis. Each property uses a slightly different PMS version, so nearly every column has formatting inconsistencies.

Columns: ReservationID, GuestName, GuestPhone, HotelName, RoomType, CheckInDate, CheckOutDate, NumberOfNights, RoomRatePerNight, TotalBill, BookingSource, PaymentStatus, State, Nationality, EarlyCheckIn

Data Quality Issues Deliberately Built In

  • RoomType has inconsistent casing for the same room category (Standard, standard, SUITE, Presidential all representing different tiers, but standard and Standard representing the same tier).
  • NumberOfNights contains a negative value that should never occur in a valid reservation.
  • CheckInDate and CheckOutDate both use mixed date formats, and CheckOutDate is blank for some rows that may represent ongoing stays or missing data.
  • RoomRatePerNight and TotalBill are stored as text with mixed currency notation, and TotalBill is blank for some rows.
  • A validation gap exists: for completed stays, TotalBill should equal NumberOfNights times RoomRatePerNight, and discrepancies can reveal rate override errors.
  • BookingSource mixes formats for the same channel (Walk-in, Walk in, walk-in; ONLINE, Online, online).
  • PaymentStatus uses inconsistent casing and overlapping labels (Paid, paid, PAID; Partial, Partially Paid; Pending, Pending Payment).
  • Nationality has inconsistent casing (Nigerian, nigerian, NIGERIAN) and is occasionally missing.
  • EarlyCheckIn mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are duplicate reservations from PMS sync collisions.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove duplicate rows on all columns first.
  2. Trim and Clean all text columns in one multi-select pass.
  3. Standardise RoomType: Capitalize Each Word, then Replace Values to fold variant spellings of the same tier into one canonical value (Standard, Deluxe, Suite, Executive, Presidential, Twin).
  4. Fix NumberOfNights: set to Whole Number, then filter for values less than 1 and route those rows to a separate review query named Reservations_InvalidNights, since a negative or zero-night stay needs a reservations officer to resolve it.
  5. Fix CheckInDate and CheckOutDate: convert both to Date type, resolve errors the same way as earlier datasets, then add a StayValidation conditional column: if [CheckOutDate] is null and the row is not flagged as an ongoing stay then "Missing checkout date" else if [CheckOutDate] <= [CheckInDate] then "Checkout before checkin - review" else "OK".
  6. Clean RoomRatePerNight and TotalBill with the standard currency-stripping and Decimal Number conversion technique.
  7. Add a calculated ExpectedBill column = [NumberOfNights] * [RoomRatePerNight] (only where NumberOfNights is positive and not null), then add a BillVariance column = [TotalBill] - [ExpectedBill] to surface rate-override rows for the revenue manager.
  8. Standardise BookingSource: Trim, Capitalize Each Word, then Replace Values to fold "Walk in" and "walk-in" into "Walk-In" and "ONLINE" and "online" into "Online", producing a clean five-value source list.
  9. Standardise PaymentStatus: Trim, Capitalize Each Word, then Replace Values to produce a four-value list (Paid, Partial, Pending, Refunded).
  10. Standardise Nationality: Trim, Capitalize Each Word. Nulls are acceptable here - missing nationality is not a blocking data quality issue for revenue reporting.
  11. Standardise EarlyCheckIn into a Logical True/False column with Replace Values before changing Data Type.
  12. Close and load as Hotel_Reservations_Clean.

Dataset 14Agricultural Produce Market Sales Records

Domain: Agriculture  |  File: 14_agricultural_market_produce_DIRTY.csv

The records unit at a state government agricultural commodities board exports a seasonal produce movement log from five major markets in southern and northern Nigeria. Field officers use paper forms that are keyed in by different data entry staff, so units, grades, and produce names have no standardisation.

Columns: RecordID, FarmerName, FarmerPhone, ProduceName, Quantity, Unit, PricePerUnit, TotalValue, Market, SaleDate, ProduceGrade, StorageFacility, State, TransportMode, Certified_Organic

Data Quality Issues Deliberately Built In

  • Unit mixes inconsistent labels for the same physical unit (kg, KG, Bags, bags, Crates, crates, Tonnes, tonnes) making any sum-by-unit report meaningless.
  • ProduceGrade has overlapping, inconsistently cased grade labels (Grade A, A, Premium are not the same scale, but Grade A and grade a refer to the same grade).
  • Quantity contains zeros and negative values that should never appear in a produce sales record.
  • PricePerUnit and TotalValue are stored as text with mixed currency notation.
  • TotalValue is missing for some rows and should be recomputable from Quantity times PricePerUnit where both are valid.
  • StorageFacility mixes inconsistent casing (Cold Room, COLD ROOM, cold room), the text N/A, and empty blanks.
  • TransportMode has inconsistent casing (Truck, truck, TRUCK).
  • SaleDate uses mixed date formats.
  • ProduceName is occasionally blank.
  • Certified_Organic mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are exact duplicates from a multi-sheet paste of the same market's records.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove duplicate rows on all columns first.
  2. Trim and Clean all text columns in one pass.
  3. Standardise Unit: Capitalize Each Word first to collapse kg/KG and bags/Bags, then Replace Values to produce a clean four-value list (Kg, Bags, Crates, Tonnes) - note that kg is conventionally lowercase but for Power Query display purposes a consistent single choice is more important than typographic convention.
  4. Standardise ProduceGrade: Trim, Capitalize Each Word, then build a lookup table that maps A to Grade A, B to Grade B, Premium to Grade A (if the business confirms this equivalence), and Reject to Grade C, and merge it in rather than stacking Replace Values steps.
  5. Fix Quantity: set to Decimal Number, then filter for values less than or equal to 0 and route them to a review query named Produce_InvalidQuantity, because a zero or negative quantity sale should never have been recorded.
  6. Clean PricePerUnit and TotalValue with the standard currency-stripping and Decimal Number conversion technique.
  7. Add a calculated RecalcTotalValue column = [Quantity] * [PricePerUnit] where both are valid and non-null, then add a TotalValueMismatch column = if [TotalValue] is null then "Missing - recalculated" else if Number.Abs([TotalValue] - [RecalcTotalValue]) > 1 then "Mismatch - review" else "OK", surfacing the discrepancies for the records team.
  8. Fix StorageFacility: Trim, Capitalize Each Word, then Replace Values to convert N/A and blank into null, and "Cold Chain" variants into a single "Cold Room" canonical value.
  9. Standardise TransportMode: Trim, Capitalize Each Word.
  10. Fix SaleDate: convert to Date type and resolve errors using the standard technique.
  11. Standardise Certified_Organic into a Logical True/False column with Replace Values before changing Data Type.
  12. Close and load as AgriProduce_Market_Clean.

Dataset 15Federal Civil Service Payroll Register

Domain: Government and Public Sector  |  File: 15_government_payroll_records_DIRTY.csv

A state auditor receives a civil service payroll register covering five ministries, compiled from individual ministry HR systems that were never migrated to a unified platform. The file is used for a payroll audit looking for ghost workers, duplicate entries, and salary grade inconsistencies.

Columns: StaffID, FullName, Ministry, GradeLevel, DateOfBirth, AppointmentDate, BasicSalary, HousingAllowance, TransportAllowance, TotalAllowances, Deductions, NetPay, BankAccountNo, State, PayStatus

Data Quality Issues Deliberately Built In

  • Ministry uses up to five different text representations for the same ministry (Ministry of Finance, ministry of finance, Min. of Finance, Finance Ministry, MOF) across the merged file.
  • GradeLevel has inconsistent formats for the same grade (GL-7, GL 7, Level 7, Grade Level 7, gl-7) and needs normalisation before any grade-band analysis.
  • BasicSalary, HousingAllowance, TransportAllowance, TotalAllowances, Deductions, and NetPay are all stored as text with mixed currency notation - the currency cleanup technique needs to be applied to six columns at once.
  • NetPay should equal BasicSalary + TotalAllowances - Deductions, and rows where it does not match (beyond a small rounding tolerance) are ghost-worker or calculation-error signals for the audit.
  • BankAccountNo is missing for some staff, which in a payroll audit context is a critical red flag rather than just a missing value.
  • DateOfBirth and AppointmentDate use mixed date formats.
  • A derived age check against DateOfBirth should flag staff who appear to be below 18 or above 60 (Nigeria's mandatory retirement age for most grades).
  • AppointmentDate should never be after the most recent payroll run date; rows where it is indicate a future-dated entry.
  • PayStatus has inconsistent casing and trailing spaces (Paid, paid, PAID, "paid ").
  • Around four percent of rows are duplicated from ministry files being merged without deduplication.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV, set StaffID and BankAccountNo to Text type immediately to preserve formatting, then remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass - this is especially important for PayStatus, which has a "paid " trailing-space variant that Replace Values will miss if Trim is skipped.
  3. Standardise Ministry: build a reference table mapping every dirty variant to one canonical ministry name, then Merge Queries (Left Outer join on Ministry) to bring in the canonical name. This is more maintainable than stacking 15+ Replace Values steps for five ministries with three to five variants each.
  4. Standardise GradeLevel: Replace Values to remove "Level ", "Grade Level ", and "gl-" prefixes into the standard "GL-" format, then Capitalize Each Word to handle remaining case inconsistencies.
  5. Clean all six salary and allowance columns in sequence - BasicSalary, HousingAllowance, TransportAllowance, TotalAllowances, Deductions, NetPay - using the same currency-stripping chain for each: Replace Values to remove naira sign, NGN, and naira, Trim, then set Data Type to Decimal Number.
  6. Add a NetPayCheck column = [BasicSalary] + [TotalAllowances] - [Deductions], then a NetPayVariance column = Number.Abs([NetPay] - [NetPayCheck]), and flag any row where the variance exceeds 1 naira as "Calculation mismatch - audit flag".
  7. Flag missing BankAccountNo: add a conditional column BankAccountFlag = if [BankAccountNo] = null then "CRITICAL - no bank account on record" else "OK", so the auditor's attention is drawn immediately to payroll records with no payment destination.
  8. Fix DateOfBirth and AppointmentDate: convert both to Date type, resolve errors. Then add an Age column and flag staff younger than 18 or older than 60. Add an AppointmentCheck to flag any AppointmentDate after the report date.
  9. Standardise PayStatus: Trim (to catch "paid "), Capitalize Each Word, then Replace Values to collapse all paid variants into "Paid".
  10. Close and load as Payroll_Audit_Clean, keeping a companion query Payroll_AuditFlags that filters the main cleaned table for every row where at least one flag column is not "OK", as a ready-made audit exception report.

Dataset 16Petrol Station Daily Fuel Sales Log

Domain: Energy and Petroleum Retail  |  File: 16_petrol_station_fuel_sales_DIRTY.csv

A petroleum products marketer exports a daily sales log from six filling stations across Lagos, Abuja, and the south-east. The log is produced by mixing a manual pump-reading register with a point-of-sale receipt system that uses different field conventions for the same data.

Columns: SaleID, StationName, AttendantName, FuelType, LitersDispensed, PricePerLiter, TotalSaleAmount, Date, PumpNumber, PumpStatus, PaymentMethod, CustomerVehicle, State, ManagerApproved

Data Quality Issues Deliberately Built In

  • FuelType uses both full product names and abbreviations inconsistently (Premium Motor Spirit (PMS), PMS, pms, Petrol; Automotive Gas Oil (AGO), AGO, ago, Diesel) creating three or four representations per product.
  • LitersDispensed contains negative values and zeros, which are physically impossible for a completed fuel dispensing transaction.
  • PricePerLiter and TotalSaleAmount are stored as text with mixed currency notation.
  • A validation gap exists: TotalSaleAmount should equal LitersDispensed times PricePerLiter, and rows where it does not match reveal pump-reading or receipt discrepancies.
  • PumpNumber contains negative values and zeros, which are physically impossible pump identifiers.
  • PumpStatus has inconsistent casing and trailing spaces (Functional, functional, FAULTY, "functional ") and an "Out of Stock" value that should ideally never appear on a record showing dispensed liters.
  • PaymentMethod and CustomerVehicle have inconsistent casing (Cash, cash, CASH; Truck, truck, TRUCK).
  • ManagerApproved mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Date uses mixed date formats.
  • Around four percent of rows are exact duplicates from a double-export of a shift change reconciliation.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and remove duplicate rows on all columns first.
  2. Trim and Clean all text columns in one pass.
  3. Standardise FuelType: build a lookup table mapping every abbreviation and full-name variant to three canonical values (PMS, AGO, Kerosene, LPG) and merge it in, since Replace Values would require at least eight separate steps.
  4. Fix LitersDispensed: set to Decimal Number, then filter for values less than or equal to 0 and route them to a review query named FuelSales_InvalidLiters, since a zero or negative volume sale should not have a receipt.
  5. Fix PumpNumber: set to Whole Number, then filter for values less than 1 and route to a separate review query, since a pump numbered 0 or lower cannot exist physically.
  6. Clean PricePerLiter and TotalSaleAmount with the standard currency-stripping and Decimal Number conversion technique.
  7. Add a calculated ExpectedTotal column = [LitersDispensed] * [PricePerLiter] (only where LitersDispensed is positive), then a SalesVariance column = Number.Abs([TotalSaleAmount] - [ExpectedTotal]) and flag any row where variance exceeds 10 naira as "Mismatch - review", surfacing possible cashier or pump calibration issues.
  8. Standardise PumpStatus: Trim (to catch "functional "), Capitalize Each Word, then Replace Values to produce a clean four-value list (Functional, Faulty, Under Maintenance, Out of Stock). Add a consistency check: any row where PumpStatus is "Faulty" or "Out of Stock" but LitersDispensed is greater than 0 should be flagged as a logical contradiction.
  9. Standardise PaymentMethod and CustomerVehicle: Trim, Capitalize Each Word.
  10. Standardise ManagerApproved into a Logical True/False column with Replace Values before changing Data Type.
  11. Fix Date: convert to Date type and resolve errors. Add a DayOfWeek column using Date.DayOfWeekName([Date]) to support a weekend versus weekday sales pattern analysis as a closing classroom exercise.
  12. Close and load as FuelSales_Clean.

Dataset 17University Student Enrollment and Academic Records

Domain: Higher Education  |  File: 17_university_student_enrollment_DIRTY.csv

A federal university's academic registry exports a student master file covering undergraduate and postgraduate students across four faculties. The file blends records from two cohorts of data entry clerks whose conventions for matric numbers, level formats, and CGPA scales differ.

Columns: StudentMatric, StudentName, University, Faculty, Department, DegreeType, Level, EntryMode, DateOfBirth, EnrollmentDate, CGPA, StudentEmail, PhoneNumber, State, ScholarshipHolder

Data Quality Issues Deliberately Built In

  • Faculty uses inconsistent representations for the same faculty (Engineering, engineering, Faculty of Engineering, Engr; Medicine, Medical Sciences, MEDICINE).
  • Level has multiple formats for the same academic year (100, 100L, level 300, 400 level) that prevent a simple GROUP BY for enrolment counts by year.
  • EntryMode has inconsistent casing and a trailing-space variant (UTME, utme, "UTME ", Post-UTME).
  • DegreeType mixes official abbreviations with informal ones for the same degree (B.Sc., B.Sc, Bsc, bsc all refer to a Bachelor of Science).
  • CGPA uses two different grading scales in the same column - some departments use a 4.0 scale while others use a 5.0 scale - making any aggregation meaningless without a scale flag.
  • StudentEmail is missing for some students and is not validated for a university domain format.
  • DateOfBirth and EnrollmentDate use mixed date formats.
  • StudentMatric has no consistent format between departments - some use alphabetic prefixes, some use numeric-only formats, and capitalisation is inconsistent.
  • DegreeType, Faculty, and Department need to align logically (an MBBS degree should only appear in Medicine) for an effective validation rule.
  • ScholarshipHolder mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are duplicate enrollment entries from a registry system migration.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV and immediately set StudentMatric to Text type so Power Query does not attempt to parse it as a number. Remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass.
  3. Standardise Faculty: build a reference lookup table (DirtyFaculty, CleanFaculty) and merge it in to produce a consistent faculty list. Trim and Capitalize first so the lookup has fewer variant rows to handle.
  4. Standardise Level: Replace Values to strip the "L" suffix and the word "level" (case-insensitively, which requires Trim and Lowercase first), then set the column to Whole Number to produce clean numeric year values (100, 200, 300, 400, 500, 600).
  5. Standardise EntryMode: Trim first (to catch "UTME "), then Capitalize Each Word, then Replace Values to fold utme into UTME since this is an acronym that should be uppercase.
  6. Standardise DegreeType: Replace Values to fold Bsc, bsc, B.Sc, and B.Sc. into B.Sc. (one canonical form), and similarly for B.A., B.Eng, and other degrees, using a lookup table.
  7. Handle the CGPA dual-scale problem: add a CGPAScale indicator column that checks if CGPA is above 4.0 and flags it as "5.0 Scale" else "4.0 Scale", making the scale explicit in the dataset before any aggregation. This is a data modelling decision that Power Query surfaces but cannot fully resolve without a business rule on which departments use which scale.
  8. Validate StudentEmail: add an IsValidEmail column = Text.Contains([StudentEmail], "@") and not([StudentEmail] = null), flagging missing or malformed emails for the registry office.
  9. Fix DateOfBirth and EnrollmentDate: convert both to Date type, resolve errors, and add an Age column. Flag any student under 15 or over 50 as potentially erroneous.
  10. Standardise ScholarshipHolder into a Logical True/False column with Replace Values before changing Data Type.
  11. Clean PhoneNumber using Text.Select to digits and + only.
  12. Close and load as University_Enrollment_Clean.

Dataset 18Electricity Distribution Company Billing Records

Domain: Utilities and Energy  |  File: 18_electricity_utility_billing_DIRTY.csv

A state electricity distribution company (DISCO) exports a monthly billing run across residential, commercial, and industrial accounts for a revenue assurance audit. Records come from three billing systems that were merged when two smaller DISCOs were consolidated, so unit formats, tariff labels, and account type terminology all clash.

Columns: AccountNo, CustomerName, CustomerPhone, DISCO, TariffCategory, AccountType, BillingMonth, UnitsConsumed_kWh, TariffRate_per_kWh, BillAmount, PreviousArrears, TotalAmountDue, PaymentStatus, MeterNumber, State

Data Quality Issues Deliberately Built In

  • TariffCategory uses both formal code names and informal descriptions for the same tariff (Residential (R1), R1, r1, Residential; Commercial (C1), C1, C1 with a trailing space, commercial).
  • AccountType mixes inconsistent labels for the same concept (Prepaid, prepaid, Pre-paid; Postpaid, POSTPAID, Post paid).
  • UnitsConsumed_kWh contains missing values and occasional outlier readings (very high values for a residential account) that need flagging.
  • TariffRate_per_kWh and BillAmount are stored as text with mixed currency notation.
  • BillAmount should equal UnitsConsumed_kWh times TariffRate_per_kWh, and discrepancies reveal billing calculation errors.
  • PreviousArrears is frequently blank and needs to be treated as zero in billing calculations, not as a missing data problem.
  • TotalAmountDue should equal BillAmount plus PreviousArrears, and rows where it does not match are revenue assurance findings.
  • PaymentStatus has inconsistent casing and trailing spaces (Paid, paid, UNPAID, "paid ") and an Arrears status that overlaps with Unpaid semantically.
  • MeterNumber is missing for some accounts, which may indicate unmetered connections - a critical revenue assurance red flag.
  • BillingMonth uses mixed date formats.
  • Around four percent of rows are duplicate billing entries from the DISCO consolidation data migration.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV, set AccountNo and MeterNumber to Text type immediately, then remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass.
  3. Standardise TariffCategory: Trim first (to catch "C1 " with trailing space), then build a lookup table mapping every variant to a clean set such as R1, R2, C1, D3 (the NERC standard codes) and merge it in.
  4. Standardise AccountType: Trim, then Replace Values to fold Pre-paid, prepaid into Prepaid and Post paid, POSTPAID into Postpaid.
  5. Clean TariffRate_per_kWh, BillAmount, and TotalAmountDue with the standard currency-stripping and Decimal Number conversion technique.
  6. Handle PreviousArrears: clean the currency text, then replace any remaining null with 0 (not with a general null-replacement because in billing a missing arrears figure means zero, not unknown), using Replace Value on null after the type conversion.
  7. Fix UnitsConsumed_kWh: set to Decimal Number, then add an outlier flag column that checks for residential accounts (TariffCategory R1 or R2) with consumption above 3000 kWh in a single month, flagging them as "High consumption - verify meter reading".
  8. Add a calculated ExpectedBill column = [UnitsConsumed_kWh] * [TariffRate_per_kWh] and a BillVariance column to surface calculation errors. Add an ExpectedTotal column = [BillAmount] + [PreviousArrears] and compare to TotalAmountDue.
  9. Flag missing MeterNumber: add a MeterFlag column = if [MeterNumber] = null then "CRITICAL - unmetered account" else "OK" for the revenue assurance team.
  10. Standardise PaymentStatus: Trim (to catch "paid "), Capitalize Each Word, then Replace Values to produce a clean set (Paid, Unpaid, Partially Paid, Arrears).
  11. Fix BillingMonth: convert to Date type, resolve errors. Note that a billing month is conventionally the first day of the month - add a BillingMonth_Start column using Date.StartOfMonth([BillingMonth]) to standardise all dates to the first of the month regardless of which day was actually captured.
  12. Close and load as Electricity_Billing_Clean, with a companion query Revenue_Assurance_Flags filtering for every row with at least one flag column that is not "OK".

Dataset 19Pharmacy Drug Inventory and Stock Records

Domain: Pharmaceutical and Healthcare Supply  |  File: 19_pharmacy_drug_inventory_DIRTY.csv

The supply chain team at a private hospital pharmacy exports its drug stock register ahead of a NAFDAC compliance audit. Records span over two years and were entered by multiple pharmacy technicians using different conventions for storage conditions, quantity units, and expiry date formats.

Columns: StockID, DrugName, DrugClass, SupplierName, UnitCostPrice, UnitSellingPrice, QuantityReceived, QuantityDispensed, ClosingStock, BatchNumber, ExpiryDate, ReceiptDate, StorageCondition, NafdacApproved, State

Data Quality Issues Deliberately Built In

  • DrugClass has inconsistent casing (Antibiotics, antibiotics, ANTIBIOTICS; Analgesics, analgesics).
  • QuantityReceived contains negative values and zeros, which should not appear in a goods-received register.
  • ClosingStock should equal QuantityReceived minus QuantityDispensed, and rows where it does not match reveal dispensing record errors or theft risk signals.
  • Some ClosingStock values are blank - they need to be recomputed where both source quantities are available, rather than left as null.
  • UnitCostPrice and UnitSellingPrice are stored as text with mixed currency notation.
  • A margin validation: UnitSellingPrice should always exceed UnitCostPrice; rows where it does not are pricing errors.
  • ExpiryDate uses mixed date formats, and some drugs have already expired (ExpiryDate before today) which is a regulatory red flag.
  • StorageCondition mixes inconsistent labels (Cold Chain (2-8 degrees C), COLD CHAIN, Refrigerated, Ambient Temperature, ambient, room temp) for what should be a two-value or three-value controlled vocabulary.
  • NafdacApproved mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • BatchNumber is missing for some records, which is a NAFDAC compliance violation.
  • Around four percent of rows are duplicate stock entries from a monthly backup restore that was accidentally appended to the live register.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV, set BatchNumber and StockID to Text type, then remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass.
  3. Standardise DrugClass: Capitalize Each Word. Since drug class names are standard pharmacological terms, Capitalize Each Word should resolve all casing issues without needing a lookup table.
  4. Clean UnitCostPrice and UnitSellingPrice with the standard currency-stripping and Decimal Number conversion technique, then add a MarginCheck column = if [UnitSellingPrice] <= [UnitCostPrice] then "Pricing error - selling below cost" else "OK".
  5. Fix QuantityReceived and QuantityDispensed: set both to Whole Number, then filter for QuantityReceived less than or equal to 0 and route those rows to a review query named Pharmacy_InvalidReceipts.
  6. Add a calculated ClosingStockCheck column = [QuantityReceived] - [QuantityDispensed] where both are not null, then compare to the original ClosingStock to flag discrepancies. Fill missing ClosingStock values from this calculated column where the calculated value is available.
  7. Fix ExpiryDate and ReceiptDate: convert both to Date type, resolve errors. Then add an ExpiryStatus column: if [ExpiryDate] < Date.From(DateTime.LocalNow()) then "EXPIRED - remove from shelf" else if [ExpiryDate] < Date.From(DateTime.LocalNow()) + #duration(90,0,0,0) then "Expiring within 90 days - review" else "OK". This is the most practically valuable derived column in this dataset for a pharmacy audit.
  8. Standardise StorageCondition: Trim, Capitalize Each Word, then build a lookup table that maps "COLD CHAIN", "Refrigerated", "Cold Chain (2-8 degrees C)" to "Cold Chain (2-8 C)" and "Ambient Temperature", "ambient", "room temp" to "Ambient Temperature", producing a three-value controlled vocabulary (Cold Chain (2-8 C), Ambient Temperature, Controlled).
  9. Flag missing BatchNumber: add a BatchFlag column = if [BatchNumber] = null then "COMPLIANCE RISK - no batch number" else "OK".
  10. Standardise NafdacApproved into a Logical True/False column with Replace Values before changing Data Type.
  11. Close and load as Pharmacy_Inventory_Clean, with a companion query Pharmacy_ComplianceFlags filtering for expired drugs, pricing errors, compliance-risk flags, and invalid receipts in one combined audit view.

Dataset 20Government Construction and Infrastructure Project Register

Domain: Construction and Infrastructure  |  File: 20_construction_project_management_DIRTY.csv

A federal ministry of works exports a project execution register covering road construction, bridge rehabilitation, hospital buildings, and school blocks across all 36 states. The register blends records from three procurement database systems that were never linked, so contractor names, funding sources, and status labels all have multiple representations.

Columns: ProjectID, ProjectName, ProjectType, ContractorName, FundingSource, ContractDate, ExpectedCompletionDate, ActualCompletionDate, ContractValue, AmountPaidToDate, PercentageCompletion, ProjectStatus, ProjectManager, State, EnvironmentalClearance

Data Quality Issues Deliberately Built In

  • ProjectType has overlapping labels from the three procurement systems (Road Construction versus Road; Bridge versus Bridge Rehabilitation; Hospital Building versus Hospital Block).
  • FundingSource has inconsistent casing (Federal Government, federal, World Bank, World bank, NGO).
  • ContractDate, ExpectedCompletionDate, and ActualCompletionDate all use mixed date formats. ActualCompletionDate is blank for ongoing and suspended projects, which is expected, but it is also blank for some rows marked as Completed, which is a data quality gap.
  • ContractValue and AmountPaidToDate are stored as text with mixed currency notation, with some values in the millions and billions making correct thousands-separator stripping critical.
  • AmountPaidToDate exceeds ContractValue in some rows, which is physically impossible without a contract amendment and should be flagged for the auditor.
  • PercentageCompletion is missing for some rows and shows 100 for some projects that are still marked as Ongoing or Suspended, which is logically contradictory.
  • ProjectStatus has inconsistent casing and a trailing-space variant (Completed, completed, ONGOING, "Completed ").
  • EnvironmentalClearance mixes Yes/No, Y/N, 1/0, and TRUE/FALSE.
  • Around four percent of rows are duplicate project entries from a database sync that ran twice.

Step-by-Step Power Query Cleaning Process (Excel and Power BI)

  1. Load the CSV, set ProjectID and ContractValue to Text type initially to avoid number-format misinterpretation, then remove duplicate rows on all columns.
  2. Trim and Clean all text columns in one pass.
  3. Standardise ProjectType: Trim, Capitalize Each Word, then build a lookup table to consolidate overlapping labels (Road, Road Construction both become Road Construction; Bridge, Bridge Rehabilitation become their correct distinct types based on ProjectName content) and merge it in.
  4. Standardise FundingSource: Capitalize Each Word, then Replace Values to fold "federal" into "Federal Government" and "World bank" into "World Bank".
  5. Fix ContractDate, ExpectedCompletionDate, and ActualCompletionDate: convert all three to Date type, resolve errors. Then add a CompletionDataCheck column: if [ProjectStatus] = "Completed" and [ActualCompletionDate] = null then "Missing actual completion date for completed project - audit flag" else "OK".
  6. Clean ContractValue and AmountPaidToDate: this dataset contains billion-naira values with thousands commas embedded in the text, so the Replace Values chain must include stripping commas as well as currency symbols and words (add Text.Replace([Column], ",", "") to the chain). Then set to Decimal Number.
  7. Add an OverpaymentCheck column = if [AmountPaidToDate] > [ContractValue] then "Overpayment - audit flag" else "OK" to surface the rows where payment exceeds contract value.
  8. Fix PercentageCompletion: set to Decimal Number, then add a ProgressConsistency column: if [PercentageCompletion] = 100 and [ProjectStatus] <> "Completed" then "Inconsistency - 100% but not marked Completed" else if [PercentageCompletion] = null then "Completion percentage missing" else "OK".
  9. Standardise ProjectStatus: Trim (to catch "Completed " with trailing space), Capitalize Each Word, then Replace Values to produce a four-value canonical list (Completed, Ongoing, Suspended, Abandoned).
  10. Standardise EnvironmentalClearance into a Logical True/False column with Replace Values before changing Data Type.
  11. Add a ProjectDurationDays column = Duration.Days([ExpectedCompletionDate] - [ContractDate]) where both dates are valid, to support a planned versus actual duration analysis in Power BI.
  12. Close and load as Construction_Projects_Clean, with a companion query Projects_AuditFlags that filters for every row with an overpayment flag, a completion data gap, a progress inconsistency, or a missing environmental clearance, producing a ready-made audit exception report.

Facilitator Notes

  • Ask trainees to name each Applied Step as they go, not at the end. Renaming steps as you build them forces the trainee to understand what the step does and produces a self-documenting query.
  • Use Column Quality (View > Column Quality) and Column Distribution (View > Column Distribution) at the start of each dataset lesson. The visual percentage bars instantly reveal the proportion of valid, empty, and error cells in every column without a single manual check.
  • Teach the difference between removing a problem row and routing it to a review table. A Remove Rows step silently destroys data that might have been recoverable. A duplicate-and-filter approach creates a separate query holding just the flagged rows, which the business team can act on.
  • Reinforce that Replace Values is case-sensitive by default. Always Trim and Capitalize (or Uppercase) a column before using Replace Values on it, otherwise a search for "Completed" will not catch "completed " (with a trailing space) or "COMPLETED".
  • Use Merge Queries (Left Outer join) for multi-value category standardisation instead of stacking many Replace Values steps. A separate two-column lookup table (DirtyValue, CleanValue) joined to the main query is more maintainable and reusable across future datasets.
  • Encourage trainees to count the Group By diagnostic before and after each cleaning step on a problematic column. Grouping on Ministry or FuelType before cleaning shows the full explosion of variants; grouping again after cleaning confirms the consolidation worked.
  • The cheat sheet M snippets at the end of this guide can be built into a personal Power Query function library. Advanced trainees can be challenged to wrap the phone cleaning logic and the currency stripping logic into named functions that they call from any future query.
