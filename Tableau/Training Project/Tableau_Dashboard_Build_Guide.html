1. Dataset Overview

The workbook clean_powerbi_dataset.xlsx contains three related sheets that together form a simple star-style data model: one fact table (Sales) and two dimension tables (Customers and Products). This structure is exactly what Tableau's Relationships feature is designed for.

1.1 Customers (100 rows)

FieldData TypeDescription
CustomerIDIntegerUnique key for each customer, 1 to 100. Links to Sales.CustomerID.
Customer NameStringFull name of the customer.
RegionStringOne of Lagos, Abuja, Port Harcourt, Kano.
AgeIntegerCustomer age, ranging from 18 to 60.
SegmentStringOne of Retail, SME, Corporate.

1.2 Products (20 rows)

FieldData TypeDescription
ProductIDIntegerUnique key for each product, 1 to 20. Links to Sales.ProductID.
Product NameStringName of the product, e.g. Laptop 1, Phone 3.
CategoryStringElectronics or Accessories.
PriceIntegerUnit list price in Naira, from 150,000 to 500,000.

1.3 Sales (500 rows)

FieldData TypeDescription
OrderIDIntegerUnique key for each transaction line, 1001 to 1500.
DateText (needs conversion)Order date, stored as a text string in the format YYYY-MM-DD. Spans 1 January 2024 to 31 December 2024.
CustomerIDIntegerForeign key linking to Customers.CustomerID.
ProductIDIntegerForeign key linking to Products.ProductID.
QuantityIntegerUnits sold on that order line, 1 to 5.
Sales AmountIntegerRevenue for the order line in Naira, 150,000 to 2,500,000.
ProfitIntegerProfit for the order line in Naira, 30,000 to 500,000.
Important data-quality note: the Date column in the Sales sheet is stored as plain text (for example "2024-09-11"), not as a true Excel date value. Excel and Tableau will both read it as a string unless it is explicitly converted. This is addressed directly in Data Preparation, Step 3, and it matters because several of the calculated fields below (Running Total, Month-over-Month Growth, Recency) rely on true date functions such as DATEDIFF and continuous MONTH().

2. Step by Step: Connecting and Loading the Data into Tableau

  1. Open Tableau Desktop (or Tableau Public). On the start screen, under Connect > To a File, click Microsoft Excel.
  2. Browse to and select clean_powerbi_dataset.xlsx, then click Open.
  3. Tableau opens the Data Source page and lists all three sheets (Customers, Products, Sales) in the left-hand pane as separate tables.
  4. Drag the Sales table onto the canvas first, since it is the fact table that the two dimension tables will connect to.
  5. Drag the Customers table onto the canvas next. Tableau will automatically draw a relationship line (a "noodle") if it detects a matching field name; if it does not detect CustomerID automatically, click the relationship line and manually set the clause to [Sales].[CustomerID] = [Customers].[CustomerID].
  6. Drag the Products table onto the canvas the same way, and confirm or set the relationship clause to [Sales].[ProductID] = [Products].[ProductID].
  7. In the bottom-left corner, choose either Live (queries the Excel file every time) or Extract (imports a fast, saved snapshot). For a static 500-row workbook like this one, choose Extract, then click the Extract radio button and Update Now once you reach the sheet.
  8. Click the Sheet 1 tab at the bottom to move from the Data Source page into the actual worksheet canvas and begin building charts.

Why Relationships and not Joins: Tableau's newer Relationships model (the noodle lines on the Data Source canvas) is preferred over a traditional inner/left Join for this kind of star schema, because it preserves the native level of detail of each table and avoids the classic problem where joining Sales to Customers would duplicate every Sales row once per matching Customer attribute change. Relationships let Tableau decide the correct join type automatically at query time based on what is actually placed on the worksheet.

3. Building the Data Model

Once all three tables are on the canvas with two relationship lines drawn (Sales to Customers, Sales to Products), the model is a simple star schema:

Customers (CustomerID) | | relationship on CustomerID | Products ----------- Sales ----------- (fact table) (ProductID) relationship on ProductID

Sales sits in the middle as the fact table containing every transaction. Customers and Products sit on either side as dimension (lookup) tables. This means any measure from Sales (Sales Amount, Profit, Quantity) can be broken down by any attribute from Customers (Region, Segment, Age) or Products (Category, Product Name, Price) without duplicating rows or inflating totals.

4. Data Preparation Checklist

Complete these checks on the Data Source page, or in the Data pane on the left of the worksheet, before building any charts.

Step 1 - Verify field roles

In the Data pane, dimensions are listed above the horizontal line in blue text, and measures are listed below it in green text. Customer Name, Region, Segment, Product Name, Category, and Date should all be Dimensions. Sales Amount, Profit, and Quantity should be Measures.

Step 2 - Convert ID fields to Dimensions

By default, Tableau treats any numeric field as a Measure. CustomerID, ProductID, and OrderID are identifiers, not quantities to be summed, so right-click each one in the Data pane and choose Convert to Dimension. Left un-converted, they would otherwise show up in the Measures list and invite someone to accidentally SUM a customer ID number, which is meaningless.

Step 3 - Convert Date from text to a true Date field

Because the Date column is stored as text (see Section 1.3), right-click the Date field in the Data pane, choose Change Data Type, and select Date. Tableau will parse the existing YYYY-MM-DD text correctly since it is already in an unambiguous ISO format. Confirm the field icon changes to a small calendar icon.

Step 4 - Set the default aggregation for Price

Products.Price is a unit list price, not something that should ever be summed across many order lines. Right-click Price in the Data pane, go to Default Properties > Aggregation, and set it to Average (or leave it as a Dimension if it will only ever be used for reference, not charting).

Step 5 - Set default number formats

Right-click Sales Amount, Profit, and Price and set Default Properties > Number Format to Currency (Custom), with NGN or the Naira symbol as the prefix and 0 decimal places, so every worksheet you build afterward inherits the correct formatting automatically.

Step 6 - Rename fields for readability (optional)

Sales Amount and Product Name are already clear. If you want shorter axis labels later, you can rename Sales Amount to Revenue by double-clicking the field name in the Data pane; this is optional and does not change the underlying data.

5. Calculated Fields Library

Every formula below has been checked for correct Tableau syntax and correct aggregation logic (no mixing of aggregate and row-level terms where that is not allowed, correct use of FIXED versus table calculations, and correct Compute Using guidance where needed). To create each one: go to Analysis > Create Calculated Field, or right-click any empty area of the Data pane and choose Create Calculated Field, then paste in the formula and name the field exactly as shown below.

1. Profit Margin %

Calculation type: Aggregate Calculation

SUM([Profit]) / SUM([Sales Amount])

Formatting: Format as Percentage, 1 decimal place.

Divides total profit by total sales for whatever is on the view (a region, a category, a single product, or the whole dataset). Both terms are wrapped in SUM() so the ratio recalculates correctly at every level of the view. Do not average a row-level profit-margin ratio across rows; that produces a mathematically wrong figure because it treats a NGN150,000 order the same as a NGN2,500,000 order.

2. Average Order Value (AOV)

Calculation type: Aggregate Calculation

SUM([Sales Amount]) / COUNTD([OrderID])

Formatting: Format as Number (Currency), 0 decimals, Naira symbol.

Total revenue divided by the number of distinct orders in view. COUNTD (count distinct) is used rather than COUNT or simply counting rows, because if an OrderID ever appears on more than one row, a plain row count would overstate the number of orders and understate the true average order value.

3. Customer Lifetime Value (CLV)

Calculation type: Level of Detail (FIXED)

{FIXED [CustomerID] : SUM([Sales Amount])}

Formatting: Format as Number (Currency).

Calculates each customer's total spend across every one of their orders, locked to the CustomerID level regardless of what else is on the sheet or which filters are applied (unless those filters are added to Context). This is what makes it possible to rank or bucket customers by lifetime spend even in a view that is otherwise sliced by Region or Category.

4. Age Group

Calculation type: Row-Level Calculation (String)

IF [Age] <= 25 THEN "18-25"
ELSEIF [Age] <= 35 THEN "26-35"
ELSEIF [Age] <= 45 THEN "36-45"
ELSEIF [Age] <= 55 THEN "46-55"
ELSE "56-60"
END

Formatting: Discrete (blue pill) string field.

Buckets the continuous Age field from the Customers table into five bands so it can be used as a discrete dimension on rows, columns, and filter cards. Without this, Age would need to be manually binned or would create dozens of single-value marks, one per age, which is not readable.

5. Profit per Unit

Calculation type: Aggregate Calculation

SUM([Profit]) / SUM([Quantity])

Formatting: Format as Number (Currency).

Total profit divided by total units sold. This shows profitability per item rather than per Naira of revenue, which is the fairer comparison between a high-ticket item like a Laptop and a low-ticket item like an Accessory.

6. Order Value Tier

Calculation type: Row-Level Calculation (String)

IF [Sales Amount] >= 1500000 THEN "High Value (NGN 1.5M+)"
ELSEIF [Sales Amount] >= 500000 THEN "Mid Value (NGN 500K-1.49M)"
ELSE "Standard (Below NGN 500K)"
END

Formatting: Discrete (blue pill) string field.

Classifies each individual order line into a spending tier based on the Sales Amount on that specific row. Useful for counting how many orders fall into each tier and for filtering the dashboard to just high-value transactions.

7. % of Total Sales

Calculation type: Table Calculation

SUM([Sales Amount]) / TOTAL(SUM([Sales Amount]))

Formatting: Format as Percentage. Set Compute Using to the dimension being broken down (e.g. Region).

TOTAL() re-runs the SUM across every partition currently in the view, so this returns each mark's share of the total shown in that specific view. If Compute Using is left on the default, every mark can incorrectly show 100%; it must be explicitly set to the dimension on Rows or Columns (Region, Category, or Product Name).

8. Running Total of Sales

Calculation type: Table Calculation

RUNNING_SUM(SUM([Sales Amount]))

Formatting: Format as Number (Currency). Set Compute Using to Date (Month).

Adds each period's sales to the cumulative sum of all periods before it. Compute Using must be set to the Month(Date) pill on the Columns shelf so the running total accumulates left to right along the timeline in chronological order rather than in an arbitrary dimension order.

9. Month-over-Month Sales Growth %

Calculation type: Table Calculation

(SUM([Sales Amount]) - LOOKUP(SUM([Sales Amount]), -1))
/ ABS(LOOKUP(SUM([Sales Amount]), -1))

Formatting: Format as Percentage. Set Compute Using to Date (Month).

LOOKUP(..., -1) retrieves the prior month's sales value inside the same table-calculation partition. Subtracting and dividing by the absolute prior value produces percentage growth month to month. ABS() protects the formula from a sign flip if a prior period were ever a net negative figure. This must also have Compute Using set to Month(Date), otherwise the first value cannot resolve and returns Null.

10. Profit Margin Category

Calculation type: Aggregate Calculation (nested)

IF SUM([Profit]) / SUM([Sales Amount]) >= 0.22 THEN "High Margin"
ELSEIF SUM([Profit]) / SUM([Sales Amount]) >= 0.18 THEN "Medium Margin"
ELSE "Low Margin"
END

Formatting: Discrete string, typically used on Color.

Because this formula contains SUM(), it is an aggregate-level calculation and must be used on a view that already has a dimension (Region, Category, Product) producing one mark per group. Tableau will reject it, or return an error, on a fully row-level view with no dimension present.

11. Recency (Days Since Last Order)

Calculation type: Level of Detail + Row-Level

DATEDIFF('day', [Date], {FIXED : MAX([Date])})

Formatting: Format as Number, 0 decimals.

{FIXED : MAX([Date])} is a Level of Detail expression with no dimensions listed, so it always evaluates to the single latest order date in the entire dataset (31 December 2024), regardless of any filters. DATEDIFF then measures how many days before that anchor date each order occurred. TODAY() is deliberately not used here, because TODAY() returns the real-world current date; against a historical 2024 dataset that would produce meaningless, very large numbers.

12. Sales Contribution % by Segment

Calculation type: Level of Detail (FIXED)

SUM([Sales Amount]) / {FIXED : SUM([Sales Amount])}

Formatting: Format as Percentage.

The denominator is an LOD expression with no dimensions, so it always equals the grand total of Sales Amount across the whole dataset. Dividing by SUM(Sales Amount) at whatever level is on the view gives that mark's true share of overall revenue. Unlike calculation 7, this is unaffected by view filters by default (only by Context Filters), which makes it useful when you want a percentage that stays anchored to the full dataset even while the user filters the dashboard.

6. Chart by Chart Build Guide

For each chart below: create a new worksheet, rename its tab to match the chart name, then follow the Rows / Columns / Marks specification exactly, followed by the numbered build steps.

Chart 1 - KPI Summary Tiles

Chart / Mark typeText table (Big Number / BAN tiles) - build as 5 separate small worksheets
Columns shelf(none)
Rows shelf(none)

SizeText size 24-36pt, bold
LabelSUM([Sales Amount]); SUM([Profit]); COUNTD([OrderID]); [Average Order Value]; [Profit Margin %]
FilterNone (whole-dataset totals) or tied to dashboard filters
Sort-

Build steps:

  1. Create a new worksheet named KPI - Total Sales.
  2. Drag Sales Amount onto the Text (Label) mark card. It defaults to SUM.
  3. Change the Marks type to Text.
  4. Format the number: right-click the SUM(Sales Amount) pill > Format > Numbers > Currency (Custom), 0 decimals, prefix NGN.
  5. Increase font size (right-click text on the mark card > Font) to around 28-32pt bold, and add a caption line above it such as Total Sales using a text object once placed on the dashboard.
  6. Repeat this pattern for Total Profit (SUM(Profit)), Total Orders (COUNTD(OrderID)), Average Order Value ([Average Order Value] calculated field), and Profit Margin % ([Profit Margin %] calculated field).

Insight: Gives an at-a-glance executive summary of the whole business before the user drills into any chart.

7. Assembling the Dashboards

7.1 Dashboard 1 - Executive Sales Overview

Create a new dashboard (Dashboard > New Dashboard), set the size to Automatic or a fixed 1366 x 768, and lay out the sheets as follows:

  1. Top row: the five KPI tiles from Chart 1, placed side by side in horizontal container spanning the full width.
  2. Second row, left two-thirds: Chart 2 (Monthly Sales Trend).
  3. Second row, right one-third: Chart 3 (Sales by Region).
  4. Third row, left half: Chart 5 (Top 10 Products by Sales).
  5. Third row, right half: Chart 4 (Sales by Product Category) and Chart 6 (Customer Segment Breakdown) stacked or side by side.
  6. Bottom strip: add Region, Category, and Segment as filter cards (drag any worksheet's Region/Category/Segment pill onto the dashboard, or use the filter drop-down on each existing chart and choose Apply to Worksheets > All Using This Data Source), plus a Date Range filter on the Date field.

To make the filters control every chart at once rather than only the sheet they came from, click the small drop-down arrow on each filter card once it is on the dashboard, and select Apply to Worksheets > All Using Related Data Source.

7.2 Dashboard 2 - Customer and Profitability Insights

  1. Top row: Chart 7 (Profit Margin % by Region) and Chart 9 (Sales vs Profit Scatter Plot) side by side.
  2. Middle row: Chart 8 (Age Group Distribution) and Chart 11 (Order Value Tier Breakdown) side by side.
  3. Bottom row: Chart 10 (Top 10 Customers by Sales) spanning the full width, with the Customer Lifetime Value calculated field shown in its tooltip.
  4. Add a floating text box at the top titled Customer and Profitability Insights, and include the same Region, Segment, and Date filters as Dashboard 1 for consistency.

7.3 Optional Dashboard 3 - Trend and Momentum

If a third, more analytical dashboard is wanted, combine Chart 12 (Running Total of Sales) with a table showing Month, SUM(Sales Amount), the Month-over-Month Sales Growth % calculated field, and the % of Total Sales calculated field, to give a finance-style monthly performance summary.

7.4 Dashboard Actions

Add interactivity between the two main dashboards using Dashboard > Actions > Add Action > Filter. For example, set a Filter action so that clicking a region bar on Chart 3 filters every other chart on the same dashboard down to that region, and clicking again clears the filter (set the action's target on the source sheet to Exclude All Values on this behavior for a clean toggle).

8. Publishing and Sharing

  1. Before publishing, click Extract on the Data Source tab and choose Extract > Compute Now, then save the workbook so the extract is embedded and the dashboard opens instantly for viewers.
  2. Use Server > Publish Workbook (Tableau Server or Tableau Cloud) or File > Save to Tableau Public if this is a portfolio piece, and choose which sheets/dashboards are visible to viewers.
  3. Set the default view that opens to Dashboard 1 - Executive Sales Overview so viewers land on the summary first.
  4. Add a workbook description and tag it (for example: Nigeria, Retail, Sales Analytics) so it is easy to find later in a project library.
