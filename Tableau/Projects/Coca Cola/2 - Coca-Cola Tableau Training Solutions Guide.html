How This Solutions Guide Is Organised

This document is the answer key to Document 1 - Task Brief. For every one of the ten Coca-Cola Nigeria Limited departments it walks through: the real business problem the department faced before the dashboard existed, the exact Tableau calculated-field formulas that solve the measurement gap, the relationship-building solution, and a build-order description of every chart, KPI and the finished dashboard.

Read the Master Solution section first - it is the same 5-stage process (Data Connection, Data Preparation, Worksheet Development, Dashboard Design, Interactivity) applied consistently to all ten departments, so it only needs to be explained once in full and then referenced by each department section.

Master Solution: The 5-Stage Tableau Build Process

Step 1: Data Connection

  1. Open Tableau Desktop (or Tableau Public) and choose 'Microsoft Excel' as the connector, then browse to Coca-Cola_Nigeria_Training_Data.xlsx.
  2. All 14 department and master sheets will appear on the left as separate tables. Drag the 4 master sheets (Employee Master, Department Master, Location Master, Product Master) onto the canvas first.
  3. Drag each of the 10 department sheets onto the canvas one at a time. Tableau will prompt you to define how each new table relates to the ones already on the canvas - this is where the shared keys (EmployeeID, DeptCode, LocationID, ProductID) are used.
  4. Use Tableau's Relationships (the default in modern Tableau), not physical Joins, so that each department sheet keeps its own native level of detail (e.g. one row per production run, one row per ticket) while still being able to bring in descriptive fields from the master sheets.
  5. For each relationship, click the linking line and confirm the correct field pairing, e.g. Operations.LocationID = Location Master.LocationID, Operations.ProductID = Product Master.ProductID, Operations.SupervisorEmployeeID = Employee Master.EmployeeID.
  6. Decide between a Live connection (queries the Excel file every time - fine for training since the file is small) and an Extract (a compressed Tableau snapshot - faster and recommended once the model is finalised).
  7. Rename the data source to something meaningful, e.g. 'Coca-Cola Nigeria - Cross Departmental Model', before moving to the sheets.

Step 2: Data Preparation

  1. Check every field's data type icon (Abc, #, calendar, globe) matches reality - ID fields should be text (Abc) even though they look alphanumeric, dates should be true Date types, and monetary/measure fields should be numeric.
  2. Rename cryptic field names to business-friendly labels (e.g. OEE_Percent to 'OEE %') using the pill's rename option, and hide fields nobody will use (e.g. free-text Description/Narration columns) to keep the field list clean.
  3. Build Date hierarchies (Year > Quarter > Month > Day) on every Date field so viewers can drill down on any trend chart without extra calculated fields.
  4. Build geographic and product hierarchies: Region > State > Location Name on the Location Master fields, and Category > Product Name on the Product Master fields.
  5. Handle nulls deliberately: DateClosed (Legal), CompletionDate (Admin) and TargetRemediationDate-derived fields are blank by design for open items - use IIF/ISNULL logic rather than letting Tableau silently drop those rows from date-based charts.
  6. Create the calculated fields listed under each department's 'Measures & Calculated Fields' section (see the KPI tables) - this is the single most important data-preparation task, because a Tableau dashboard is only as trustworthy as its calculated fields.
  7. Set default number formats (currency in NGN with thousands separators, percentages to 1 decimal place) on every measure so every worksheet inherits consistent formatting automatically.
  8. Create Groups for any dimension with messy or duplicate labels (e.g. supplier name variants) so the roll-up in charts is accurate.

Step 3: Worksheet Development

  1. Build one worksheet per KPI card and one worksheet per chart listed in each department's section below - do not try to build the whole dashboard on one worksheet.
  2. For KPI cards: place the single aggregated measure on Text, use a large font, add a comparison element (e.g. a reference line for target, or a trend arrow) and format the number (currency/percentage) correctly.
  3. For bar/column charts: put the dimension on Rows (or Columns) and the measure on Columns (or Rows), sort descending unless there's a natural order (e.g. months, grades, priority levels), and add data labels for the top values.
  4. For trend/line charts: put the Date hierarchy on Columns and the measure on Rows, add a trend line or forecast if useful, and use colour to split by a second dimension (e.g. Factory, Priority).
  5. For heat maps and the risk matrix: put one dimension on Rows and another on Columns, drop the measure onto Colour (and Size where relevant), and choose a diverging colour palette (green-to-red) for anything risk- or variance-related.
  6. For Pareto charts (Operations downtime, root-cause analysis): combine a descending bar chart of the measure with a dual-axis cumulative % line, and add a reference line at 80% to highlight the vital few causes.
  7. Name every worksheet clearly (e.g. 'OPS - OEE by Line', 'FIN - Budget Variance Heatmap') so they are easy to find when assembling dashboards.

Step 4: Dashboard Design

  1. Create one dashboard per department using the exact titles given in each department's section (e.g. 'Coca-Cola Nigeria: Manufacturing Performance Dashboard'), plus one Executive Summary dashboard that pulls the single most important KPI from every department.
  2. Use a fixed-size dashboard (1366x768 or 1920x1080) for consistent viewing, and lay it out with KPI cards along the top, the main trend/breakdown chart in the centre, and supporting detail charts or a table below or to the side.
  3. Add a title banner using a Text object styled with the Coca-Cola Nigeria brand-style dark green, and include the department name and reporting period.
  4. Use containers (horizontal and vertical) rather than free-form floating placement so the dashboard resizes cleanly across devices.
  5. Add a company logo/text mark and a small 'Prepared by Kajola Gbenga, Data Scientist & AI Engineer' credit line in the dashboard footer for the training deliverable.
  6. Build the Executive Summary dashboard last, once all department dashboards exist, and add navigation buttons (see Interactivity) so users can jump from the summary into any department's detail dashboard.

Step 5: Interactivity

  1. Add Filter actions so that clicking a bar in one worksheet (e.g. a Product bar in the Operations dashboard) filters every other worksheet on that dashboard to the selected product.
  2. Add a Highlight action on categorical charts (e.g. hovering a Department in Finance highlights the same department across all charts) to guide the eye without hiding other context.
  3. Add global Filters (Date range, Location, Department) as Quick Filters set to 'Apply to Worksheets > All Using This Data Source' so one control drives every chart on the page.
  4. Add Parameters where a user needs to choose between measures (e.g. a parameter to switch the Operations trend chart between 'Actual Output' and 'OEE %') and wire it into a calculated field with a CASE/IF statement.
  5. Add Navigation buttons or a navigation menu on every dashboard (styled as simple rectangles or icons) linking to the Executive Summary and to each of the other 9 department dashboards, so the whole workbook behaves like one connected application.
  6. Add URL actions or Tooltip customisation so hovering a mark shows a rich, formatted tooltip (e.g. an Employee's full name pulled from Employee Master, rather than just the raw EmployeeID) - a direct, visible result of building the relationships correctly in Step 1.
  7. Test every action and filter end-to-end: click through from the Executive Summary into each department dashboard, use every filter, and confirm no KPI breaks or shows a null when a filter is applied.

Operations - Problems & Solutions

Source sheet: OperationsDepartment code: OPS

The Business Problems (Before The Dashboard)

Problem: Two factories run 6 lines across 3 shifts, and management cannot tell which line/shift combination is losing the most output.
Problem: Downtime reasons are logged but nobody has ranked them to know which one to fix first.
Problem: Scrap is tracked per run but never compared across products to flag which product is hardest to manufacture cleanly.

The Solution - Data Preparation & Relationships

Solution: connect the Operations sheet to Employee Master, Department Master, Location Master and/or Product Master via the shared key columns identified in the column table below, using a many-to-one Tableau Relationship for each. Calculated Field Solutions (copy these formulas directly into Tableau)

Create calculated field 'Output Achievement %' = SUM([ActualOutputCartons]) / SUM([PlannedOutputCartons]).

Create calculated field 'Total Downtime Hours' = SUM([DowntimeHours]) with a table calc for % of total.
Create a Date hierarchy (Year > Quarter > Month) on the Date field for drill-down trend charts.
Build the relationship OPS.LocationID -> Location Master.LocationID and OPS.ProductID -> Product Master.ProductID.

Calculated Field Solutions (copy these formulas directly into Tableau)

Create calculated field 'Avg Days to Close' = AVG(IIF([Status]="Closed",DATEDIFF('day',[DateOpened],[DateClosed]),NULL)).
Build the relationship Legal.DeptCodeInvolved -> Department Master.DeptCode and Legal.AssignedEmployeeID -> Employee Master.EmployeeID.
