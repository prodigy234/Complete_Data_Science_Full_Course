0. Business Context

Read this before starting. You will not be given the answers here - only the problem. Work through the tasks in every section below, then compare your build against the Solutions Guide (Geregu_Tableau_Solutions_Guide.html).
ProblemDescription
Fragmented departmental reportingEach of the ten departments at Geregu Power Energy PLC keeps its own records with no shared reporting layer, making it impossible for management to see a single, current picture of performance.
Delayed visibility of plant performanceOperations data on generation, downtime and fuel use is reviewed manually at month-end, meaning avoidable downtime and fuel inefficiency are caught too late to act on.
No consolidated financial control viewRevenue, opex and capex are tracked in separate spreadsheets without a live comparison to budget, so variances are discovered well after the period has closed.
Limited cross-department accountabilityBecause Employee_ID is not consistently used to link activity back to individual staff, workload, caseload and performance cannot be attributed at the individual or department level.
Weak risk and audit visibilityInternal Control findings and the enterprise risk register are maintained independently, so leadership cannot see, at a glance, which departments carry the highest combined audit and risk exposure.
Inconsistent KPI definitionsWithout a single, agreed KPI framework, different departments have historically calculated similar-sounding metrics (for example, resolution time or turnaround time) in different ways, making cross-department comparison unreliable.

1. Dataset & Column Tasks - Explain and Prepare Every Column

For each sheet below: read the column explanation, then complete the stated task before moving to Worksheet Development. Sheets are listed in the order they should be connected in Tableau.

Dim_Date

Purpose: Central date table used to connect every transactional sheet for consistent time intelligence (year, quarter, month) across all eleven department reports.
Grain: One row per calendar day, 1 January 2025 to 31 December 2025.

ColumnExplanationTask To Complete
DateThe calendar date. This is the linking field to every Date column in the transactional sheets.Set as a Date data type in Tableau. Mark this table as the date table when building relationships so all department sheets share one consistent calendar.
YearThe four-digit year extracted from Date.Use for year-over-year filters and as a backup dimension if a continuous date axis is not needed.
QuarterCalendar quarter label (Q1 to Q4).Convert to a string dimension; use in quarter-over-quarter comparison worksheets.
Month_NoNumeric month (1 to 12) used for correct chronological sorting.Use this field to sort Month_Name correctly instead of relying on alphabetical sorting.
Month_NameFull month name (January to December).Sort by Month_No; use on axes where a friendly label is preferred over the numeric month.
Week_NoISO week number of the year.Use for weekly trend analysis on Operations and IT ticket volumes.
Day_NameDay of week name (Monday to Sunday).Use to analyse whether weekday vs weekend affects ticket volume, downtime or customer complaints.
Is_WeekendYes/No flag for Saturday or Sunday.Convert to a Boolean calculated field for quick weekend vs weekday grouping.

2. Data Connection Tasks

Task List: Build the Relationship Model

  1. Connect Tableau Desktop to the workbook Geregu_Power_Energy_PLC_Training_Dataset.xlsx using Connect > Microsoft Excel.
  2. Drag Dim_Employee onto the canvas first; this is the hub table for the whole model.
  3. Drag Dim_Department onto the canvas and build a relationship: Dim_Employee.Department = Dim_Department.Department_Name.
  4. Drag Dim_Date onto the canvas; it will only be related once each transactional sheet is added, since Dim_Date connects to each sheet's own Date field.
  5. Add Operations and build a relationship on Employee_ID; add a second relationship path from Operations.Date to Dim_Date.Date.
  6. Repeat the same two-relationship pattern (Employee_ID to Dim_Employee, Date to Dim_Date) for Legal, Supply_Chain, Admin, Customer_Service, IT, Accounts_Finance, Internal_Control and Risk_Mgmt_Compliance.
  7. For Human_Resources, relate on Employee_ID and Date as above; Department is already carried on the sheet so no extra relationship is required for department slicing.
  8. Use Tableau relationships (the default noodle in the data model canvas), not physical joins, so each department sheet keeps its own grain and does not fan out or duplicate rows.
  9. Rename the data source to Geregu Power Energy PLC - Training Model so it is recognisable when published to Tableau Server or Tableau Cloud.
  10. Set default properties: format Amount_NGN, Cost_Incurred_NGN, Total_Cost_NGN, Cost_NGN and Variance_NGN fields as Currency (Naira, no decimal on dashboards, two decimals on detail views).
  11. Set the default aggregation for all *_Percent, *_Score and *_Rating fields to Average rather than the Tableau default of Sum.
  12. Hide technical key fields (Employee_ID, Department_ID, Record_ID, PO_ID, Case_ID, Ticket_ID, Audit_ID, Risk_ID, Transaction_ID, Request_ID) from the end-user view once relationships are built, keeping them available for calculated fields only.

3. Data Preparation Tasks

General Preparation Task List (apply across all sheets)

  1. Confirm data types on import: Date fields as Date, monetary fields as Number (Decimal), ID fields as String even though they look numeric (this avoids Tableau auto-aggregating a key field).
  2. Rename fields for end-user clarity where the raw header is technical, e.g. rename Amount_NGN to Amount (NGN) using field aliases rather than editing the source column.
  3. Create groups for high-cardinality dimensions: group Job_Title into Management, Technical and Support bands; group Vendor_Name into Top 10 vs Other for cleaner charts.
  4. Split combined fields where useful, e.g. splitting Department_Mandate is not required, but splitting Employee_Name into First/Last is worth doing if a directory-style worksheet is needed.
  5. Create bins for continuous measures used in histograms, e.g. bin Performance_Rating and Satisfaction_Score into whole-number bins for clean distribution charts.
  6. Check for and handle nulls deliberately: Resolution_Date, Closure_Date and Resolution_Time_Hours are legitimately blank for still-open items; use IFNULL or filter logic rather than treating blanks as zero.
  7. Standardise category spellings across sheets (Case_Status, Status, Delivery_Status, Approval_Status) so a single Status filter can be reused conceptually across dashboards even though each sheet has its own physical field.
  8. Set default number formats once, at the data source level, so every worksheet built afterwards inherits correct currency and percentage formatting automatically.
  9. Add data source filters to exclude test rows if any are added during future data refreshes, keeping the training dataset clean for demonstration.
  10. Document every calculated field with a clear comment inside Tableau's calculation editor describing its business logic, so the workbook remains maintainable after the training.

7. Interactivity Tasks per Dashboard

Executive Overview Dashboard

  • Parameter control to switch the Executive Overview between Month-to-Date, Quarter-to-Date and Year-to-Date.
  • Filter action from the KPI Tile Row: clicking a department tile navigates to that department's own dashboard.
  • A global Date Range filter (relative date filter on Dim_Date.Date) applied to every worksheet on the dashboard.

Operations Performance Dashboard

  • Plant_Unit filter (multi-select) affecting every worksheet on the dashboard.
  • Highlight action: hovering a bar in the Downtime Reason Pareto highlights matching shifts in the Generation Trend line.
  • Parameter to toggle the Generation Trend between Daily, Weekly and Monthly granularity.

Legal Case Management Dashboard

  • Filter action from Cases by Counterparty to a detail worksheet listing individual cases.
  • Parameter to select a specific legal officer (Employee_Name) and see their personal caseload across every chart.
  • Set action: selecting a Risk_Level in the matrix filters the Resolution Time Trend to matching cases only.

Supply Chain & Procurement Dashboard

  • Filter action: clicking a vendor in Top Vendors by Spend filters Lead Time by Vendor and Delivery Status Overview.
  • Item_Category quick filter (single-select) applied to all worksheets.
  • Parameter to flag vendors whose average lead time exceeds a user-defined threshold (default 21 days).

Admin & Facilities Dashboard

  • Location filter (single-select) applied to every worksheet.
  • Filter action from Requests by Type to a detail grid of individual requests.
  • Highlight action linking Priority Status Grid selections to the Turnaround Trend line.

Customer Service Dashboard

  • Customer_Type filter (multi-select) applied to all worksheets.
  • Filter action from Priority Heat Map to a ticket-level detail worksheet.
  • Parameter to switch Satisfaction by Customer between Average Score and Count of Resolved Tickets.

IT Support Dashboard

  • System_Affected filter (multi-select), with SCADA set as a default highlighted selection.
  • Filter action from Tickets by System to Downtime Trend.
  • Parameter to set a Service Level Agreement threshold (hours) shown as a reference line on Resolution Time by Priority.

Finance Performance Dashboard

  • Transaction_Type filter (single-select) applied to all worksheets.
  • Filter action from Variance by Category to a transaction-level detail worksheet.
  • Parameter to switch the whole dashboard between NGN actuals and % of Budget view.

HR Analytics Dashboard

  • Department filter (multi-select) applied to all worksheets.
  • Parameter to switch Headcount by Department between headcount count and average tenure (years).
  • Filter action from Performance Rating Distribution to an employee-level detail worksheet.

Internal Control (Audit) Dashboard

  • Department_Audited filter (multi-select) applied to all worksheets.
  • Filter action from Severity Breakdown to a finding-level detail worksheet.
  • Parameter to set a remediation SLA (days) shown as a reference line on Remediation Time Trend.

Risk Management & Compliance Dashboard

  • Risk_Category filter (multi-select) applied to all worksheets.
  • Filter action from the Risk Heat Map: clicking a point filters Risk by Department to that risk's department.
  • Parameter to set the high-priority threshold (default Risk_Score >= 15) used to colour-code the heat map.
