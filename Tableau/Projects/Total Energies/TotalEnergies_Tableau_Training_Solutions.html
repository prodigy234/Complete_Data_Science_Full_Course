2. Building the Dashboards: Data Connection to Interactivity

The build process runs through five stages. Each numbered item below is a real problem a trainee will meet, the task that was set, and the fully worked solution.

1. Data Connection

Connect Tableau Desktop to the TotalEnergies_Training_Dataset.xlsx workbook and build the relationship model that links all 11 sheets together through the Employees and Departments hub tables.

PROBLEM 1

The workbook has 11 separate sheets and no single flat table. A trainee who simply drags every sheet onto the canvas and joins them all on EmployeeID will get row multiplication (a fan-out/many-to-many blow up), because one employee appears in many Operations, Legal, SupplyChain, CustomerService and IT rows at the same time.

Task: Connect to TotalEnergies_Training_Dataset.xlsx. Bring in all 11 data sheets. Build a data model using Tableau's Relationships (not physical Joins) so that each department sheet relates to Employees and Departments without inflating row counts. Decide, for each relationship, which fields are the matching keys.

Solution: On the Data Source page, add each table as its own logical table (do not use the canvas Join icon between fact tables). Drag Employees to the canvas first as the anchor. Then drag Operations, Legal, SupplyChain, Admin, CustomerService, IT, AccountsFinance, InternalControl and RiskComplianceRegister one at a time; when the relationship dialog appears, set the match to EmployeeID = SupervisorEmployeeID / LegalOfficerEmployeeID / ProcurementOfficerEmployeeID / CustodianEmployeeID / AgentEmployeeID / RequesterEmployeeID / ApprovedByEmployeeID / ResponsibleEmployeeID / RiskOwnerEmployeeID as appropriate for each sheet. Add Departments and relate it to Employees on Department = DepartmentName, and to InternalControl and RiskComplianceRegister on DepartmentID = DepartmentID. Because Relationships preserve each table's native grain and only combine rows at the level a worksheet actually needs, no fan-out occurs; SUM(ActualVolume) in Operations still returns the correct total even after Employees is related in.

PROBLEM 2

Trainees need to prove the model is correct before building any charts, but there is no obvious way to check for row duplication.

Task: Validate the data model. Build a quick test worksheet that proves SUM(TotalCost_EUR) from SupplyChain does not change whether or not Employees is in the model.

Solution: Create a worksheet with SUM(TotalCost_EUR) on Text, no other fields. Note the value. Then drag Employees.FullName onto the view alongside it. If Relationships are configured correctly, SUM(TotalCost_EUR) stays identical, only now split across employees; if it changed, the offending relationship is a Join rather than a Relationship, and should be rebuilt using the Data Source page's relationship canvas.

PROBLEM 3

Secondary cross links exist between fact tables themselves (SupplyChain to AccountsFinance via PO_ID, Legal to AccountsFinance via ContractID, InternalControl to RiskComplianceRegister via AuditID), and trainees are unsure whether these need relationships too.

Task: Decide which of the secondary links (PO_ID, ContractID, AuditID) should be modelled as Tableau relationships and which are better handled as a blend or a LOD calculation instead.

Solution: Because AccountsFinance.RelatedPO_ID and AccountsFinance.RelatedContractID are frequently blank (not every transaction is tied to a PO or contract), a Relationship using these as the sole match would silently drop unmatched rows in some views. Model AccountsFinance <-> SupplyChain and AccountsFinance <-> Legal as Relationships anyway (Tableau relationships behave like a left join at the grain requested, so unmatched Finance rows are preserved), but add a comment field explaining that PO/Contract level questions ('spend confirmed by PO') should always start the analysis from AccountsFinance and pull SupplyChain/Legal fields in, not the reverse, to avoid confusion about which side is authoritative.

2. Data Preparation

Clean, type, and enrich the fields so that every worksheet built later is fast, accurate and easy to maintain.

PROBLEM 1

Dates arrive as plain Date fields; trainees need Month, Quarter and Year granularity on several dashboards without cluttering the data pane with duplicate date fields.

Task: Set the correct default date level on ProductionDate, OrderDate, DateOpened, DateLogged, TransactionDate and AuditDate, and create a reusable Fiscal Month/Year hierarchy where needed.

Solution: Right click each date field and set Default Properties > Date Format to a consistent 'Mon YYYY' style, and set Default Properties > Aggregation implicit level to Month for trend charts. Build a single Date hierarchy per sheet (Year > Quarter > Month > Day) by dragging Year onto Quarter onto Month in the Data pane; this lets a viewer drill from year down to day on any trend chart without adding new fields.

PROBLEM 2

AssetField in Operations mixes the licence code and the field name in one string (for example 'Nigeria - Egina'), making it impossible to group all production by licence alone.

Task: Split AssetField into two separate dimensions, Licence and FieldName, without altering the source Excel file.

Solution: Right click AssetField > Split (Tableau auto-detects the ' - ' delimiter) to create AssetField - Split 1 and AssetField - Split 2. Rename these to Licence and FieldName. Alternatively use a calculated field: Licence = TRIM(SPLIT([AssetField], ' - ', 1)) and FieldName = TRIM(SPLIT([AssetField], ' - ', 2)) if the split needs to survive a refresh where delimiter position could vary.

PROBLEM 3

JobGrade, Priority and Severity are ordinal text values (for example 'Low, Medium, High, Critical') but Tableau sorts them alphabetically by default, putting 'Critical' before 'Low'.

Task: Force the correct business order onto JobGrade (Employees), Priority (IT) and Severity (InternalControl and RiskComplianceRegister).

Solution: Right click the field in the Data pane > Default Properties > Sort > Manual, and drag the values into the correct order (Low, Medium, High, Critical). This sort order is then remembered on every worksheet that uses the field, so bar charts and colour legends always read in the correct business sequence.

PROBLEM 4

Several KPIs require calculations that do not exist as raw columns: Production Efficiency %, Attrition Rate %, On Time Delivery Rate %, Risk Score bands, and Contract expiry flags.

Task: Build the calculated fields needed to power every KPI listed in the measures and KPIs section, using correct LOD or table calculation syntax where a simple aggregation is not enough.

Solution: Create: [Production Efficiency %] = SUM([ActualVolume])/SUM([PlannedVolume]). [Attrition Rate %] = COUNTD(IF [Status]='Exited' THEN [EmployeeID] END) / COUNTD([EmployeeID]). [On Time Delivery Rate %] = COUNTD(IF [ActualDeliveryDate] <= [ExpectedDeliveryDate] THEN [PO_ID] END) / COUNTD([PO_ID]). [Risk Band] = IF [RiskScore] >= 15 THEN 'Critical' ELSEIF [RiskScore] >= 9 THEN 'High' ELSEIF [RiskScore] >= 4 THEN 'Medium' ELSE 'Low' END. [Contract Expiring Soon] = DATEDIFF('day', TODAY(), [EndDate]) <= 90 AND [Status]='Active'. Each of these is placed on the correct shelf (Measures for numeric results, Dimensions for the banded/boolean flags) once created, by dragging it from Measures to Dimensions in the Data pane if Tableau mis-classifies it.

PROBLEM 5

Blank values in RelatedOperationID, RelatedPO_ID, RelatedContractID, DateClosed and DateResolved show up as literal 'Null' marks on charts and break AVG calculations for resolution time.

Task: Handle nulls correctly so that open tickets do not corrupt the Average Resolution Time KPI and blank relationship keys do not appear as a spurious category.

Solution: For ResolutionTimeDays/ResolutionTimeHours, the underlying formula already guards with IF DateClosed/DateResolved is blank THEN blank END, so AVG naturally excludes open tickets; do not overwrite this with ZN(). For the relationship keys, set Format > Pane > Special Values > 'Hide' for any view that should only show linked records, or add a calculated filter [Has Related Operation] = NOT ISNULL([RelatedOperationID]) and drop it on the Filters shelf.

3. Worksheet Development

Build the individual charts and KPI worksheets that will later be assembled into each department dashboard.

PROBLEM 1

Trainees do not know which chart type fits which question, and often default to a table for everything, which is not comprehensive enough for a KPI focused review.

Task: For each department, build the specific worksheets listed under 'Charts to build' in the Dashboards and KPIs section (see the full list per department), choosing the chart type that best answers the underlying business question.

Solution: Follow the chart list department by department (Operations bar and Pareto charts, Legal bar and donut charts, Supply Chain bar and bullet charts, Admin treemap, Customer Service line and bullet, IT stacked bar, Finance line, HR bar and donut, Internal Control stacked bar, Risk heat map). Build one worksheet per chart, name it exactly after its purpose (for example 'Downtime Pareto', 'Spend by Category') so it is easy to find again when assembling dashboards.

PROBLEM 2

KPI number cards (BANs) need to look clean and be instantly readable, but a raw SUM() dropped on a worksheet just shows a plain number with no context.

Task: Build a proper KPI card worksheet for each headline metric (Total Actual Volume, Total Spend, Headcount, Open Critical Risks, Average CSAT and so on) that shows the number, a short label and, where relevant, a comparison to target or prior period.

Solution: Create a new worksheet, place the measure on Text, remove all other shelves, then format the mark label with a large font size for the number and a smaller caption line for the label (use a calculated field that concatenates the label and value with a line break, or two stacked text objects when assembled on the dashboard). Add a reference line or a second small calculated field for 'vs Target' or 'vs Prior Month' using a table calculation such as [This Period] - LOOKUP([This Period], -1).

PROBLEM 3

The Downtime Pareto chart for Operations needs both bars and a cumulative percentage line together, which trainees find is not a single default chart type in Tableau.

Task: Build the Downtime Hours Pareto chart combining a descending bar chart of DowntimeHours by DowntimeReason with a cumulative percentage line on a dual axis.

Solution: Put DowntimeReason on Columns sorted descending by SUM(DowntimeHours), and SUM(DowntimeHours) on Rows as bars. Add a second copy of DowntimeHours on Rows, change its mark type to Line, and set its table calculation to Running Total, then to Percent of Total on the same axis, computed using DowntimeReason. Right click the second axis > Dual Axis, then Synchronise Axis so the line reads from 0 to 100 percent while the bars read in hours.

PROBLEM 4

The Risk heat map needs to show both how many risks fall in each Likelihood/Impact cell and how severe they are, which is more than a single measure can convey on a plain grid.

Task: Build the Risk Likelihood x Impact heat map worksheet with both count and severity visible at a glance.

Solution: Place Likelihood_1to5 on Columns and Impact_1to5 on Rows (both treated as discrete dimensions), set the mark type to Square, put COUNTD(RiskID) on Size and AVG(RiskScore) or the Risk Band calculated field on Colour with a red amber green diverging palette. Add COUNTD(RiskID) to Label so each square shows its risk count directly.

4. Dashboard Design

Assemble the worksheets into the 11 department dashboards plus the Executive Overview, with consistent layout, titles and branding.

PROBLEM 1

Trainees tend to drop worksheets onto a dashboard in a random order, producing a cluttered page with no visual hierarchy and inconsistent sizing.

Task: Design each dashboard (see the full list of dashboard titles and their charts in the Dashboards and KPIs section) using a consistent layout: title band at the top, KPI cards in a row beneath it, then supporting charts arranged in a grid below.

Solution: Use a fixed size dashboard (1366 x 768 for desktop delivery). Add a horizontal container at the top for the title and company logo/colour band. Add a second horizontal container immediately below it holding the KPI card worksheets, each roughly equal width. Add a vertical or grid layout of containers beneath for the supporting bar/line/heat map charts, keeping no more than 3 to 4 charts per dashboard page so it remains readable.

PROBLEM 2

Every dashboard needs a clear, business friendly title, and trainees are unsure what to name each page so that end users immediately know what they are looking at.

Task: Apply the exact dashboard titles from the KPI/Dashboard list (Executive Overview Dashboard, Operations Performance Dashboard, Legal and Contracts Dashboard, Supply Chain Dashboard, Admin and Assets Dashboard, Customer Service Dashboard, IT Service Desk Dashboard, Finance Dashboard, HR Dashboard, Internal Control Dashboard, Risk Management and Compliance Dashboard) to each dashboard tab and title text object.

Solution: Rename each dashboard tab (double click the tab name) to match the titles exactly. Add a title text object at the top of each dashboard using the same wording, in a larger bold font, so the tab name and the on-screen title always match; this avoids confusion when dashboards are exported to PDF or PowerPoint where only the on-screen title is visible.

PROBLEM 3

The Executive Overview Dashboard needs to combine measures from several different sheets (Operations, SupplyChain, Employees, RiskComplianceRegister, CustomerService) on one page, and trainees are unsure whether this requires a single worksheet with every field or several small worksheets.

Task: Assemble the Executive Overview Dashboard from the individual KPI and chart worksheets already built for each department, rather than building new mega-worksheets that mix every table together.

Solution: Drag the existing 'Total Actual Volume' KPI (Operations), 'Total Spend' KPI (SupplyChain/AccountsFinance), 'Headcount' KPI (Employees), 'Open Critical Risks' KPI (RiskComplianceRegister) and 'Average CSAT' KPI (CustomerService) onto the Executive Overview dashboard as separate floating or tiled objects. Because the relationship model keeps each table at its native grain, each KPI worksheet independently queries only the tables it needs, so there is no cross contamination between departments on the same page.

PROBLEM 4

Dashboards look inconsistent across departments because trainees pick different fonts, colours and container spacing on each page.

Task: Apply a consistent visual style (colour palette, font, spacing) across all 11 dashboards so the finished workbook reads as one coherent training deliverable.

Solution: Create one dashboard first (Executive Overview) and use Format > Workbook to set a single font (for example Arial) applied to the whole workbook. Save the colour choices as a custom colour palette in Tableau's Preferences.tps file (or simply document the hex codes used, for example a dark blue #1F4E78 for headers and a teal accent) and reuse the exact same palette, container padding (use 8px inner padding on every container) and title banner height on every subsequent dashboard.

5. Interactivity

Add filters, parameters and dashboard actions so the finished dashboards let a user explore, drill down and answer follow up questions without leaving the page.

PROBLEM 1

Every dashboard needs the same basic slicing (by Department, by Date range) but trainees keep rebuilding the same filter on every single dashboard, which is slow and inconsistent.

Task: Build one set of global filters (Department, Year, Quarter) that can be applied consistently across all dashboards.

Solution: Build the filter once on the Executive Overview dashboard, set it to apply to 'All Using This Data Source' (or the relevant related data sources) via the filter's dropdown menu, then use Dashboard > Actions or simply copy/paste the filter object onto each subsequent dashboard, keeping the same 'Apply to Worksheets > All Using Related Data Sources' setting so behaviour stays identical everywhere.

PROBLEM 2

Clicking a bar in the 'Spend by Category' chart should let a user immediately see the underlying purchase orders, but by default nothing happens when a mark is clicked.

Task: Add a Filter Action so that clicking a category bar on the Supply Chain Dashboard filters a detail table of purchase orders on the same page.

Solution: Go to Dashboard > Actions > Add Action > Filter. Set the source worksheet to 'Spend by Category', the target worksheet to the PO detail table, run the action On Select, and set 'Clear selection' to show all values, so clicking a category filters the table and clicking again (or hitting Escape) resets it.

PROBLEM 3

Executives want to switch the Executive Overview KPI cards between 'This Month', 'This Quarter' and 'This Year' without navigating away from the page.

Task: Add a parameter driven date range control to the Executive Overview Dashboard.

Solution: Create a String parameter [Date Range Selector] with values 'This Month', 'This Quarter', 'This Year'. Build a calculated field [Date Filter Logic] that returns TRUE/FALSE by comparing the relevant date field to TODAY() using DATETRUNC, based on the parameter's current value with a CASE/IF statement, and place that calculated field on the Filters shelf of every KPI worksheet, set to True. Show the parameter control on the dashboard so users can change it live.

PROBLEM 4

Drilling from the Executive Overview straight into a department's own dashboard currently requires manually clicking through dashboard tabs, which is not intuitive for first time users.

Task: Add navigation buttons or a Go To Sheet action so a user can click a KPI on the Executive Overview and land directly on the matching department dashboard.

Solution: Add a Navigate object (Dashboard > Objects > Navigation, or an Image/Button object) beneath or beside each KPI card on the Executive Overview, and set its destination to the relevant department dashboard (for example the Total Spend KPI navigates to the Supply Chain Dashboard). Alternatively use Dashboard > Actions > Add Action > Go to Sheet triggered On Select from the KPI card itself.

PROBLEM 5

Tooltips currently show Tableau's default 'field name: value' list, which is not friendly for non technical business users viewing the dashboards.

Task: Redesign the tooltips on every chart to be a short, readable sentence rather than a raw field list.

Solution: Open each worksheet's Tooltip editor (Marks card > Tooltip) and replace the default content with a plain English sentence using inline field placeholders, for example 'In <ProductionDate>, <AssetField> produced <SUM(ActualVolume)> <UnitOfMeasure> against a plan of <SUM(PlannedVolume)>.' Remove any field the sentence does not need so the tooltip stays short and focused.
