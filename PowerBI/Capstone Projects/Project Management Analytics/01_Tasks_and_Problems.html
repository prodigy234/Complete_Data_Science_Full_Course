1. Dataset column dictionary

Before touching Power BI, work through every table below and understand each column - what it means, its correct data type, and how it will be used. This is the foundation everything else in this training is built on.

Dim_Date Dimension

Rows: 1,461 (2023-01-01 to 2026-12-31, one row per day)  |  Model role: Standalone calendar table. Mark as a Date Table in Power BI. Every fact table connects to it on Date.

ColumnData typeDescription
DateDateOne calendar day. The primary key of the table and the field every relationship to a fact table is built on.
YearWhole NumberCalendar year of the date (2023-2026). Used to slice every dashboard by year and to build year-over-year DAX measures.
QuarterNumberWhole NumberQuarter as a number (1-4). Used for correct chronological sorting of the Quarter text column.
QuarterTextQuarter label such as Q1, Q2. Sorted by QuarterNumber so it does not sort alphabetically.
MonthNumberWhole NumberMonth as a number (1-12). Sort-by column for MonthName/MonthShort so months read Jan to Dec, not alphabetically.
MonthNameTextFull month name (January, February...). Used on axis labels where space allows.
MonthShortTextAbbreviated month name (Jan, Feb...). Used on compact chart axes.
MonthYearTextMonth and year combined (Jan-2023). Used as the axis field on trend charts that span multiple years.
WeekNumberWhole NumberISO week number (1-53). Supports weekly trend analysis of timesheets.
DayWhole NumberDay of month (1-31).
DayNameTextFull weekday name (Monday...). Used to analyse which weekdays log the most hours.
DayOfWeekNumberWhole NumberWeekday as a number, Monday=1...Sunday=7. Sort-by column for DayName.
IsWeekendTrue/FalseTRUE for Saturday/Sunday. Used to filter or flag weekend work in timesheet measures.
IsWorkingDayTrue/FalseOpposite of IsWeekend. Used when computing available working capacity for utilization measures.

Dim_Employees Dimension

Rows: 48 employees across 8 departments  |  Model role: The staffing dimension. It plays FOUR different roles in the model (assignee, project manager, account manager, risk owner) which is exactly why the training covers active vs inactive relationships and USERELATIONSHIP.

ColumnData typeDescription
EmployeeIDTextUnique key, format EMP001. The relationship key from this table to Dim_Tasks, Dim_Projects, Dim_Clients and Fact_Risks/Fact_Timesheets.
FullNameTextEmployee display name, used on every employee-level visual and slicer.
DepartmentTextOne of 8 departments (Software Development, QA, Design, Business Analysis, PMO, DevOps, Data & Analytics, Marketing). Used to slice cost and utilization by department.
RoleTextJob title, e.g. Software Engineer, Project Manager. Finer grain than Department.
SeniorityLevelTextJunior, Mid, Senior, Lead or Principal. Drives HourlyRate_USD and is used to analyse cost by seniority.
HourlyRate_USDDecimal NumberBilling/cost rate per hour. Multiplied by hours logged to derive labour cost where actual cost is not already captured in Fact_Budget.
LocationTextCity/country the employee is based in. Used for a geographic view of resourcing.
EmailTextWork email. Not used in visuals - included for realism, and to teach students to hide unused columns from the report view.
HireDateDateDate the employee joined. Used to compute tenure and to filter to employees hired before a project started.
EmploymentStatusTextActive or Inactive. Used to exclude former staff from current utilization measures.

Dim_Clients Dimension

Rows: 18 clients  |  Model role: One row per client account. Connects to Dim_Projects; also links to Dim_Employees through AccountManagerID.

ColumnData typeDescription
ClientIDTextUnique key, format CL001. Relationship key to Dim_Projects.
ClientNameTextClient display name.
IndustryTextClient's industry sector (Banking, Healthcare, Retail...). Used to analyse revenue/project mix by industry.
CountryTextClient's country.
RegionTextBroader geographic region grouping Country. Used for a regional map/bar visual.
AccountManagerIDTextEmployeeID of the account manager responsible for the client. A second relationship into Dim_Employees (inactive by default - see Relationships).
ClientSinceDateDate the client relationship began. Used to compute client tenure.
ContractValue_USDDecimal NumberOverall contract value with the client. Used for a client-value ranking visual, independent of individual project budgets.

Dim_Projects Dimension (and the model's centre table)

Rows: 32 projects  |  Model role: The central table of the star schema. Everything - tasks, timesheets, budget, milestones, risks - ultimately rolls up to a project.

ColumnData typeDescription
ProjectIDTextUnique key, format PRJ001. Relationship key to Dim_Tasks, Fact_Timesheets, Fact_Budget, Fact_Milestones and Fact_Risks.
ProjectNameTextProject display name, used as the row label on most project-level visuals.
ClientIDTextForeign key to Dim_Clients. Blank for internal projects, which is a deliberate teaching point about handling blanks in a relationship.
DepartmentTextDepartment that owns delivery of the project.
ProjectManagerIDTextEmployeeID of the project manager. A third relationship into Dim_Employees (inactive by default).
ProjectTypeTextFixed Price, Time & Material, or Internal. Used to compare delivery models.
PriorityTextLow, Medium, High or Critical.
StatusTextNot Started, In Progress, On Hold, Completed or Cancelled. The main slicer for portfolio health.
StartDateDatePlanned/actual project start date.
PlannedEndDateDateBaseline end date agreed at project start. Used with ActualEndDate to compute schedule variance.
ActualEndDateDateReal completion date, blank until the project finishes. Used to compute on-time delivery.
PlannedBudget_USDDecimal NumberTotal approved budget for the project, compared against SUM of Fact_Budget[ActualCost_USD].

Dim_Tasks Dimension (bridges Projects and Timesheets)

Rows: 350 tasks  |  Model role: One row per task inside a project. Parent of Fact_Timesheets and a child of Dim_Projects; also links to Dim_Employees via AssignedToID.

ColumnData typeDescription
TaskIDTextUnique key, format TSK0001. Relationship key to Fact_Timesheets.
ProjectIDTextForeign key to Dim_Projects.
TaskNameTextShort description of the work item, e.g. Feature Development, User Acceptance Testing.
PhaseTextProject phase the task belongs to: Initiation, Planning, Execution, Testing or Closure. Used as the stage axis on the schedule dashboard.
TaskTypeTextCategory of work: Development, Design, Testing, Documentation, Meeting or Review. Used for a work-mix visual.
AssignedToIDTextEmployeeID the task is assigned to. The main (active) relationship into Dim_Employees.
StartDateDateDate work on the task began or is scheduled to begin.
DueDateDateDate the task is due. Compared to today's date to flag overdue tasks.
CompletionDateDateDate the task was actually finished, blank if not yet completed.
StatusTextNot Started, In Progress, Completed or Blocked.
PriorityTextLow, Medium, High or Critical.
EstimatedHoursWhole NumberPlanned effort for the task, compared against actual hours logged in Fact_Timesheets.

Fact_Timesheets Fact (transaction grain: one time entry)

Rows: 2,575 rows  |  Model role: The most granular table in the model. Every hour billed or worked is one row here.

ColumnData typeDescription
TimesheetIDTextUnique key for the time entry.
EmployeeIDTextForeign key to Dim_Employees - who logged the hours.
ProjectIDTextForeign key to Dim_Projects - which project the hours belong to.
TaskIDTextForeign key to Dim_Tasks - which task the hours were logged against.
DateDateForeign key to Dim_Date - the day the work happened.
HoursLoggedDecimal NumberNumber of hours logged in this entry. The core additive measure of the fact table.
BillableFlagText (Yes/No)Whether the hours are billable to the client. Drives billable vs non-billable utilization measures.
OvertimeFlagText (Yes/No)Whether the entry represents overtime work. Used for an overtime-cost/risk analysis.

Fact_Budget Fact (grain: one project/category/month)

Rows: 1,820 rows  |  Model role: Planned vs actual cost by project, cost category and month.

ColumnData typeDescription
BudgetLineIDTextUnique key for the budget line.
ProjectIDTextForeign key to Dim_Projects.
CategoryTextCost category: Labor, Software & Tools, Hardware, Travel, Training, Contingency or Marketing.
MonthDateFirst day of the month the budget line applies to. Foreign key to Dim_Date.
PlannedCost_USDDecimal NumberBudgeted cost for that project/category/month.
ActualCost_USDDecimal NumberActual cost incurred. Compared against PlannedCost_USD to compute variance.

Fact_Milestones Fact (grain: one milestone)

Rows: 160 rows  |  Model role: Planned vs actual milestone delivery, 5 milestones per project.

ColumnData typeDescription
MilestoneIDTextUnique key for the milestone.
ProjectIDTextForeign key to Dim_Projects.
MilestoneNameTextMilestone label, e.g. Design Sign-off, Go-Live.
PlannedDateDateBaseline planned date for the milestone.
ActualDateDateActual date achieved, blank if not yet reached.
StatusTextCompleted, On Track, Delayed or At Risk.

Fact_Risks Fact (grain: one identified risk)

Rows: 127 rows  |  Model role: Risk register - one row per identified risk, with probability, impact and an owner.

ColumnData typeDescription
RiskIDTextUnique key for the risk.
ProjectIDTextForeign key to Dim_Projects.
RiskDescriptionTextShort description of the risk.
CategoryTextTechnical, Financial, Schedule, Resource, Scope, External or Compliance.
ProbabilityTextLow, Medium or High likelihood of the risk occurring.
ImpactTextLow, Medium or High impact if it occurs.
RiskScoreWhole NumberProbability level multiplied by Impact level (1-9). Drives the risk-matrix heatmap.
StatusTextOpen, Mitigated, Closed or Occurred.
DateIdentifiedDateDate the risk was logged.
DateResolvedDateDate the risk was closed/mitigated, blank if still open.
OwnerIDTextEmployeeID responsible for managing the risk. A fourth relationship into Dim_Employees (inactive by default).

2. Data loading tasks (Power Query)

The Excel workbook is already clean - your job is to load all nine sheets correctly, set the right data types, and prepare the model. Attempt each task below yourself before checking the Solutions HTML file.

Task 1 - Dim_Date

Load the sheet, confirm Date is typed as Date (not Date/Time), and mark this table as a Date Table on the Date column.

Task 2 - Dim_Employees

Load the sheet, confirm HourlyRate_USD is Decimal Number and HireDate is Date, then hide the Email column from the report view.

Task 3 - Dim_Clients

Load the sheet and confirm ContractValue_USD is Decimal Number and ClientSince is Date.

Task 4 - Dim_Projects

Load the sheet, set the three date columns and PlannedBudget_USD correctly, and confirm ClientID is allowed to be blank (internal projects).

Task 5 - Dim_Tasks

Load the sheet and set EstimatedHours to Whole Number and the three date columns to Date.

Task 6 - Fact_Timesheets

Load the sheet, set HoursLogged to Decimal Number, and disable Load if a staging query is used, keeping only the final table loaded to the model.

Task 7 - Fact_Budget

Load the sheet and set PlannedCost_USD and ActualCost_USD to Decimal Number, and Month to Date.

Task 8 - Fact_Milestones

Load the sheet and set PlannedDate and ActualDate to Date, keeping in mind ActualDate is legitimately blank for unfinished milestones.

Task 9 - Fact_Risks

Load the sheet, set RiskScore to Whole Number, and the two date columns to Date.

Think about it: Dim_Employees connects into four different places (assignee, project manager, account manager, risk owner). Why can Power BI only make one of these active at a time, and what DAX function lets a measure use one of the inactive ones anyway? Work out your answer, then confirm it in the Solutions file and the Word manual.
  1. Build the 9 core one-to-many relationships listed in the Relationships table (Dim_Projects to Dim_Tasks, Dim_Projects to each fact table, Dim_Tasks to Fact_Timesheets, Dim_Clients to Dim_Projects).
  2. Connect Dim_Date to Fact_Timesheets[Date], Fact_Budget[Month], Fact_Milestones[PlannedDate] and Fact_Risks[DateIdentified] as the four active date relationships.
  3. Connect Dim_Employees[EmployeeID] to Dim_Tasks[AssignedToID] and Fact_Timesheets[EmployeeID] as the two active employee relationships.
  4. Add the four additional employee relationships (to Dim_Projects[ProjectManagerID], Dim_Clients[AccountManagerID], Fact_Risks[OwnerID], and Dim_Date to Fact_Milestones[ActualDate]) and leave them inactive - Power BI will grey these out automatically because an active path already exists.
  5. Confirm every relationship's cardinality reads One-to-Many with the 1 on the dimension side, and cross filter direction is Single, in the relationship properties panel.

4. DAX measures to build

For every measure below, write the DAX yourself first. Only the measure name and what it should return/drive are given here - the full formula, line-by-line explanation and dashboard impact are in the Solutions HTML file and the Word manual.

  1. Create a dedicated Measures table (a blank table with no columns from any source) to hold every DAX measure, keeping the model organised.
  2. Build the 6 foundational measures (Total Projects, Active Projects, Completed On-Time %, Total Planned Budget, Total Actual Cost, Budget Variance, Budget Variance %).
  3. Build the 6 task & schedule measures, including the running-total pattern using ALLSELECTED.
  4. Build the 4 budget & cost measures, including the DATEADD time-intelligence measure - this step requires Dim_Date to already be marked as a Date Table.
  5. Build the 6 resource & utilization measures, including the two USERELATIONSHIP measures.
  6. Build the 5 risk measures, including the second USERELATIONSHIP measure and the IN operator pattern.
